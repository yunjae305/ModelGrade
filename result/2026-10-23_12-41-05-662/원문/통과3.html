답변
문자열을 그대로 비교하는 `sorted()`를 사용하면 앞자리 0을 보존하면서 사전식 오름차순으로 정렬한 새 목록을 만들 수 있어요.

## 함수와 사용 예

```python
def sort_book_numbers(book_numbers):
    """도서 번호 문자열 목록을 사전식 오름차순으로 정렬해 반환합니다."""
    return sorted(book_numbers)

numbers = ["010", "2", "001", "10"]
sorted_numbers = sort_book_numbers(numbers)

print(sorted_numbers)  # ['001', '010', '10', '2']
print(numbers)         # ['010', '2', '001', '10']
```

### 동작 방식

`sorted()`는 목록의 원소를 **문자열 그대로** 비교해 새 목록을 반환합니다. 그래서 `"001"`의 앞자리 0이 유지되고, 원래 목록도 바뀌지 않아요. 숫자 크기 순이 아니라 글자 순으로 정렬하므로 `"10"`이 `"2"`보다 앞에 옵니다.

## 겹침 판별 함수

아래 함수는 두 예약이 **실제로 겹칠 때만 `True`**를 반환합니다. 종료 시각과 다음 예약의 시작 시각이 같으면 겹치지 않습니다.

```python
def reservations_overlap(start1, end1, start2, end2):
    return start1 < end2 and start2 < end1

result = reservations_overlap(60, 90, 90, 120)
print(result)  # False
```

### 작동 방식

첫 번째 예약이 두 번째 예약보다 먼저 끝나거나, 두 번째 예약이 첫 번째 예약보다 먼저 끝나면 겹치지 않습니다. 위 예시에서는 첫 예약의 종료 시각 `90`과 다음 예약의 시작 시각 `90`이 같으므로 `False`가 나옵니다.

함수는 입력값을 다시 대입하거나 변경하지 않고, 비교 결과만 반환합니다.

## 원리와 관찰 순서

### 원본과 캐시

📌 **원본 데이터**는 서버가 기준으로 삼아 보관하는 실제 값이고, **캐시**는 빠르게 보여 주려고 잠시 저장해 둔 복사본입니다. 화면은 원본을 매번 직접 읽기보다 캐시에 있는 값을 먼저 보여 줄 수 있습니다.

관찰하신 순서를 이 원리로 설명하면 다음과 같습니다.

1. 서버의 값을 수정합니다.
2. 화면이 갱신된 원본 대신 이전에 저장된 캐시를 읽어 예전 값이 보입니다.
3. 캐시를 비우면 그 사본을 더는 사용할 수 없게 됩니다.
4. 화면이 서버에서 값을 다시 받아오면서 새 값이 표시됩니다.

이 순서만으로는 수정된 값이 처음부터 원본에 저장되지 않았다고 단정할 수 없습니다. 캐시가 어디에 있었는지, 수정 후 서버 응답이 어떻게 처리됐는지는 관찰 내용만으로 확인되지 않습니다.

## 도서관 대출 목록에 비유

### 각 요소의 대응

도서관 전산실에 **최신 대출 기록 원본**이 있고, 안내 데스크에는 그 내용을 미리 복사해 둔 **대출 목록 사본**이 있다고 생각해 보세요. 전산실에서 기록을 바꿔도 데스크의 사본을 바로 갱신하지 않으면, 이용자는 한동안 이전 목록을 보게 됩니다. 사본을 치우고 전산실 기록을 다시 확인하면 최신 목록이 보입니다.

- 전산실의 최신 대출 기록 → **서버의 원본 데이터**

- 사본을 치우고 최신 기록을 다시 확인하는 일 → **캐시를 비운 뒤 서버에서 다시 가져오는 과정**

여기서 캐시는 틀린 원본이 아니라 **원본을 복사해 둔 자료**입니다. 다만 갱신 시점이 늦으면 원본과 내용이 달라질 수 있습니다.
