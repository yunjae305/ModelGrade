## 겹침 판별 함수

아래 함수는 두 예약이 **실제로 겹칠 때만 `True`**를 반환합니다. 종료 시각과 다음 예약의 시작 시각이 같으면 겹치지 않습니다.

```python
def reservations_overlap(start1, end1, start2, end2):
    return start1 < end2 and start2 < end1

result = reservations_overlap(60, 90, 90, 120)
print(result)  # False
```

### 작동 방식

첫 번째 예약이 두 번째 예약보다 먼저 끝나거나, 두 번째 예약이 첫 번째 예약보다 먼저 끝나면 겹치지 않습니다. 위 예시에서는 첫 예약의 종료 시각 `90`과 다음 예약의 시작 시각 `90`이 같으므로 `False`가 나옵니다.

함수는 입력값을 다시 대입하거나 변경하지 않고, 비교 결과만 반환합니다.

## 원리와 관찰 순서

### 원본과 캐시

📌 **원본 데이터**는 서버가 기준으로 삼아 보관하는 실제 값이고, **캐시**는 빠르게 보여 주려고 잠시 저장해 둔 복사본입니다. 화면은 원본을 매번 직접 읽기보다 캐시에 있는 값을 먼저 보여 줄 수 있습니다.

관찰하신 순서를 이 원리로 설명하면 다음과 같습니다.

1. 서버의 값을 수정합니다.
2. 화면이 갱신된 원본 대신 이전에 저장된 캐시를 읽어 예전 값이 보입니다.
3. 캐시를 비우면 그 사본을 더는 사용할 수 없게 됩니다.
4. 화면이 서버에서 값을 다시 받아오면서 새 값이 표시됩니다.

이 순서만으로는 수정된 값이 처음부터 원본에 저장되지 않았다고 단정할 수 없습니다. 캐시가 어디에 있었는지, 수정 후 서버 응답이 어떻게 처리됐는지는 관찰 내용만으로 확인되지 않습니다.

## 무엇이 바뀌었는지

### 물리적 밝기와 지각
**물리적 밝기**는 화면에서 나오는 빛의 양을 가리키고, **지각된 밝기**는 눈과 뇌가 그 빛을 주변 환경과 함께 받아들인 결과예요. 주변 조명을 끄면 화면의 실제 밝기가 자동으로 바뀌는 것은 아니지만, 어두운 주변에 비해 화면이 더 밝게 두드러질 수 있습니다.

원인 설명의 순서는 중요해요. 먼저 바뀐 조건은 **주변 조명**이고, 그 결과 화면과 주변의 밝기 차이가 커졌습니다. 어두운 환경에 눈이 적응하는 과정도 화면을 더 강하게 느끼는 데 영향을 줄 수 있지만, 화면 자체의 밝기가 변했다고 결론 내릴 근거는 아닙니다.

### 비유와 대응
어두운 방에서 손전등을 켜면, 밝은 방에서 같은 손전등을 켰을 때보다 빛이 훨씬 두드러져 보입니다. 손전등의 빛이 더 강해져서라기보다, **주변이 어두워져 빛과 배경의 차이가 커졌기 때문**이에요.

- 손전등에서 나오는 빛 → 화면의 물리적 밝기
- 방의 밝기 → 주변 조명
- 빛이 더 두드러져 보이는 정도 → 지각된 눈부심과 밝기

### 이 경우에 적용하면
화면 밝기는 그대로이고 주변 조명만 꺼졌다면, 손전등 비유처럼 화면이 주변보다 더 밝게 느껴질 수 있습니다. 눈의 적응이나 화면의 색·내용도 느낌에 영향을 줄 수 있지만, 주어진 상황에서 먼저 달라진 조건은 **주변 조명의 감소**입니다. 그래서 눈부심이 커졌다는 느낌만으로 실제 화면 밝기가 바뀌었다고 단정할 수는 없습니다.
