1. 차가운 물병이 따뜻한 방에 들어옵니다. 방 안의 따뜻한 공기에는 눈에 보이지 않는 수증기가 들어 있습니다.

## 캐시와 원본 데이터의 차이

원본 데이터는 서버에 실제로 저장된 정보이고, \*\*캐시(Cache)\*\*는 화면을 빠르게 보여 주기 위해 이전에 가져온 정보를 임시로 저장한 것입니다.

쉽게 이해할 수 있도록 도서관 대출 목록에 비유해 보겠습니다.

### 1. 도서관 대출 목록으로 비유하기

도서관에 대출 정보를 관리하는 컴퓨터와 안내 데스크에 놓인 대출 목록 출력물이 있다고 생각해 보겠습니다.

- 원본 데이터(서버): 도서관 컴퓨터에 저장된 실제 대출 기록입니다.
- 캐시: 안내 데스크에 미리 출력해 둔 대출 목록입니다.
- 화면: 이용자가 안내 데스크에서 확인하는 대출 목록입니다.
- 서버 데이터 수정: 사서가 컴퓨터의 대출 기록을 변경하는 것입니다.
- 캐시 삭제: 오래된 출력물을 버리고 최신 목록을 다시 가져오도록 하는 것입니다.

### 2. 실제 상황에 적용하기

관찰하신 순서대로 살펴보겠습니다.

1\. 서버의 값을 수정했습니다. 사서가 컴퓨터에서 책의 대출 상태를 '대출 중'에서 '반납 완료'로 변경한 상황에 해당합니다.

2\. 화면에는 이전 값이 남아 있었습니다. 안내 데스크에는 아직 '대출 중'이라고 적힌 오래된 출력물이 놓여 있습니다. 컴퓨터 기록이 바뀌었더라도 출력물이 자동으로 바뀌지 않으면 이용자는 이전 정보를 보게 됩니다.

3\. 캐시를 삭제했습니다. 안내 데스크에서 오래된 출력물을 버리는 것과 같습니다.

4\. 화면에 새로운 값이 나타났습니다. 도서관 컴퓨터에서 최신 대출 목록을 다시 가져와 '반납 완료'라고 표시하게 된 것입니다.

### 3. 왜 이런 현상이 발생할까요?

캐시는 같은 정보를 매번 서버에서 가져오는 시간을 줄여 화면을 빠르게 표시하도록 도와줍니다.

하지만 서버의 데이터가 변경되었을 때 캐시가 즉시 갱신되지 않으면 원본 데이터와 캐시에 저장된 값이 서로 달라질 수 있습니다.

| 구분      | 원본 데이터        | 캐시              |
| ------- | ------------- | --------------- |
| 역할      | 실제 정보 저장      | 빠른 조회 지원        |
| 저장 내용   | 서버가 관리하는 데이터  | 이전에 가져온 데이터의 사본 |
| 수정 후 상태 | 수정이 성공했다면 새 값 | 이전 값이 남을 수 있음   |
| 삭제 시 영향 | 일반적으로 영향 없음   | 임시 저장 정보가 제거됨   |

### 4. 이번 현상에서 알 수 있는 점

이번에는 서버 값을 수정한 뒤에도 화면에 이전 값이 표시되었지만, 캐시를 삭제하자 새 값이 나타났습니다.

따라서 서버의 원본 저장에 실패했다고 단정할 수는 없습니다. 오히려 캐시에 이전 데이터가 남아 있어 화면이 최신 상태를 보여 주지 못했을 가능성이 있습니다.

다만 캐시 삭제 후 새로운 값이 표시되었다는 사실만으로 정확히 어느 캐시가 원인이었는지까지 확정할 수는 없습니다. 브라우저 캐시, 서버 캐시, 애플리케이션 내부 캐시 등 여러 종류가 있기 때문입니다.

핵심은 원본 데이터가 바뀌는 것과 화면에 표시되는 정보가 갱신되는 것은 별개의 과정이라는 점입니다. 캐시는 속도를 높여 주지만, 갱신이 제대로 이루어지지 않으면 오래된 정보를 보여 줄 수 있습니다.

```python
def check_exam_eligibility(attempts: int, limit: int) -> bool:
    """응시 횟수(attempts)가 한도(limit) 미만인지 확인하여 결과를 반환합니다."""
    return attempts < limit


# --- 사용 예시 ---

# 1. 응시 횟수(2)가 한도(3) 미만인 경우 -> True

result2 = check_exam_eligibility(user_attempts, exam_limit)
print(f"응시 횟수: {user_attempts}, 한도: {exam_limit} => 결과: {result2}")

# 3. 응시 횟수(4)가 한도(3)를 초과한 경우 -> False

exam_limit = 3
result3 = check_exam_eligibility(user_attempts, exam_limit)
```

1. **`attempts < limit` (미만 비교 연산)**

* 응시 횟수가 한도보다 작을 때만 `True`가 되고, 한도와 같아지거나(도달) 더 커지면(초과) 자동으로 `False`를 반환합니다.


2. **입력값 유지**
* 함수 내부에서 `attempts`나 `limit`의 값을 변경하는 동작(`+=` 등)을 하지 않고 단순 비교만 수행하므로, 함수를 호출한 뒤에도 전달한 변수의 원본 값은 그대로 유지됩니다.

* 별도의 `if` 문을 사용하지 않고 `return attempts < limit` 표현식을 바로 사용하면, 비교 결과인 `True` 또는 `False`가 곧바로 반환되어 간결한 코드가 됩니다.

`set`을 활용해 이미 등장한 `name` 값을 기록하면서 새 리스트를 만들어내는 방식을 사용하면 순서를 유지하면서 원본을 손상시키지 않고 중복을 제거할 수 있습니다.

```python
def remove_duplicate_names(data_list):
    seen = set()  # 이미 확인한 name을 저장할 집합
    result = []   # 중복이 제거된 결과를 담을 새로운 리스트
    
    for item in data_list:
        name = item["name"]
        # 아직 등장하지 않은 name인 경우에만 결과에 추가
        if name not in seen:
            seen.add(name)
            result.append(item)
            
    return result


# --- 사용 예시 ---
original_data = [{"name": "솔", "v": 2}, {"name": "별", "v": 1}, {"name": "솔", "v": 8}]

# 함수 실행
filtered_data = remove_duplicate_names(original_data)

print("중복 제거 결과:", filtered_data)
print("원본 데이터 보존:", original_data)

```

### 작동 원리 설명

1. **새로운 리스트 생성 (`result = []`)**
* 원본 목록을 직접 수정하지 않기 위해 결과를 담을 빈 리스트 `result`를 따로 만듭니다.


2. **중복 확인용 집합 (`seen = set()`)**
* `set`은 값의 존재 여부를 빠르게 찾아내는 데 최적화되어 있습니다. 이미 지나간 `name` 값들을 적어두는 메모장 역할을 합니다.


3. **순서대로 순회 (`for item in data_list`)**
* 목록의 첫 항목부터 차례대로 확인하기 때문에 **처음 등장한 순서가 자연스럽게 보존**됩니다.
* 이미 `seen`에 있는 `name`이라면 아무 작업도 하지 않고 넘어가므로, **가장 처음 기록된 항목만** `result`에 들어갑니다.

두 예약 시간이 겹치는지 판단할 때 핵심이 되는 조건은 **"첫 번째 예약의 시작 시각이 두 번째 예약의 종료 시각보다 빠르고, 두 번째 예약의 시작 시각이 첫 번째 예약의 종료 시각보다 빠른가?"** 입니다.

끝나는 시각과 다음 시작 시각이 같은 경우(예: 90분)는 겹치지 않아야 하므로 `<` (미만) 연산자를 사용합니다.

### 파이썬 코드 및 사용 예시

```python
def is_overlapping(start1: int, end1: int, start2: int, end2: int) -> bool:
    """두 예약 구간이 겹치는지 여부를 반환합니다.

    입력값을 직접 변경하지 않으며, 시작/종료 시각이 맞닿는 경우(end1 == start2)는 False를 반환합니다.
    """
    return start1 < end2 and start2 < end1


# 사용 예시: 60~90분 예약과 90~120분 예약
reservation1_start, reservation1_end = 60, 90
reservation2_start, reservation2_end = 90, 120

result = is_overlapping(
    reservation1_start, reservation1_end, reservation2_start, reservation2_end
)

print(f"예약1 ({reservation1_start}~{reservation1_end})과 "
      f"예약2 ({reservation2_start}~{reservation2_end}) 겹침 여부:", result)

```

### 초보자를 위한 원리 설명

두 구간이 **겹치지 않는 경우**를 떠올려보면 쉽게 이해할 수 있습니다.

1. **예약1이 예약2보다 아예 먼저 끝나는 경우**: `end1 <= start2`
2. **예약2가 예약1보다 아예 먼저 끝나는 경우**: `end2 <= start1`

두 예약이 서로 완전히 떨어져 있거나 시각이 딱 맞닿아 있다면 위의 조건 중 하나가 성립하여 겹치지 않습니다.

따라서 두 예약이 **겹치는 경우**는 위 조건의 반대(부정)가 됩니다.

* `end1 > start2` (예약1이 끝나기 전에 예약2가 시작함) **그리고** `end2 > start1` (예약2가 끝나기 전에 예약1이 시작함)

이를 코드 형태로 작성하면 `start1 < end2 and start2 < end1`이 됩니다.

#### 60~90 및 90~120 예시 적용

* `start1` = 60, `end1` = 90
* `start2` = 90, `end2` = 120

1. `start1 < end2` → `60 < 120` (참)
2. `start2 < end1` → `90 < 90` (거짓)

두 조건이 모두 참이어야 하나, 두 번째 조건이 거짓이 되므로 함수는 `False`를 반환합니다.
