8개는 k의54개 후보에서는 제외하되, **모든11개 대화에 각8개 구조를 명시적으로 요구**했습니다. 각 기준의 예정 평가 기회는 독립대화11개로 목표10개 이상입니다.

| 기준 | 대화에 넣은 유도 요구 |
|---|---|
| 1-2.fence_imbalance | 실제 운영 메모 코드블록의 여는·닫는 구획 |

| 1-3.internal_link | 접수·문의 목차링크와 실제 대응 제목 |

자세한 요구·턴 위치는 `answer_dependent_plan.json`에 있습니다. 수동 구조 검증용 예시답변을 실제 CODE 검사기와 J5 적용 인식기에 넣어8개 모두 유효 구조로 인식되는 것을 확인했습니다. 실제 모델의 답변이나 의미 판정이 끝났다는 뜻은 아닙니다.

답변 수집 후 모델별 CSV(case_id,answer)를 다음 명령으로 점검합니다:

`python check_answer_dependent_coverage.py <ModelGrade프로젝트경로> <answers_모델.csv>`

구조가 없는 `:none` PASS는 유효 노출로 세지 않고8개 각각의 독립대화 수10회 이상을 확인합니다. 부족하면 종료코드2와 누락 구조를 표시합니다. 빈답변만 있는 대조군을 검사해 유효노출0개로 집계되는 것도 확인했습니다. 구조 누락은 요청 불이행으로 별도 기록하며 의미 PASS/FAIL은 공식 심판 결과를 사용합니다.

## 전달 형식과 재현

`questions.json`의 reference에는 문서전체가 포함되어 있습니다. reference_file만으로는 공식 수집기가 문서를 불러오지 않습니다. 첨부 path는 files/를 뺀 파일명입니다. set.json에는 공식 id 키가 있습니다.

검사원문은 `precheck.json`, 정확한k와ID는 `k_audit.json`, 기준별ID는 `coverage.json`, 실제72개 정의는 `criteria_catalog.json`, 토큰측정은 `reference_audit.json`, 첨부전달검사는 `collector_compatibility.json`에 있습니다.

참조문서는 앞4장 서술을 유지하고 나머지는 장별 운영 일지를 코드로 합성했습니다. 동일 긴 문단 복사는 없으나 반복된 일지 스키마가 있는 합성 자료입니다. 자연 장문과 동일하다고 주장하지 않습니다.

갱신프롬프트는 `질문생성_프롬프트_v3.3_독립판.md`입니다.

멀티턴k수정전후는 `multiturn_k_changes.json`에 기록했습니다. 고유성은 Q43·44·63·64, 제목은 Q26·27·35·36에 재배치하여 모든64개 기준의10회 하한을 유지했습니다.
