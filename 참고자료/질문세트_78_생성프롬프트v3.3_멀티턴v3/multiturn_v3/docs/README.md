# 멀티턴 v3 턴 문서 작성 규칙 (공통)

10턴 대화 11개의 턴마다 붙일 문서입니다. 파일 하나 = 한 턴의 '[붙여 넣은 자료]' 내용입니다. 질문 본문은 빌더가 `[붙여 넣은 자료]\n{문서}\n[자료 끝]\n\n{요청 문장}` 으로 조립합니다.
대화별 설계서(`briefs/Q<번호>.md`)에 그 대화의 사실 · 턴별 요청 문장 · 문서 종류 · 꼭 넣을 것 · 넣으면 안 되는 것이 있습니다.

## 1. 길이 — 턴마다 10,000토큰 이상
- 문서 하나가 o200k_base 로 **10,200토큰 이상**이어야 합니다(요청 문장을 합쳐 10,000 이상이 되게 여유를 둠). 한국어는 대략 1토큰 ≈ 1.8~2.1자라 **약 20,000~22,000자**입니다.
- 쓴 뒤 반드시 세어 확인합니다:
  `python -X utf8 -c "import sys; sys.path.insert(0, '.'); from code_eval.long_context import count_tokens; print(count_tokens(open(r'<파일>', encoding='utf-8').read()))"`
  (작업 폴더 `C:\Users\winz\Desktop\quality-test-integrated` 에서). 모자라면 새 내용(새 항목 · 새 기록)을 더해 늘립니다.

## 2. 내용 — 길이를 '진짜 자료'로 채운다
- 그 턴의 요청을 처리하는 데 실제로 쓰이는 문서여야 합니다. 같은 기관 · 같은 행사의 실제 업무 문서처럼 씁니다: 회의록, 기록부, 대장, 메일 묶음, 점검 일지, 공문, 게시판 글 등.
- **금지**: 같은 문단 · 같은 문장 반복, 번호만 바꾼 같은 항목 나열, 의미 없는 채움 글, 앞 턴 문서를 다시 붙이기, 다른 대화의 문서 재사용.
  표나 목록의 행은 행마다 실제로 다른 내용(다른 사람 · 다른 시각 · 다른 물품 · 다른 사연)이어야 합니다.
- 분량을 채우는 좋은 방법: 시각별 기록, 담당자별 메모, 이전 회차 사례와 비교, 논의 과정(누가 무엇을 제안했고 왜 보류됐는지), 참가자 문의와 답변, 시설 · 물품의 세부 상태, 결정의 이유.
- 설계서의 '확정 사실'(시각 · 인원 · 금액 · 이름 · 장소 · 예외 조건)과 **어긋나는 값을 새로 만들지 않습니다.** 설계서에 없는 세부(사람 이름, 물품 상태, 과거 일화 등)는 지어내도 되지만 확정 사실과 충돌하면 안 됩니다.
  단, '자료 대조(check)' 턴 문서만 설계서가 정한 몇 곳을 일부러 틀리게 적습니다.
- 계산 결과(합계 · 총액 · 잔액)나 그 턴 질문의 정답을 문서에 미리 적지 않습니다(모델이 직접 해야 함).
- **행사 날짜는 미정**입니다(안내문에 '미정' 으로 남는 값). 문서 작성일 · 회의일 · 메일 날짜는 2026년 9월 안에서 자유롭게 쓰되, 행사 당일 날짜를 정해 적지 않습니다('행사 당일', '시범 운영 날' 처럼).
  문의처 연락처(전화 · 메일)도 미정입니다.
- 기관 · 인물은 모두 꾸민 것이지만 문서 안에 '가상' 이라는 말을 쓰지 않습니다. 실제 회사 · 실존 인물 · 실제 연락처(전화번호 · 메일 주소 형식)를 쓰지 않습니다(연락처가 필요하면 '내선 미기재' 처럼).
- 문서는 사람이 쓴 업무 기록의 말투(~다 · ~함 · ~합니다)로 씁니다. AI 에게 하는 지시나 질문('~해 주세요', '답변은 ~') 문장을 넣지 않습니다(메일 · 게시판 글 속 사람끼리의 부탁은 괜찮음).

## 3. 형식
- 마크다운 문서. 제목 · 소제목 · 목록 · 표 사용 가능.
- **표 계산(calc) 턴 문서에는 마크다운 표가 설계서의 수량 표 하나뿐**이어야 합니다(`| --- |` 구분 줄이 정확히 1번). 그 표는 설계서에 적힌 그대로(행 순서 · 값 · 중복 행 포함) 넣고, 다른 장부 내용은 목록이나 글로 씁니다.
- **쓰면 안 되는 낱말: '요약', '정리해', '핵심만', '간추려'** — 문서 안에 있으면 평가 프로그램이 요약을 시킨 턴으로 잘못 읽습니다. '정리: 한송이' → '작성: 한송이', '요약표' → '일람표', '정리해 둔' → '모아 둔' 처럼 바꿔 씁니다('정리함 · 정리일 · 정리한' 도 피하는 편이 안전).
- 코드블록(```)을 쓰지 않습니다. '[자료 끝]' 이나 '[붙여 넣은 자료]' 라는 글자를 문서 안에 쓰지 않습니다.
- 파일 이름: `docs/Q<번호>_T<턴>.md` (UTF-8).

## 4. 다 쓴 뒤 확인
- 10개 파일 모두 10,200토큰 이상인지 세어 표로 남깁니다(`docs/Q<번호>_tokens.txt`).
- '요약 · 정리해 · 핵심만 · 간추려' 가 문서에 없는지 찾아봅니다.
- calc 문서는 `| --- |` 가 1번인지, 수량 표가 그대로 들어갔는지 확인합니다.
- 확정 사실(설계서 1장)과 어긋나는 값이 없는지 한 번 훑습니다(check 문서의 일부러 틀린 곳 제외).
