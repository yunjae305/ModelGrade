체크리스트 4~7번을 사용자가 직접 돌릴 때 순서입니다. 모델 호출이 드는 단계는 예상 비용을 적었습니다(실제 사용량은 실행이 끝나면 터미널의 `[LLM 비용]` 줄과 실행 기록에 남습니다).

## 0. 서버 다시 띄우기 (코드가 바뀌었으므로 한 번)
- 미리보기 `workspace`(포트 8091)를 다시 시작합니다. 설정은 `.env` 그대로: `SEMANTIC_ENGINE=dual`(GPT-6 Luna high + Jev 병행), 수집용 GPT 모델 `gpt-6-luna`, Gemini `gemini-3.6-flash`.
- 화면 '평가 설정'에 **"Jev + GPT-6 Luna 병행 · gpt-6-luna + jev-latest"** 가 보이면 됩니다.

## 1. 질문 326개 만들기 (체크리스트 4 — 질문생성 프롬프트 v2)
- 화면 '질문 세트 만들기': 질문 수 **326**, 10턴 대화 **16**, 긴 문서 질문 **10**. 공개 질문(base)은 비웁니다(사용자 결정: 공개 질문 안 씀).
- 생성기(question-gen-v2.0-kvar)가 계획 → 만들기 → 빠진 기준 보충 → 질문당 기준 수(k_var) 6~10 맞추기 순으로 돌고, 끝나면 요약에 `k_var`(k 분포·범위 밖 수·상한 46)가 나옵니다. 경고에 "범위 밖 단일 질문이 … 상한을 넘습니다"가 있으면 한 번 더 만들거나 그대로 쓸지 정합니다.
- 비용: 앞선 205개 생성이 66회 호출·입력 17만·출력 43만 토큰(gpt-6-luna, 약 $0.3)이었습니다. 326개 + 긴 문서 1개 + 대화 16개는 **약 $1 안팎**.
- 질문별 평가 프롬프트(체크리스트 3)는 이 세트로 다시 만듭니다: `python -X utf8 참고자료/분석/2026-10-18-질문당기준수/build_eval_prompts.py data/question_sets/<세트 id> 참고자료/질문별평가프롬프트_최종326`

## 2. 네 모델 답 받기 (체크리스트 5 앞부분)
- 세트 화면에서 '평가 시작' → 수집만 합니다(자동 평가 꺼져 있음). AIONA 는 웹, GPT·Claude·Gemini 는 API(수집용 Chrome 에 그 사이트 탭이 열려 있으면 그 모델은 웹으로 바뀝니다 — API 로 받으려면 탭을 닫아 두세요).
- 실패한 턴이 있으면 세트 화면의 '이어서 수집'(앞 실행 id)으로 실패한 것만 다시 받습니다. 빈 답을 요구하는 질문에 AIONA 가 "처리 중 오류" 화면을 내는 것은 다시 받아도 같습니다(모델 쪽 원인).
- 비용: API 세 모델 326개 약 $25 (긴 문서 10개 포함).

## 3. 평가 (체크리스트 5 뒷부분 — 병행 판정)
- 실행 화면 '평가 진행'. GPT-6 Luna 가 모든 기준을, Jev 가 J1~J4 를 함께 보고, 갈리면 Luna 가 한 번 더, 또 다르면 보류입니다. J5 에서 사실·출처를 확인하지 못한 것도 보류(화면 '확인 필요').
- 비용: 앞선 326 세트 3모델 평가가 Luna 약 $15.8(긴 문서 2배 요금 포함)·Jev 약 $0.3 → 네 모델 **약 $20**.

## 4. 보류 검수 (체크리스트 7 — 보류 데이터를 예외 데이터로)
```bash
python -X utf8 tools/export_review.py data/comparison_runs/<실행 id>.json --held
```
- `results/review/<실행 id>-held.csv` 에 모델·질문·기준·보류 사유(심판 갈림 / J5 근거 부족 / 출처 원문 확인 실패 …)·질문·답변 발췌가 나옵니다. `gold` 열에 PASS 또는 FAIL 을 적으면 `tools/sample_size_study.py --gold` 가 그대로 읽습니다.
- 사유가 "심판 갈림"이면 `judge_original_reason` 열에 Jev·Luna·재판정 값이 있습니다.

## 5. 질문 수 줄일 수 있는지 (체크리스트 6 — 기울기 그래프)
```bash
python -X utf8 tools/question_gradient.py <실행 id>
```
- `참고자료/분석/<날짜>-기울기-<실행 id>/gradient.md·svg` 에 "기준 많은 질문부터 넣을 때" 모든 기준이 1회·10회 이상 덮이는 질문 수, 모델 순위·통과율이 안정되는 질문 수가 나옵니다. 최소 검증 = 순위가 고정되는 수, 정밀 검증 = 10회 커버리지와 ±3pp 를 모두 만족하는 수로 읽으면 됩니다.
