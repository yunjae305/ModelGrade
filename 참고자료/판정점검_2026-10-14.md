## 1. 기준 수 한 줄 정리 — 28 + 44 = 72, 80은 다른 단위

**평가 기준은 총 72개 = CODE평가 소분류 28 + LLM의미평가 소분류 44.** 질문 수를 셀 때 쓰는 '세부 기준 80개'는 답변으로만 정해지는 8개(CODE 7 + J5-3.a)를 빼고, 질문에 조건이 있는 CODE 소분류 17개를 질문 조건 37개로 나눠 센 단위(CODE 37 + LLM 43)라 72와 다르다.

| 단위 | CODE | LLM | 합 | 쓰는 곳 |
|---|---|---|---|---|
| 평가 기준(소분류) | 28 | 44 | **72** | 기준 카드, 점수, 보고 |
| 질문 조건(질문만 보고 적용 여부를 셀 수 있는 것) | 37 (소분류 17개에서) | 43 (44 − J5-3.a) | **80** | 질문 생성 목표, 고정 세트 덮음 수, 질문 수 근거 |

CODE 28 중 질문 조건으로 세지 않는 11개 = 답변 전용 7개 + 항상 켜져 있어 질문 조건이 없는 4개(1-1 글 깨짐·펜스 검사 등).

같은 문장을 화면(`frontend/workspace.html` 기준 머리글)과 [SERVICE_UI.md](SERVICE_UI.md)에 넣었다.

## 3. 답변으로만 정해지는 8개 조건이 꼭 필요한가

대상: CODE 7개(`1-2.fence_imbalance`, `1-2.orphan_closing_tag`, `1-3.footnote_link`, `1-3.citation_link`, `1-3.internal_link`, `3-1.answer_equation`, `3-2.declared_count`) + LLM `J5-3.a`(답변 속 수치·인용의 자기 일관). 300세트 3모델 × 450턴 실제 결과:

| 조건 | 실제 FAIL/NO | 판단 |
|---|---|---|
| 1-2.orphan_closing_tag | 1 (실탐) | 유지 |
| 3-1.answer_equation | 4 (전부 오탐 → 2-1 에서 수정) | 유지 — 수정 후 실탐 0, 오탐 0 |
| 3-2.declared_count | 1 (오탐 → 수정) | 유지 |
| J5-3.a | NO 12 (GPT 10 · Gemini 2) | 유지 — 모델 간 차이를 가장 크게 내는 조건 |
| 1-2.fence_imbalance, 1-3.footnote_link, 1-3.citation_link, 1-3.internal_link | 0 | 유지 — 비용 없는 안전 검사(펜스·링크가 깨진 답을 잡는 용도) |

**결론: 8개 모두 유지.** 다만 질문 수·기준 덮음 수를 셀 때는 빼고, 화면·보고서에서는 '답변 무결성 검사(항상 실행)' 로 따로 묶어 보여 주는 것을 권고한다. 지금 코드도 질문 조건 80개에서는 빼고 있으므로 집계 쪽 변경은 없다.
