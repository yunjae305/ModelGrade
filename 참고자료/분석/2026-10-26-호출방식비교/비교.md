# 첫 Codex 호출 방식 비교 — 묶음 10개 · 한 번(표준 입력) · 한 번(파일) (2026-10-26)

사용자 요청 "묶음으로 평가돌리게 하는데 그거를 그냥 파일 하나를 특정 위치에 저장시키게 하고 그것을 읽게 해서 한번의 호출로 평가 돌리는것도 해보고".

## 같은 조건

- 대상: 지금 묶음으로 가는 질문 전부 — 첨부 이미지 없는 단일 질문 94개(Q11~Q78 × 네 모델 중 Codex 로 넘어간 것).
- 1차 판정은 지난 판(v4-s1~s4)의 것을 그대로 썼다(`--reuse-first`). 걸린 항목 197개가 모든 방식에서 같다.
- 첫 호출만 바꾸고, 그 뒤 다시 묻기 · 안전장치 · 합치기는 같다.
- 멀티턴 · 첨부 · 롱컨텍스트는 넣지 않았다. 롱컨텍스트는 하나가 약 110만 바이트라 한 호출에 함께 넣을 수 없다.

10-25 의 폴더 방식(`tools/judge_folder.py run --mode folder`)은 Codex 가 결과 파일을 써야 해서 Windows 샌드박스의 쓰기 막힘으로 멈췄다. 이번 방식은 파일을 읽기만 하고 답은 출력으로 받는다. 위 설정으로 Windows 에서도 읽기는 된다.

## 판단

- **기본은 묶음 10개 그대로 둔다.** 가장 빠르다(네 모델 동시). 일치율도 기준이다.
- **한 번 · 표준 입력은 쓸 수 있다.** 호출 수와 입력 토큰이 적다(−10번 · −22%). 대신 한 호출이 끝나야 다음으로 가서 2.6배 느리다. 시간보다 사용량이 급할 때 `--codex-one-call stdin`.
- **한 번 · 파일은 쓰지 않는다.**
  - 읽는 동안 맥락을 계속 다시 보내 입력 토큰이 1.7배다. 첫 답의 인용이 원문과 맞지 않는 칸이 많아 다시 묻기도 2배였다(묶음 23 · 표준 입력 24 · 파일 47번, 거의 모두 인용 불일치). 셸로 잘라 읽은 글을 옮겨 적다 인용이 어긋난 것으로 보인다.
  - 판정에 셸을 열어야 한다. 읽기 전용이어도 판정 심판이 PC 의 다른 파일(.env 등)을 읽을 수 있게 된다. 답변 원문에 섞인 지시가 그 셸을 쓰게 할 위험도 생긴다. 표준 입력 방식은 셸을 열지 않는다.
- 판정 도구에는 두 방식 모두 옵션으로 남겼다(`tools/judge_v4.py --codex-one-call stdin|file`).
