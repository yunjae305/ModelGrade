# 3차 검토 요청 — 2차 지적 4건 반영

1. `semantic_evidence._loose`: 공백을 모두 지우지 않고 **서식 공백만** — 공백 연속을 하나로 줄인 뒤 구두점·기호(`[^\w\s]`) 양옆 공백만 제거. 낱말·숫자 사이 공백은 보존 → `"12 34"` ≠ `"1234"`, JSON 줄바꿈·들여쓰기는 같아짐. 확인: `{"value":"1234"}` vs `{"value":"12 34"}` False, 표 칸 `3층 자료실 | 10:00` vs `| **3층 자료실** | 10:00 |` True.
2. `question_generation` 고치기 단계: 고치기 전 커버리지를 적어 두고, 고친 뒤 `check` 로 다시 세어 어떤 기준이 `min(이전 수, per_target 또는 10)` 아래로 떨어지면 그 기준을 쓰던 고침을 **되돌리고** 다시 센다(경고 기록). 모두 되돌렸으면 회차 종료.
3. `parse_k_repair(text, known_ids)`: `questions` 가 목록이 아니면 GenerationError, `target_items` 가 목록이 아니면 비우고 경고, 모르는 기준 id 는 빼고 경고.
4. `dual_judge`: Jev part 의 `unreported_attempts` 키 제거, 합친 JevCall 의 `attempts = len(cost_parts) + 미관측 시도 합` 으로 두어 ledger 의 `attempts - len(parts)` 가 미관측 수와 정확히 같게 함(중복 없음). 사람이 보는 시도 횟수는 `verification.dual_judge` 에 있음.

새 파일(검토 대상 추가): `tools/question_gradient.py` — 질문을 k_var 큰 순서로 넣으며 커버리지·모델별 통과율·순위 안정 지점을 표·SVG 로 내는 분석 도구(모델 호출 없음). `webapp.run_summary.question_outcomes/question_units/unit_outcome` 과 `question_generation.k_var_by_group/target_counts` 를 씀. 실험용 `--records-dir` 경로는 jsonl 판정 + `engine.evaluate_batch` CODE 로 질문 판정(갈림·J5 확인 실패는 보류, 수집 실패는 FAIL).
