- **이전 턴 지시 승계**: 이어받은 조건도 같은 규칙을 따른다. 판정할 수 없으면 행 없이 skipped 로 남는다.

### F5b 상세

- **원문의 조건**: `server_tool_use`(web_fetch)의 id·요청 URL 과 `web_fetch_tool_result` 의 tool_use_id·결과 URL 이 모두 맞는 결과만 쓴다. 텍스트 원문(`source.type=text`)만, 2 MiB 이하만. PDF(base64)는 대조하지 않는다. 평가자가 '확인했다'고 적은 내용은 근거가 아니다.
- **언제 쓰나**: 서버 수집이 접근 문제(`http_error`·`fetch_error`·시간·DNS·크기·형식·인코딩·압축·수집 한도)로 실패한 경우만. 공개 주소·포트·URL 차단(SSRF 방어), 다른 호스트로 이동·연속 이동·잘못된 이동은 대신하지 않는다. 서버 수집 자체(공개 DNS 고정 연결·인증서 검증·리다이렉트 검사)는 바뀌지 않았다.
- **기록**: 인용문이 그 원문에 있으면 `quote_verified`, `retrieval=provider_document`, `server_fetch_status`. 없으면 `quote_not_found`. 원문은 메모리에서만 쓰고 결과에는 `verification.provider_documents`(URL·받은 시각·글자 수)만 남는다. 공신력·기준 시점 조건은 그대로다.
- **사실 오류와 검증 불가**: 확보된 원문이 주장과 충돌하면 J5 FAIL `contradicted`(사실 오류 확정, D2-02 유형). 서버도 공급자도 원문을 확보하지 못하면 지금처럼 `SOURCE_ORIGINAL_UNAVAILABLE` FAIL(사실 오류 아님).
- **검색 오류와 원문 열기 오류**: `search_errors`·`fetch_errors` 를 나눠 기록한다. 검색 없이 연 원문만 실패하면 `J5_FETCH_ERROR`(판정 미완료 — 원문 열기 도구 오류). 이전에는 같은 경우를 `J5_SEARCH_ERROR`(검색 실행 오류)로 적었다 — 판정 값(미완료)은 같고 사유만 바뀐다. 나눠 기록하지 않은 옛 결과는 이전 해석 그대로다. 검색 한도 도달 표시는 검색 도구 기준으로만 센다(이전에는 원문 열기 한도도 섞였음).
- **범위**: Claude API 평가자만 공급자 원문을 넘긴다. Codex CLI·OpenAI API 평가자는 이전과 같다.

### 기존 J5 정책과 확인이 필요한 점 (변경하지 않음)

1. **검증 불가의 판정 값**: 원문을 아무도 확보하지 못한 경우는 기존 정책대로 FAIL(사실 오류 아님)로 남겼다. '검증 불가 = 판정 미완료'로 바꾸는 것은 문서의 대안 P2 로, 공식 판정 정책 변경이라 하지 않았다.
2. **원문 열기 도구 접근 실패(`url_not_accessible`)**: 검색 없이 연 원문을 공급자도 받지 못한 경우는 판정 미완료로 남는다(이전과 같음). 이것을 출처 원문 확인 실패 FAIL 로 볼지는 정책 결정이다.
3. **공급자 원문의 출처 동일성**: web_fetch 결과의 `url` 은 요청 URL 이라 공급자 쪽 리다이렉트를 알 수 없다. 서버 수집이 리다이렉트 문제로 실패한 경우는 대신하지 않지만, 접근 실패(403 등)인데 공급자가 다른 호스트로 이동해 받은 원문이면 구분할 수 없다.
