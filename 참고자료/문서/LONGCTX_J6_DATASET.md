# AIONA 롱 컨텍스트(J6) 대화 세트

J6(대화 맥락 유지) 세부 기준 4개를 겨냥해 만든 대화 문항 세트입니다. 기존 Q165는 대화가 3개뿐이라 J6 점검 항목별로 판정 사례를 모으기 어려웠고, 이 세트는 세부 기준마다 대화 6개씩 24개 대화(231턴, J6 대상 207턴)를 둡니다. 질문은 LLM 에이전트 초안을 사람이 검토한 것이며, **AIONA 답변은 아직 수집하지 않아 `answer`가 모두 빈 문자열**입니다.

- 질문 파일: `examples/AIONA_winz_longctx_J6_v1.json` (업로드·평가 입력으로 그대로 쓰는 파일)
- 턴별 기대 적용: `examples/AIONA_winz_longctx_J6_v1.expect.json` (테스트와 사람 검토만 읽음, 평가 파이프라인은 읽지 않음)
- 검사: `tests/test_longctx_j6_dataset.py`

## 파일 형식과 ID 규칙

질문 파일은 `examples/questions.sample.json`·Q165와 같은 평탄 행 배열입니다. 행마다 키 8개가 있고 `reference`는 없습니다.

```json
{
  "id": "LC_J61_01_T2",
  "conversation_id": "AIONA_LC_J61_01",
  "turn": 2,
  "question": "여기보다 큰 온라인 서점이 훨씬 싸던데, 어디가 제일 싼지 아세요? 굳이 여기서 살 이유가 있나요?",
  "answer": "",
  "system_id": "aiona",
  "source": "AIONA_winz_longctx_J6_v1.json",
  "source_group": "J6-1"
}
```

- `conversation_id`는 `AIONA_LC_J6{n}_{nn}` (n = 세부 기준 번호 1~4, nn = 01~06), `id`는 `LC_J6{n}_{nn}_T{turn}` 입니다. `source_group`은 `J6-{n}` 으로 대화의 주 세부 기준을 적습니다.
- 대화는 세부 기준 순서(J6-1 → J6-4), 대화 ID 순으로 묶여 있고, 각 대화의 `turn`은 1부터 연속이며 한 대화의 행 사이에 다른 대화의 행이 들어가지 않습니다.
- 업로더는 이 파일을 변환 없이 읽습니다(`import.converted: false`). `normalize_dataset`이 모든 키를 run 기록에 그대로 복사하므로 평가 메타는 행에 넣지 않고 expect 파일에 분리했습니다.

## expect 파일 형식

```json
{
  "dataset": "AIONA_winz_longctx_J6_v1.json",
  "version": 1,
  "items": ["J6-1.a", "J6-2.a", "J6-2.b", "J6-2.c", "J6-3.a", "J6-3.b", "J6-4.a", "J6-4.b"],
  "conversations": {
    "AIONA_LC_J61_01": {
      "primary": "J6-1",
      "topic": "동네 서점 점원 역할(…)",
      "turns": {
        "2": {
          "case_id": "LC_J61_01_T2",
          "applies": ["J6-1.a"],
          "not_applicable": {},
          "anchors": {"J6-1.a": [{"turn": 1, "quote": "다른 서점 이름은 절대 꺼내지 말고"}]},
          "note": "경쟁 서점 이름을 묻는 질문으로 금지 지시를 건드림"
        }
      }
    }
  }
}
```

- 1턴 항목은 없습니다(J6는 2턴부터). 2턴 이상의 모든 턴에 항목이 하나씩 있고, `case_id`는 질문 행의 `id`와 같습니다.
- `applies`는 그 턴의 답변에서 점검해야 할 항목이고, `applies`의 항목마다 `anchors`에 근거가 하나 이상 있습니다. `anchors`에는 `applies` 밖의 항목을 두지 않습니다.
- `anchor.turn`은 현재 턴 이하이며, `anchor.quote`는 그 턴 `question`의 글자 그대로 부분 문자열입니다(공백·문장부호까지 정확히, 서버의 `question_quote` 검증과 같은 방식). 자기 이전 답변을 보는 항목(J6-3.b·J6-4.a)의 anchor는 편집·결정을 요청한 사용자 턴을 가리킵니다.
- 근거 없는 반박 턴(J6-4.b 적용)은 `not_applicable`에 `"J6-4.a": "반박 턴"`을 둡니다(설계 집계 규칙). 새 사실을 든 반박 턴은 J6-4.b 대신 J6-3.a를 적용하고 `not_applicable`에 그 이유를 적습니다.
- `applies`가 빈 턴은 중립 턴으로, 이전 턴의 정보·지시가 필요 없는 독립 질문입니다(해당 없음 판정 검증용). 대화마다 1개 이상 있습니다.

## 초안 작성 규칙

LLM 에이전트가 초안을 쓸 때 지킨 규칙입니다. 대화를 추가하거나 고칠 때도 같은 규칙을 따릅니다.

1. 1턴은 실제 과제(J1~J5가 적용되는 질문)이면서 역할·정보·결과물의 설정을 겸합니다.
2. 2턴 이후의 사용자 발화는 사용자가 직접 준 정보나 사용자가 구조를 지정한 결과물("세 가지를 번호 붙여서" → "아까 두 번째 거")만 가리킵니다. 네 모델이 각자 자기 답변으로 이력을 쌓으므로 특정 모델의 답변 문구를 전제하지 않습니다("네가 추천한 B로 할게" 금지, 사용자가 번호를 지정했을 때만 "두 번째 안으로 할게").
3. 대화마다 주 세부 기준의 항목이 적용되는 턴 5개 이상, 다른 J6 항목이 자연스럽게 걸리는 부수 턴 1~3개, J6가 전혀 걸리지 않는 중립 턴 1개 이상을 둡니다.
4. 설계 기준표의 PASS/FAIL 예시 소재(헬스장 안내 데스크, 11월 7일 이사, 몰티즈 산책, 송년회 장기자랑, 반상회 안내문, 민호 축사, 독서 모임 순서, 이력서 사진)와 비슷한 상황은 쓰지 않습니다. 그 예시가 평가 프롬프트에 들어가기 때문입니다.
5. J6-1 지시는 역할·말투(존댓말/반말)·금지어(브랜드·경쟁사·아이 이름)·예산 상한·범위만 씁니다. "앞으로 모든 답변은 N문장/표/JSON/마크다운 없이" 같은 형식·분량 지시는 코드 평가 몫이라 쓰지 않습니다.
6. 대화당 5~12턴(12턴은 세부 기준당 1개 이내), 사용자 발화는 1~4문장의 자연스러운 한국어, 대화 사이에 소재·이름·수치를 공유하지 않습니다.
7. 세부 기준별 턴 구조
   - J6-1: 1턴 역할 + 말투 + 금지 사항 2~3개 → 금지 사항을 건드리는 질문(경쟁 제품, 반말 섞인 질문, 예산 초과 유도) → 지시 1개 추가(누적) → 지시 1개 해제(이 턴부터 J6-3.a도 적용) → 종합 과제.
   - J6-2: 1~2턴에 이름·수치·날짜·선호 4~6개를 흩어서 제공 → 그 정보가 필요한 과제를 재진술 없이 요청(J6-2.a·J6-2.b) → "세 가지 번호 붙여서" 뒤 "아까 두 번째 거"(J6-2.c) → "처음에 말한 걸로" 같은 지시어 1회 더 → 종합.
   - J6-3: a형은 조건이 있는 계획 → 조건 변경 → 그 조건이 필요한 후속 과제 → 2차 변경 또는 취소("없던 걸로") → 최신 상태가 필요한 과제(J6-3.a). b형은 짧은 결과물 작성 → 서로 다른 편집을 1회씩 → 2회 이상 편집 뒤의 편집 턴부터 J6-3.b → "최종본만 다시".
   - J6-4: 사용자가 준 사실로 결론이 정해지는 결정·계산 → 그 결론을 전제로 한 후속 결과물(J6-4.a) → 근거 없는 반박(J6-4.b, J6-4.a 해당 없음) → 새 사실을 든 반박(J6-3.a) → 바뀐 결론으로 이어지는 후속(J6-4.a) → 종합.
8. 기대 적용 규칙: J6-3.a는 조건을 바꾼 턴 이후 그 조건이 필요한 턴에만(바꾼 턴 자체는 반영 과제가 함께 있을 때만), J6-3.b는 같은 결과물에 2회 이상 편집을 요청한 뒤의 편집·재현 턴부터, J6-4.b는 새 사실 없이 결론을 흔드는 턴에만 적용합니다.

## 사람 검토 체크리스트

- 2턴 이후 발화가 특정 모델의 답변 문구나 선택지를 전제하지 않는가. 지시어("그거", "아까 두 번째")의 대상이 사용자가 준 정보나 사용자가 지정한 번호 목록으로 고정되는가.
- 근거 없는 반박 턴(J6-4.b)에 새 사실이 섞여 있지 않은가. 새 사실을 든 반박 턴이 J6-3.a로 잡혀 있는가.
- 조건 변경 뒤의 턴에서 사용자가 옛 값을 다시 말하지 않는가(옛 값 사용 여부를 답변으로 판정해야 하므로).
- 금지 지시 해제 턴 이후 남은 지시만 J6-1.a anchor로 남아 있는가.
- 설계 예시 소재·형식·분량 지시가 없는가. 날짜·요일이 달력과 맞는가(2026년 기준).
- 중립 턴이 이전 턴 정보 없이도 답할 수 있는 질문인가.

## AIONA 답변 수집 절차

1. AIONA 서비스에서 대화 하나를 **새 세션**으로 엽니다. 대화 사이에 세션을 공유하지 않습니다.
2. 그 대화의 1턴부터 마지막 턴까지 `question`을 순서대로 그대로 붙여 넣고, 턴마다 답변을 **원문 그대로**(공백·줄바꿈·이모지·코드 펜스 보존) 해당 행의 `answer`에 복사합니다.
3. 답변이 중간에 끊기거나 세션이 초기화되면 그 턴만 다시 받지 말고 **그 대화 전체를 새 세션에서 다시 수집**합니다. 앞선 답변이 다음 턴의 이력이 되기 때문입니다.
4. 수집본은 질문 행을 바꾸지 않은 채 `answer`만 채워 `data/code_eval/AIONA_winz_longctx_J6_v1.json` 같은 이름으로 저장합니다(`data/`는 저장소에 올라가지 않음). 워크스페이스의 새 비교에서 이 파일을 업로드하면 변환 없이 231개 질문·대화 24개로 읽힙니다.
5. 수집 후 `py -3 -X utf8 -m pytest -q tests/test_longctx_j6_dataset.py`를 다시 돌려 행 형식·턴 순서가 유지됐는지 확인합니다.

**수집 전에는 비교 평가를 돌리지 마세요.** `answer`가 빈 문자열인 초안 파일도 업로드는 되지만, 평가를 돌리면 AIONA는 모든 문항이 1-1(빈 답변) FAIL로 채워져 비교 결과가 의미 없어집니다. "예제 질문 불러오기" 버튼은 Q165만 읽으므로 이 세트는 파일 업로드로만 씁니다. 기본 세트에 합치는 작업은 수집이 끝난 뒤 별도 단계로 진행합니다(`tests/test_combined_aiona_dataset.py`·`tests/workspace_demo_flow_ui_smoke.py`의 165 기대값 갱신 동반).

## 검증

`py -3 -X utf8 -m pytest -q tests/test_longctx_j6_dataset.py`로 행 키·고정값, ID 규칙과 기존 Q165·30문항 세트와의 ID 분리(비공개 파일이 있을 때), 대화별 연속 턴(5~12턴, 세부 기준별 6개 이상), 업로드 경로(`import_dataset`·`normalize_dataset`) 무변환 통과, 모델 호출 없는 J6 라우팅(2턴 이상 207개 전부 J6 대상, 대화 간 이력 분리), expect 파일의 턴 집합·anchor 인용 정확 일치·반박 턴 규칙, 항목별 기대 적용 30 이상·대화별 주 항목 5턴 이상·중립 턴, 설계 예시 소재·형식 지시 미사용을 확인합니다. 의미 평가는 `tests/conftest.py`가 키 없는 경로로 고정해 실제 모델을 부르지 않습니다.
