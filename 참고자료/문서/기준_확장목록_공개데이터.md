# 평가 기준 추후 확장 목록 — 공개 데이터 기준 (2026-10-26 밤)

공개 데이터(IFEval-Ko 342 · KoMT-Bench 80 = 422문항, 사용자가 말한 '약 440')를 우리 기준 72개로 세어 본 결과에서, **기준을 늘릴 필요가 있는 곳**만 순서대로 모았다. 숫자 · 방법의 근거는 [공개세트 늘릴 기준 분석](../분석/2026-10-26-공개세트-늘릴기준/정리.md)(재현 `count_public.py`). 이 목록은 **아직 기준을 바꾸지 않은 계획**이다 — 넣을 때는 기준 v2 문서 → 코드 → 시험 순(사용자 규칙).

## 결론 — 확장이 필요한가

- **필요하다. 다만 첫 일은 새 기준이 아니라 지금 기준의 인식 넓히기다.** 공개 질문의 절반 이상(IFEval 205/342 · KoMT 42/80)이 '하세요 · 하십시오 · 하라'로 끝나 지금 규칙으로는 요청 문장이 0개다. 이것만 고쳐도 IFEval '기준 1개 이상' 225 → 277.
- 새 기준은 13개 후보 중 **CODE 4개 + 정답 대조 1개**가 우선이다(아래 2단계). 결과가 정해진 검사이고 덮는 문항이 많다.
- 모두 넣어도 공개 질문은 질문당 요구가 1~3개라 **k 6~10 에 드는 것은 IFEval 27 · KoMT 0** 이다. 공개 질문을 평가 세트에 직접 쓰려면 기준 확장과 따로 'k 범위 · 공개 세트 미사용(v2 4절)'을 공개 질문에만 다르게 둘지 결정해야 한다.

## 하는 순서

1. **R4 오인식 고침**(거짓 FAIL 위험) → 지금 78 세트 · 네 모델 결과에서 2-2.heading 판정이 바뀌는지 확인.
2. **R1 요청 문장 끝** → 78 세트 k 다시 맞춤(범위 밖 0) → 판정 프롬프트 · 1차 심판 질문은 그대로.
3. R2 · R3 · R5 · R6(문서 → 코드 → 시험).
4. N1~N4(CODE) → 질문생성 프롬프트 3-1장 '검증 가능한 지시 종류' 표에 추가 → 새 질문 리스트(메뉴 2)로 기준마다 10문항 이상 확보.
5. N5 — KoMT 참조 답을 받은 뒤.
6. 3단계는 변별력을 본 뒤 정함(2단계까지 넣은 결과로 '모든 모델 PASS' 인 기준은 넣지 않음).

## 정해야 할 것 (넣기 전)

- 새 기준을 72 밖으로 따로 셀지, 2-1 · 2-2 안 조건 종류로 넣을지(기준 수 · k 셈이 달라짐).
- 공개 질문을 평가 세트에 직접 쓸지 — 쓰면 k 범위 · v2 4절 '공개 세트 미사용'을 공개 질문에만 다르게.
- KoMT 2턴(80개)은 J6(10턴 · 10만 토큰)에 안 맞고 질문생성 프롬프트의 '2턴 금지'와 부딪힘 — 이번 목록에서는 뺐다.
