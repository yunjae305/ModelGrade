**평가(판정)는 필요할 때 10~20개씩만** — 300개 이상 한 번에 돌리지 않는다(사용자 10-19). Codex CLI 로 판정이 되는 상태에서만 돌린다.

## 2. 한 명령으로: 메뉴 → 네 모델 동시 수집 → 판정 → 결과 (10-19 밤 6)

```bash
python -X utf8 tools/modelgrade.py
```
- 인자 없이 부르면 `start`: **1. 간단평가(78개) / 2. 정밀평가(326개)** 를 물어 번호를 받는다(미리 주려면 `start --choice 2`). 간단평가는 326 중 `참고자료/질문세트_최소78/ids.json` 번호를 그 순서로.
- 그 세트를 **네 모델이 동시에** 받는다: ChatGPT 앱(오른쪽 60%)·Claude 앱(왼쪽 60%)·Gemini 웹(오른쪽 위 40%)·AIONA 웹(오른쪽 아래 40%). 앱과 수집용 Chrome 은 알아서 켠다. 이미 받은 질문은 건너뛴다.
- 실행은 같은 세트·종류의 최근 실행을 이어 쓴다(정밀평가는 AIONA 웹 답을 올린 889e429f6d07). 수집이 끝나면 "이어서 판정할까요?" 에 y 면 20개씩 끝까지 판정하고 결과를 보인다(`--judge y|n` 으로 미리 정할 수 있음).
- Gemini·AIONA 는 수집용 Chrome 한 프로필(`data/browser_profiles/chrome-cdp`)에서 각자 창 — 로그인은 `python tools/chrome_cdp.py --login`(평소 Chrome 으로 같은 프로필, Google 은 여기서) 또는 AIONA 는 `python tools/web_chat_login.py aiona --auto`(.env, 사용자가 실행). Gemini 계정 bora3159@gmail.com, AIONA 주소 https://dev.aiona.kr(.env AIONA_URL).

### 2-1. 앱·웹만 따로 받기 (묶음 20개)

```bash
python -X utf8 tools/modelgrade.py collect app --provider gpt,claude,gemini,aiona --run 889e429f6d07 --next 20
```
- 여러 모델이면 **동시에**(사용자 지시 10-19 밤): 모델마다 자식 프로세스, 창 자리는 모델별 고정(Claude 왼쪽·ChatGPT 오른쪽 60%, Gemini 오른쪽 위·AIONA 오른쪽 아래 40%; ChatGPT 앱은 물리 1,600px 보다 좁으면 모드 버튼을 숨긴다), 실행 JSON 은 잠금 아래 자기 모델 자리만 합쳐 저장. 출력은 `[gpt]`·`[claude]`… 머리말로 섞여 나오고, 질문마다 `▶ Q36 (1턴) — 이번 묶음 3/20 · 전체 14/326` 로 진행을 보여 준다.
- 한 번에 20개(질문 번호순, 이미 받은 질문은 건너뜀). 같은 명령을 다시 부르면 이어서. 한 앱만: `--provider gpt` / `--provider claude`, 특정 질문만: `--only 36,56`.
- ChatGPT 앱이 트레이에만 떠 있으면 수집기가 창을 보이게 한다(실행 파일을 한 번 더 실행 → 떠 있던 앱이 창을 띄움, 포트 유지).
- 수집 중에는 Claude 앱 창이 앞으로 나오고 키 입력(Esc·Ctrl+V)이 그 창으로 가므로 PC 에서 다른 입력을 하지 않는다(창을 옮기거나 탭을 바꾸면 그 질문은 실패로 남고 다음에 다시 받는다). 로그인은 사람이 앱에서 미리.
- 한 번에 다: `run --run 889e429f6d07 --collect gpt,claude --next 20` = 앱 수집 → 판정 20개 → 결과.

## 2-2. 사람이 받아 적은 답변 CSV 가 있으면 올리기 (예비)

```bash
python -X utf8 tools/modelgrade.py collect import --provider gemini --csv 참고자료/질문세트_326_생성프롬프트v2/수집용/answers_gemini.csv --run 889e429f6d07
```
- 실행 889e429f6d07 = AIONA 웹 답변이 올라간 CLI 실행(평가 PC `data/comparison_runs/`, git 제외). GPT 웹 답변도 받으면 같은 식으로.
- 답 없는 줄은 ERROR(판정에서 FAIL), note '빈 답'은 받은 답. 올리면 CODE 평가(28개)까지 끝남.
- **빈 출력 요구 질문(8개)**: 답이 공백뿐이거나 받을 답이 없으면(모델 오류 포함) PASS, 결과에 수집 상태·오류를 `collection_note` 로 명시. 글을 냈으면 FAIL. (사용자 규칙 10-19 밤)
- **Jev 긴 자료**: 입력이 35,000자를 넘으면 첨부·참조 본문만 줄여 보낸다(.env JEV_TRIM_CHARS). 자료 없는 긴 대화는 Jev 가 거부하면 Codex 가 J1~J4 도 대신(결과 'GPT 대신 판정').

## 3. 판정은 20개씩 — 사용자에게 어느 모델·몇 개를 돌릴지 확인한 뒤

```bash
python -X utf8 tools/modelgrade.py judge --run 889e429f6d07 --next 20 --providers aiona,claude
python -X utf8 tools/modelgrade.py report --dir data/judge_runs/889e429f6d07
```
- `--next 20` 은 아직 안 한 질문부터 번호순으로 20개. 같은 명령을 다시 부르면 이어서. 429 는 알아서 기다린다.
- 결과 줄에 `problems`(인용 불일치·판정 없음)가 있으면 보류 — 묶음마다 `report` 로 보고.
