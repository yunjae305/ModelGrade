## 2. 설정 확인 (평가 PC, `.env` — 값은 출력하지 않는다)

- GPT CLI: `codex login status` 가 로그인 상태인지. `.env` 의 `CODEX_CLI_PATH`(없으면 PATH 의 codex)·`CODEX_CLI_MODEL`(기본 gpt-6.1-sol)·`CODEX_CLI_REASONING`(기본 high)·`CODEX_CLI_TIMEOUT`(기본 1800초)·`SEMANTIC_WEB_SEARCH=live`(J5-1 사실 확인에 웹 검색).
- Jev: `TYPESAFE_API_KEY` 가 있는지(키 이름만 확인), `JEV_MODEL`, `JEV_MAX_STATE_CHARS`(기본 150000 — 넘는 질문은 GPT 가 J1~J4 도).
- 키가 없으면 그 사실만 사용자에게 알리고 멈춘다(대신 넣지 않는다). Jev 키가 없으면 J1~J4 도 GPT 가 판정 — 이것도 알린다.

## 3. 시험 판정 — 질문 9개 × AIONA·GPT

종류별 하나씩: Q36 단일·사실 확인 · Q17 10턴 대화 · Q56 2턴 대화 · Q1 긴 문서(Jev 입력 상한 → GPT 대신 예상) · Q30 TXT 첨부 · Q46 PDF · Q47 이미지 · Q48 DOCX · Q31 빈 출력 요구(보내지 않고 보류여야 함).

```bash
python -X utf8 tools/judge_run.py data/comparison_runs/8c61f117e661.json --only 36,17,56,1,30,46,47,48,31 --providers aiona,gpt --out data/judge_runs/pilot-v3
```

확인하고 표로 보고:
1. `data/judge_runs/pilot-v3/summary.md` — 모델별 PASS·FAIL·보류, GPT 대신 판정 수, 평균 시간(GPT·Jev).
2. `results.jsonl` 에서 `problems` 가 있는 항목 수와 종류(판정 없음 = 빠진 항목, 인용이 원문에 없음, 선택지 밖). 특히 Q17(10턴)에서 빠진 항목이 있는지.
3. `calls` 의 상태 — Jev `TOO_LONG`·`ERROR` 와 이유, GPT 실패. Q1 은 Jev TOO_LONG → `gpt_fallback` 이어야 함. Q31 은 `held_empty_output`.
4. J5-1.a 가 UNVERIFIED 로 많이 나오는지(웹 검색이 실제로 됐는지 — `calls.gpt.search`).
5. 질문 하나 판정 시간(분) → 326 × 4 모델 예상 시간. 구독 사용 한도에 몇 번째에서 걸렸는지.

## 4. 판단

- 문제가 없으면 사용자에게 전체 실행 확인을 받고 5번.
- 문제가 있으면(빠진 항목이 많음, 규칙을 안 따름, 출력 형식 오류) **전체 실행 전에** 고친다 — 프롬프트를 고치면 v4 새 파일(`tools/build_judge_prompt_v3.py` 를 바탕으로 v4), v3 는 그대로 둔다. 실행 도중에는 고치지 않는다(결과가 섞임).
