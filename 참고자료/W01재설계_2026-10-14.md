### A. 왜 CODE 검사와 의미 평가를 함께 쓰고, 기준별로 만드는가

- **CODE 검사**(`code_eval` 엔진): 개수·글자 수·표 모양·계산값처럼 정답이 정해진 것을 규칙으로 센다 — 빠르고 비용 0, 늘 같은 결과. 의도·논리는 판단하지 못한다.
- **의미 평가**(Claude 심사, `jev_*`): 의도·대상·논리·사실·대화 맥락처럼 읽어야 아는 것을 판단 — 비용이 들고 판정이 맞는지 사람 검수가 필요하다.
- 함께 쓰는 이유: 한쪽만 쓰면 '형식은 맞는데 엉뚱한 답'(CODE 만) 또는 '내용은 좋은데 200자 제한 위반'(의미 평가만)을 놓친다.
- 유형별 → 기준별: 멘토(10-13 미팅)가 '유형 7개 × 30개'로는 세부 기준마다 몇 번 평가되는지 알 수 없다고 지적, 사용자 결정(10-13, 생성기 코드 머리말) '세부 평가 항목 전부를 가장 적은 개수로'.
- 질문 하나에 여러 기준: 멘토(10-13) '한 질문이 여러 항목을 평가하니 더 줄 수 있다'. 실제 300개 세트에서 질문 하나에 세부 기준이 **평균 9.7개** 적용됐다(늘 적용 검사 제외) — GPT 가 목표로 적은 평균 1.7개보다 훨씬 많다.

## 3. 질문 생성 프롬프트의 구성 근거

### 프롬프트는 3종이 아니라 7종

기존 화면의 원문 3개는 **질문 300개를 요청할 때 처음 보내는 대표 호출**이었다. 실제 함수는 7종이며, 나머지 4종은 앞 단계 결과로 내용이 달라져 이번에 **예시 입력**(질문 세트 300 점검 결과·예시 주제)으로 만든 원문을 '기술 자료'에 추가했다(실제로 보낸 원문 아님).

| 함수 | 역할 | 언제 |
|---|---|---|
| `plan_prompt` | 첫 계획 — 모든 기준을 덮는 질문 최대 40개 | 생성 시작 1번 |
| `multi_turn_prompt` | 10턴 대화(J6) 전용, 한 번에 4개 | 질문 수를 정했을 때 |
| `long_context_prompt` | 긴 문서(J7) 질문 (+ 같은 문서로 질문을 더 만드는 변형) | 질문 수를 정했을 때 |
| `supplement_prompt` | 보충 — 한 번도 적용 안 된 기준·첨부 종류만 | 최대 2번 |
| `extra_prompt` | 추가 — 목표 수까지 적게 적용된 기준을 노려 40개씩 | 목표에 못 미치면 반복 |
| `_material_prompt` | 질문이 아니라 긴 문서 본문 조각 | 문서 하나에 수십 번 |
| `_paste_prompt` | 질문이 아니라 대화에 붙여 넣을 자료 | 자료가 필요한 턴마다 |

## 4. 질문 300개를 만든 목적과 실제 결과

- 목적: 사용자 요청(10-14) '질문 300개를 만들어 시험'. 필요한 수를 계산해 정한 값이 **아니다**(실험 설정).
- 만든 판: question-gen-v1.2 (GPT gpt-6-luna), 질문 300 · 턴 450 · 첨부 질문 9 · 10턴 대화 1 · 긴 문서 질문 1. 난도 쉬움 42 · 보통 120 · 어려움 138.
- 목표 기준 적용: GPT 가 적은 목표 498건 → 답이 있어야 아는 11건 보류 → 판단 가능 487건 중 **적용 245건(50.3%)**, 미적용 242건.
- J6 불일치: J6 목표 177건 = 10턴 대화 1개에서 8건(전부 적용) + **2~4턴 짧은 대화 103개에서 168건(0 적용)** + 1턴 질문 1건(0). 짧은 대화는 모두 Q55~Q300 — 첫 계획 40개(Q1~Q40, 대화 1개뿐) 뒤 보충·추가 단계에서 나왔고, v1.2 '질문 추가' 프롬프트에는 10턴 조건이 없었다(`776f3bd` 코드 확인). 평가기 J6 조건은 최신 main 에서도 multi-turn-v2(10턴 이상 · 대화 전체 10K 토큰). **AI 답변 품질 문제가 아니라 생성 조건과 평가 조건의 불일치**다. J6 를 빼면 76.4%.
- 질문 수 증가: 채울 기준 80개 중 생성 순서로 10개 → 30, 50개 → 68, 100개 → 71, 300개 → 77. 무작위 순서 평균 10개 25.6 · 50개 52 · 100개 62.5 · 300개 77. 5번 이상 시험된 기준은 300개에서 52개. 50개 이후 250개가 더한 기준은 9개뿐이다.
- 중복: 첫 문장이 완전히 같은 질문 3개(Q1·Q137·Q168 '아무것도 출력하지 마.'), 3글자 단위 유사도 0.5 이상 쌍 5개. 20자 이하 단일 질문인데 '어려움' 표시 1개(Q250 '96을 8로 나누면 값은?').
- 평가 비용 추정(참고, 다른 실행의 답변당 비용으로): 질문 50개(59턴)×3개 시스템 약 $23 · 100개 약 $50 · 300개 약 $177. 생성 비용은 기록이 없어 계산하지 않았다.
- 판단: 기준별 시험 횟수가 크게 고르지 않으므로 '질문 수'가 아니라 '기준마다 몇 번 시험되는지'를 목표로 만들어야 한다(v1.4 `per_target`). 몇 개가 필요한지는 평가 결과로 W03 에서 실험해야 하며, 지금 데이터로 적정 질문 수를 정하지 않는다.

## 10. 발표용 1분 대본

> AI 답변을 평가하려면 먼저 시험 문제가 필요합니다. 저희 평가 기준은 프로그램이 정확히 세는 CODE 검사와, AI 심사위원이 내용을 읽는 의미 평가 두 가지인데, 질문은 이 기준을 하나하나 실제로 시험하도록 만듭니다.
>
> 방법은 이렇습니다. 기준 목록을 그대로 GPT 에 주고 질문을 만들게 한 뒤, 평가기와 똑같은 규칙으로 '그 기준이 정말 켜지는지' 점검하고, 빠진 기준만 다시 요청합니다. 한 번에 40개씩 요청하는 건 답이 잘리지 않게 하려는 기술 설정이고, 40개가 가장 좋다는 실험은 아직 없습니다.
>
> 실제로 만든 300개를 점검해 보니, GPT 가 시험하겠다고 적은 기준 중 50.3%만 실제로 켜졌습니다. 이건 AI 의 정답률이 아닙니다. 빗나간 것의 대부분은 긴 대화 기준 J6 였는데, 2~4턴짜리 짧은 대화로 만들었기 때문입니다. 평가기는 10턴 이상 대화만 J6 로 봅니다. 또 질문을 50개에서 300개로 늘려도 새로 시험된 기준은 9개뿐이었습니다.
>
> 그래서 다음 단계는 세 가지입니다. 새 생성기 v1.4 로 소량을 실제로 만들어 같은 점검을 다시 하고, 질문 수 대신 기준마다 몇 번 시험되는지를 목표로 하며, 몇 개가 필요한지는 평가 결과와 사람 검수로 W03 에서 정하겠습니다.
