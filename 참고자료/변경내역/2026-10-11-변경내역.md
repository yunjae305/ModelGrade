## 상세 변경

- 의미평가용 모델·effort·주소·시간·출력·검색·조회·이어가기 설정은 `SEMANTIC_ANTHROPIC_*`로 분리했습니다. 답변 수집용 `ANTHROPIC_MODEL`과 별개이며, 현재 키 값과 수집 설정은 그대로입니다. 명시한 Claude API 키가 없으면 설정 오류로 남기고 CLI로 대체하지 않습니다.
- J1~J6, 전체 question·answer·reference·history, 모델 식별 메타데이터를 제거하는 블라인드 입력을 유지합니다. 원문을 잘라 보내거나 context compaction을 허용하지 않습니다. strict 스키마에서 지원하지 않는 수치 범위는 설명으로 전달하고 로컬 판정 검증에서 다시 확인합니다.
- 참조 자료가 없는 J5에 `web_search_20250305`와 `web_fetch_20250910`을 제공합니다. 서버 도구 ID가 연결된 실제 결과만 출처로 인정하고, 도구 오류·미완료 응답·인용 불일치·검색 없는 근거 주장은 완료 판정으로 통과시키지 않습니다. J6의 과거 대화 인용 대조도 유지합니다.
- 정상 `pause_turn`의 응답 블록을 그대로 이어 보내며, 최대 2회 이어가기와 API 요청 전체 180초 한도를 적용합니다. 검색 4회·원문 조회 8회는 문항 전체 예산으로 관리합니다. 후속 요청에서 이미 사용한 횟수를 빼며, 이어가기에 필요한 예산이 없으면 미완료 상태로 종료합니다. HTTP 오류·잘린 최종 출력·누락된 판정에는 자동 재시도하지 않습니다.
- 진행 중 HTTP는 취소 토큰으로 중단합니다. 시작하지 않은 요청은 비용 호출 수에서 제외하고, 이미 시작했지만 사용량이 돌아오지 않은 요청은 미확인으로 남깁니다. 원격 제공자에서 발생한 실행과 비용까지 취소된다고 보장하지 않습니다.
- 비용은 요청별 `cost_parts`를 런타임에서만 합산합니다. 검색 비용, 캐시 읽기 및 5분·1시간 쓰기, 표준 서비스 등급, 응답의 추론 지역을 반영합니다. 검색 토큰과 thinking 토큰을 이중 계산하지 않고, 필수 사용량이 없으면 알려진 부분과 미확인 부분을 구분합니다. 달러 금액은 UI·저장 결과에 추가하지 않았습니다.
- `code_eval.semantic_check` 기본 실행은 설정만 읽으며 모델 호출이나 CLI 로그인 확인을 하지 않습니다. 실제 연결 확인은 별도 smoke 옵션이나 평가 실행으로 구분합니다. README에 현재 모델과 설정 확인 명령을 추가했습니다.

## 영향 및 호환성

- ENV에 Claude 의미평가 전용 설정을 추가하고 실제 엔진을 전환했습니다. 현재 설정 검사는 `ready: true`, `engine: anthropic_api`, `model: claude-sonnet-5-5`, `reasoning_effort: medium`입니다. `auto`의 기존 호환 동작과 다른 엔진의 명시적 선택은 유지합니다.
- 외부 의미평가 요청은 Claude `POST /v1/messages`를 사용합니다. 워크스페이스의 업로드·수집·평가 API 계약과 기존 저장 판정은 유지하며, 새 실행의 평가 조건 기록에 엔진·모델·effort·도구 한도를 보존합니다. 이전 평가자와 다른 조건의 결과를 같은 조건으로 간주하지 않습니다.
- UI 디자인과 파일 업로드 흐름은 유지했습니다. 기존 원본·저장 자료 26개 SHA-256이 모두 동일합니다. 앞서 중단한 `e2a098cc7d65`도 `CANCELLED` 상태와 22:58:12 수정 시각이 그대로이며 이번 작업에서 고객 전체 자료를 재평가하지 않았습니다.
- 8080 서버는 종료 상태입니다. `py -3 -X utf8 run.py`로 실행하면 새 의미평가 설정을 사용합니다. 기존 기록의 중단 작업을 자동 재호출하지 않습니다.
- 실사용 검사는 공개·합성 3문항입니다. 고객 자료 272건의 총 완료 시간, 제공자 rate limit, 모든 문항의 판정 품질을 검증한 결과는 아닙니다. PDF·MathML 출처 등 기존 근거 수집 한계도 그대로입니다.
