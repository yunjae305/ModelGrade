## 기존 → 변경 후

| 구분 | 기존 (semantic-binary-outcome-v2) | 변경 후 (semantic-hold-unverified-v3) |
|---|---|---|
| 근거 부족 UNVERIFIED (J1~J8) | FAIL `EVALUATION_EVIDENCE_INSUFFICIENT` | **보류** — `status: UNVERIFIED` 유지, `decision: None`, 같은 reason_code, 사유 "보류 — …", `decision_policy.outcome_basis: held_for_review`, `review_required: true` |
| 출처 원문 확인 실패 (J5, j5-source-original-failure) | FAIL `SOURCE_ORIGINAL_UNAVAILABLE` | **보류** (v3) |
| 확인된 사실 오류·출처 불일치·답변이 든 URL 접근 불가 | FAIL | FAIL (그대로) |
| 검색 불가·도구 오류 | INCOMPLETE | INCOMPLETE (그대로) |
| J5 사유 라벨 | — | `held` "보류 — 확인하지 못해 사람이 판단" 추가 |

집계는 바꾸지 않았다 — 보류는 이미 있던 `unverified`/`pending`·`review_required`(확인 필요) 칸으로 센다. 화면의 '확인 필요' 가 곧 보류다.

## 영향

- 질문 단위 판정: 유효 FAIL 이 하나라도 있으면 FAIL, 없고 보류가 있으면 보류(분모 유지), 모두 통과면 PASS.
- 실험 300문항 기준 보류 수(J5 확인 실패 + 심판 갈림): GPT 13 · Claude 29 · Gemini 32. 이 중 B·D 는 아래 2·3번 수정으로 줄어든다.
- 이전 결과는 다시 계산하지 않는다. 새 결과에는 `semantic-hold-unverified-v3` 가 기록된다.
