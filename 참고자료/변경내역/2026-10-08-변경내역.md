# Codex · 2026-10-08 · 공통 미판정 조건의 PASS/FAIL 보완

**주요 파일**: `code_eval/common_adjudication.py`, `code_eval/jev_eval.py`, `code_eval/jev_criteria.py`, `code_eval/combined.py`, `code_eval/report_html.py`, `frontend/src/workspace-results.js`, `frontend/src/workspace.js`, `frontend/workspace.html`, `frontend/code-eval.html`, `frontend/src/code-eval.js`, `frontend/src/code-eval.css`, `tests/test_common_adjudication.py`, `tests/test_jev_eval.py`, `tests/test_code_eval_v16.py`, `참고자료/SERVICE_UI.md`.

## 배경

사용자가 AIONA 특화 내부 마커·금지 규칙을 제외한 기준은 PASS 또는 FAIL로 보여야 한다고 요청했습니다. 이전 Q165 비교에는 부분 범위 문장 수, 혼합 자료형 정렬, YAML 내부 목록, 단위·부정 문맥 등에서 공통 CODE 미판정 조건 29개가 남아 있었습니다. 기존 J1~J6는 코드 영역을 중복 판단하지 않으므로 의미 평가가 성공해도 미판정이 해소되지 않았습니다.

적용 대상이 없는 기준의 표시 방식을 별도로 질의했고, 회신 전에는 기존 적용 정책을 유지한다고 안내했습니다. 단일턴 J6 등의 ‘해당 없음’은 유지하며, 적용되는 공통 미판정만 보완합니다. 호출 실패를 품질 PASS/FAIL로 임의 변환하지 않습니다.

## 기존 → 변경 후

| 구분 | 기존 | 변경 후 | 변경 이유 |
|---|---|---|---|
| 공통 코드 미판정 | UNSUPPORTED 등이 최종 판단 보류로 남음 | 같은 의미 평가 요청에 C 기준을 추가하여 PASS/FAIL·확신도·근거를 받음 | 코드 해석 범위 밖의 적용 조건을 원문으로 보완 |
| 코드 판정 보존 | CODE와 의미 평가를 분리 보관 | 코드 원본·해시 유지, code_completion에 별도 판정·표시용 결과 추가 | 기존 확정 판정을 재판정하지 않고 변경 근거를 추적 |
| 화면과 보고서 | 코드 원본의 미판정 수가 계속 표시됨 | 공통 조건 집계·질문 상태·기준 비교·상세·HTML에 보완 판정을 일관되게 반영 | 보완 완료 후에도 미완료로 보이는 불일치 방지 |
| 질문 단위 집계 | 보고서에서 일부 PASS만 있어도 미완료 질문을 통과로 계산할 수 있음 | 적용 조건과 의미 기준이 모두 완료되어야 PASS, FAIL 우선, 나머지 평가 미완료 | 호출 장애나 미판정이 통과율을 높이지 않게 수정 |
| 특화·비적용 | 공통과 특화가 종합 질문 FAIL에 섞일 수 있음 | 내부 마커·금지 표현은 별도 집계, 비적용 기준은 해당 없음 유지 | 모든 모델에 동일한 공통 비교 범위 적용 |

## 상세 변경

- CODE 공통 미판정만 조건 ID·인덱스로 연결합니다. 원문 질문·답변·전체 이력·참조 데이터는 보존하고, 코드의 확정 판정·측정값·공급자 정보를 평가 프롬프트에 넣지 않습니다. C 기준의 판정 지침은 기존 소분류의 검사 범위와 PASS/FAIL 기준을 사용합니다.
- J1~J6와 C 조건을 질문당 한 호출에서 받되 응답 검증은 독립적으로 처리합니다. 보완 근거 누락, 잘못된 판정, 시간 초과, 호출 예외를 기록하며 유효한 다른 그룹의 판정은 유지합니다. JEV 단계 버전은 `jev-semantic-eval-v2.4`, 보완 버전은 `common-adjudication-v1`입니다.
- 성공한 보완 결과는 `jev_eval.records[].code_completion`에 저장합니다. 원본 CODE cases·summary·result_digest는 변경하지 않고 표시할 때만 결과와 집계를 합칩니다. HTML에서 LLM 보완과 코드 원래 미판정 사유를 구분합니다.
- 비교 카드·범례·질문 상태는 PASS/FAIL을 명시하고, 수집·평가 장애는 ‘평가 미완료’로 표시합니다. 기존 4개 모델 카드·9개 비교 행·상세 보고서 구조는 유지합니다.
- 종합 통과율은 실제 판정된 질문으로 계산합니다. 알려진 FAIL이 있으면 미완료 상태에서도 FAIL을 보존하며, AIONA 특화 위반은 공통 질문 판정에 합치지 않습니다.
