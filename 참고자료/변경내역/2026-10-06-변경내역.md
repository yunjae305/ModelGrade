# Claude · 2026-10-06 · CODE + Jev 하이브리드 평가

**주요 파일**: `code_eval/jev_criteria.py`(신규), `code_eval/jev_client.py`(신규), `code_eval/jev_eval.py`(신규), `code_eval/__main__.py`, `code_eval/__init__.py`, `code_eval/report_html.py`, `code_eval/taxonomy.py`, `webapp/code_eval_service.py`, `frontend/code-eval.html`, `frontend/src/code-eval.js`, `frontend/src/code-eval.css`, `.env.example`, `tests/test_jev_eval.py`(신규), `tests/conftest.py`, `tests/test_code_eval_v16.py`, `results/set2_q100/`

## 배경

사용자가 "객관적 검증은 CODE, 의미 품질은 Jev" 원칙으로 Decision AI Jev(TypeSafe System One)를 추가하도록 요청했다. Jev 기준은 J1 의도 충족성·J2 내용 적절성·J3 논리 타당성·J4 충분성 4개로 제한하고, CODE와 Jev 결과는 합산하지 않고 따로 보여 준다. 기존 LLM 재검토는 "Jev로 바꾸는 것"이라고 사용자가 정했고, 코드는 지우지 않고 별도 실행으로 남겼다. 작업은 단계마다 결과를 보이고 확인받으며 진행했다.

## 기존 → 변경 후

| 구분 | 기존 | 변경 후 | 변경 이유 |
|---|---|---|---|
| 기본 평가 흐름 | CODE 필수 → CODE FAIL 질문만 LLM 재검토(5개 항목) | CODE → Jev 의미 평가(J1~J4, 모든 질문). CODE PASS·FAIL과 관계없이 평가하고 CODE 판정·결과 해시는 바꾸지 않음 | 사용자 결정 ("기존 LLM 검토 방식을 Jev로 바꾼다") |

## 상세 변경

- J1~J4 정의는 `code_eval/jev_criteria.py` 한 곳에만 둔다. Jev 요청 문구, 보고서 기준 카드, 화면 판정 방법 탭(`/api/code-eval/info`의 `taxonomy.jev`)이 모두 이 정의에서 만들어진다.
- CLI는 CODE 단계의 네트워크 차단(`_code_phase_guard`)을 그대로 두고, 그 뒤에 Jev 단계를 실행한다. 그래서 CODE와 Jev는 동시에 돌지 않는다. Jev 단계 안에서는 질문 4개를 동시에 호출한다.
- Jev 기록은 `batch["cases"]`와 같은 순서로 저장한다(같은 case_id가 있어도 순서로 대응).
- 오류 문구는 `redact`를 거쳐 저장하고, 인증값은 결과·로그·manifest에 남기지 않는다.
- 테스트 중에는 `.env`에 키가 있어도 실제 Jev를 부르지 않는다(`tests/conftest.py`).
- 기존 테스트 3개를 새 기본 흐름에 맞게 고쳤다: CLI 기본 흐름(LLM → Jev), 웹 LLM 재검토(요청할 때만), 보고서 기준 섹션(02 = Jev).
- 새 테스트 9개: 정상 답변(공식 REST 형태 확인), CODE 형식 FAIL에도 Jev 평가, 형식은 맞지만 J2·J3·J4 FAIL(3개), Jev 장애 3종(API_ERROR·TIMEOUT·INVALID_RESPONSE), 키 없음. Jev 판단은 대역 응답으로 흉내 냈다. 실제 Jev의 판단 품질은 검증하지 않았다.

## 영향 및 호환성

- CODE 판정은 바뀌지 않았다. set2 100문항 결과 해시 `e9a9ffc40014b6b1`(2026-10-02와 같음).
- 키가 없으면 Jev는 `NOT_CONFIGURED`로 기록되고 CODE 결과는 그대로 나온다.
- `results.json`에서 `llm_review`가 빠지고 `jev_eval`이 생겼다. 예전 결과 파일(`jev_eval` 없음)도 보고서·화면에서 "Jev 결과 없음"으로 표시된다.
- v18 기준 HTML의 운영 탭 흐름도는 아직 "CODE 필수 → FAIL 질문만 LLM 재검토"로 적혀 있다(CODE 기준은 바뀌지 않아 이번에 고치지 않음).
