## 배경

사용자가 v19 HTML·다른 참고자료·저장 보고서와 현재 구현의 일치 여부를 검토하도록 요청했다. 기존 테스트 132개와 Q100 결과는 재현됐지만, 추가 입력에서 정상 음수 계산과 목록을 FAIL로 판정하거나 의미 평가 기준이 빠지는 오류를 확인했다. 사용자가 이 오류들의 수정을 요청하여 판정·파싱·라우팅과 결과 탐색·작업 보관을 보완했다.

## 상세 변경

- 계산 숫자는 일반 개수·분량 파서와 분리하여 부호를 처리한다. `%` 결과는 질문 계산값 연결에서도 일반 숫자로 대신 사용하지 않는다.
- 목록 도입 설명, 들여쓴 설명, 빈 줄 없는 이어지는 문단, 중첩 항목을 처리한다. 실제 네 번째 항목은 계속 FAIL로 검출하고 독립 문단으로 구분된 다른 목록은 합치지 않는다.
- history 축약은 기존 턴당 2,000자·필요시 오래된 답변부터 300자 정책을 유지한다. 그래도 상한을 넘으면 `HistoryLimitExceeded`를 배치 단계에서 처리한다. J1~J5의 독립 평가 경로는 유지하며, 해당 턴 J6는 제외한다. 앞선 턴에 J6 FAIL이 있으면 대화 FAIL은 유지한다.
- HTML의 기존 고유 ID 앵커는 보존하고 중복 표시 ID에만 충돌 없는 키를 부여한다. 종합 FAIL, 코드 위치, 별도 LLM 재검토, 대화 턴·첫 FAIL 링크까지 같은 키를 사용한다. 과거 대화 결과는 대화 ID·턴·표시 ID로 유일하게 대응하는 경우 연결한다.
- 엔진 `aiona-code-eval-v16.2.4`, 구조 분석 `v16-analysis-1.1`, 추출 `v16-extract-1.5`, 의미 평가·적용성 `v2.1`로 버전을 갱신했다. 의미 평가 기준 J1~J6의 정의는 유지했다.
- 측정 규칙과 구현 연결표에 수정된 동작 및 회귀 테스트 경로를 반영했다.

## 영향 및 호환성

- 입력 형식, 사용자 `case_id`, DB, ENV, 인증 및 의미 평가 엔진 연결 설정은 변경하지 않았다. 원본 Q100과 기존 `results/`·저장 실행 결과는 덮어쓰지 않았다.
- 결과 JSON의 `combined.problems[]`와 `jev_eval.conversations.items[].turn_results[]`에 0부터 시작하는 `case_index`를 추가했다. 기존 필드는 유지한다.
- `/api/code-eval/jobs`는 모든 보관 슬롯에서 작업이 실행 중일 때 HTTP 429를 반환한다. 완료된 작업은 기존처럼 오래된 순서로 보관 대상에서 정리한다.
- Q100 판정·측정값·집계·J 선택은 기존과 같다. 검사 버전 기록이 바뀌므로 CODE 결과 해시는 `e9a9ffc40014b6b1…`에서 `921152184d462d7f…`로 변경됐다.
- 실제 Jev 연동과 AIONA 운영 설정·표시본의 미완료 상태는 이번 수정 범위 밖이다.

# Codex · 2026-10-07 · 응답 수집 완료 후 블라인드 배정과 평가가 시작되도록 단계 정리

## 배경

사용자가 파일 업로드 후 평가 시작 버튼을 누르면 세 제공자의 답변을 받은 다음 블라인드 처리와 평가를 진행해야 한다고 순서를 명확히 했습니다. 실제 CODE·LLM 평가는 수집 종료 후 실행되고 있었지만, 모델 A~D 배정과 화면 가림은 실행 생성 시점부터 적용되고 있었습니다. 수집 단계에서 어떤 제공자에 요청하고 있는지 확인하기 어렵고, 요청한 단계 순서와 화면이 일치하지 않았습니다.

## 기존 → 변경 후

| 구분 | 기존 | 변경 후 | 변경 이유 |
|---|---|---|---|
| 블라인드 배정 | 실행 생성 시 A~D 배정 | 수집 종료 후 평가 직전에 한 번 배정 | 답변 수집 → 블라인드 → 평가 순서를 코드에도 명시 |
| 수집 화면 | 수집 중에도 모델 A~D·평가 대기 표시 | 실제 제공자명과 답변 수집 중·대기·종료 표시 | 답변을 받는 단계와 평가 단계를 구분 |
| 시작 버튼·단계 안내 | 4개 모델 수집·평가 시작, 일반적인 응답 수집·평가 안내 | 평가 시작, 세 모델 답변 수집과 이후 블라인드 평가 안내 | 한 번의 시작으로 전체 작업이 이어진다는 사용자 흐름 반영 |

## 상세 변경

- 수집 시작에는 `blind_requested`만 저장합니다. 세 제공자 수집이 끝나면 `collection_completed_at`을 기록하고, 평가 시작 직전에 블라인드 매핑과 `applied_at`을 생성한 뒤 평가 스레드를 시작합니다.
- 수집 중 직접 평가 요청은 기존처럼 거부합니다. 수집 취소 시 블라인드 매핑·수집 완료 시각을 만들지 않고 자동 평가도 시작하지 않습니다. 수집 오류·미완료 처리 및 명시적 평가 재시도 동작은 유지합니다.
- 기존 매핑이 있는 과거 기록과 재평가는 A~D 순서를 다시 배정하지 않습니다. 질문·답변·모델별 멀티턴 이력과 평가자에게 보내는 필드는 그대로 유지합니다.
- 수집 화면에 실제 제공자 이름을 표시하고, 현재 순차 수집 순서에 따라 진행 상태를 표시합니다. 평가 단계 진입 후에는 네 모델을 A~D로 가립니다. 원문에 포함된 이름은 계속 보존합니다.
- 기능 정보에 `blind_after_collection: true`를 추가해 이전 서버에는 재시작 안내를 표시합니다. 기존 plain CSS를 사용하며 화면 구성·평가 기준·모델·키 설정은 변경하지 않았습니다.
