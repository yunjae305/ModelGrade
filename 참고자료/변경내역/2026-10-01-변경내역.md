# Codex · 2026-10-01 · 코드 평가 HTML 보고서의 기준과 결과 화면 개선

**주요 파일**: `code_eval/report_html.py`, `tests/test_code_eval_v16.py`, `results/code_only_v17_q100/report.html`, `results/code_eval/sample/report.html`

## 배경

기존 보고서는 소분류와 특화 평가를 표로만 나열해 세 대분류와 각 기준의 의미를 먼저 파악하기 어려웠다. 고객이 요청한 L1~L4도 보이지 않았다. 저장소에는 L1~L4의 공식 번호 연결과 해당 실행 결과가 없지만, `docs/source/채팅품질 평가기준.md`에는 LLM 비교용 기본 4축이 있다.

## 기존 → 변경 후

| 구분 | 기존 | 변경 후 | 변경 이유 |
|---|---|---|---|
| 공통 기준 | 8개 소분류 집계표 | 3개 대분류 카드 안에 8개 세부 기준의 설명과 검사 건수 표시 | 평가 체계를 먼저 읽고 결과를 이해할 수 있도록 |
| LLM 기준 | 보고서에 표시 없음 | 기존 지식베이스의 기본 4축을 L1~L4에 표시용으로 임시 대응하고 이번 실행 미평가 상태 표시 | 기존 설명을 활용하면서 공식 번호 연결과 실제 판정 결과의 부재를 드러내기 위해 |
| 특화 기준 | 2개 항목 집계표와 긴 설정 JSON | 각 기준의 조건·검사 방법·결과 카드, 적용 대상 아님 건수 표시, 설정은 접기 | 고객이 적용 범위와 0건의 의미를 구분하도록 |
| 결과 요약 | 검사 PASS/FAIL 수 중심의 동일한 카드 | 실패가 있는 질문 수, 검사 PASS/FAIL/미판정 수, 통과율 계산 범위를 분리 | 질문 수와 검사 건수를 혼동하지 않도록 |
| 질문 상세 | 질문별 검사 내용·실패 이유·문제 위치 제공 | 기존 상세와 FAIL 이동 링크 유지 | 실패 근거를 계속 확인할 수 있도록 |

## 상세 변경

- HTML 생성기에 기준 설명과 결과를 연결한 상단 카드, 요약 영역, 모바일 레이아웃과 키보드 초점 표시를 추가했다.
- 기존 `results.json`을 사용해 100문항 보고서와 샘플 보고서를 다시 생성했다. 평가 엔진과 판정 데이터는 변경하지 않았다.
- 공통 기준, L1~L4, 특화 기준이 질문별 결과보다 먼저 표시되는 회귀 검사를 추가했다.

## 영향 및 호환성

- 생성되는 `report.html`의 화면만 변경된다. DB, ENV, API, 인증, `results.json` 형식 변경 없음.
- L1~L4 번호와 기본 4축의 연결은 보고서 표시용 임시 대응이다. 공식 번호 연결과 이번 실행의 LLM 결과가 없으므로 점수를 계산하지 않는다.
