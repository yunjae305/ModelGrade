# AIONA 코드 평가기 v16 — 측정 규칙과 실제 지원 범위

엔진: `aiona-code-eval-v16.3.1` (`code_eval/`) · 원본 기준: `참고자료/채팅품질 평가기준.md` (sha256 `fb7126e7…`, v16 HTML 인용본과 동일)

이 문서는 **구현된 동작**을 적는다. 기준을 새로 설계하지 않는다. 원본 MD 에 없는 규칙은 "구현 결정"으로 표시한다.

## 1. 공통 원칙 (구현 확인됨)

| 항목 | 구현 |
|---|---|
| 판정 | `PASS` / `FAIL` / `null` 만. severity·주의·심각·HOLD·가중치 없음 |
| 실행 상태 | `EXECUTED` · `CONFIG_MISSING` · `DISPLAY_MISSING` · `INCOMPLETE` · `UNSUPPORTED` · `DEPENDENCY_FAILED` · `CHECK_ERROR` · `LIMIT_EXCEEDED` · `OUT_OF_SCOPE` · `DUPLICATE` · `APPLICABILITY_EXCEPTION`, 케이스 단위 `INPUT_ERROR` |
| 통과율 | `PASS / (PASS + FAIL)`, 분모 0 → `null`. 미판정·관측은 분모 제외. AIONA 특화는 공통 통과율과 별도 |
| 해당 없음 | 결과를 만들지 않는다 (분모를 늘리지 않음). 예: 표 요구가 없으면 표 결과 없음 |
| 경로 | 질문 유형 분류·배분 없음. 모든 입력이 같은 검사 함수 목록(`engine._COMMON`)을 지난다 |
| LLM | 이 코드 검사 단계에서는 사용하지 않음. 조건 추출·대상 선택·판정 이유 모두 정규식·파서·고정 템플릿. 기본 후속 단계는 모든 유효 질문에 대한 J1~J6 의미 평가(`code_eval/jev_eval.py`). 코드 FAIL 질문의 옛 LLM 재검토(`code_eval/llm_review.py`)는 별도 실행 |
| 중복 | 같은 대상·조건·범위·정규화의 결과는 `dedupe_key` 로 한 번만 집계 (예: 질문의 금지 문자열과 AIONA 금지 목록이 같은 문자열·같은 표시본) |
| 재현성 | `result_digest` 는 실행 시각·실행 ID·소요 시간을 뺀 결과 해시. 같은 입력·버전·설정이면 같다 (1,500건 재실행으로 확인) |

## 2. 1-1 응답·문자 정상성

- **응답 존재**: `textparse.strip_non_content`. 공백·제어문자 제거 후 1자 이상. 질문이 빈 출력을 명시하면(`아무것도 출력하지 마`, `빈 문자열로 출력`) `APPLICABILITY_EXCEPTION` 이고 준수 여부는 2-1 `explicit_empty` 가 판정. `answer` 필드 누락·비문자열은 `INPUT_ERROR`.
- **문자 규칙**: 등록 서명 4종(U+FFFD, UTF-8→Latin-1 모지바케, C1 제어, 외톨이 서로게이트) + C0 제어 문자(탭·줄바꿈 제외, 구현 결정 — 운영 정책의 "제어 문자"에 대응). `U+XXXX` 를 출력·포함·예시로 **요청**한 경우 그 코드 포인트를 예외로 기록. 그 밖의 깨짐 표기는 한 줄이 아니라 주변 맥락으로 읽는다: 질문이 인코딩·UTF·문자 깨짐을 다루거나, 같은 문단·목록 항목(목록을 여는 줄 포함)·표 행·코드블록 앞뒤 설명 문단에 인코딩·예시 설명이 있으면 예시로 제외한다. 같은 문장이 '결과는·실제 출력·읽은 결과'처럼 실제 결과로 제시하면(예시·가정 표현 없이) FAIL.
- **외국 문자 (`1-1.foreign_script`)**
  - 문자 속성: Unicode 15.1.0 `Scripts.txt` 의 Han·Hiragana·Katakana 구간을 `code_eval/scripts.py` 에 옮김 (Python 표준 `unicodedata` 에 Script 속성이 없어서). Script_Extensions 는 등록한 일부 코드 포인트만(장음 부호 ー, 탁점, 々 등). 한글과 공유되는 부호(、。「」)는 구간을 새로 열지 않는다. 키릴·태국·아랍·히브리·데바나가리 등은 글자·결합 부호의 문자 이름 첫 단어로 판별 (`scripts.OTHER_SCRIPTS`). 라틴·그리스(수식 기호)·한글은 대상이 아니다.
  - 제외 범위: 펜스 코드 구획·인라인 코드.
  - 판정: 구간마다 PASS 근거를 찾는다 — 질문에 같은 종류의 문자·같은 문자열이 있음 / 질문이 그 문자·언어를 다룸(한자·일본어·번역·표기 등) / 따옴표·괄호·인용 안 / 바로 뒤 괄호에 한글 병기 / 같은 문단·목록 항목·표 행·코드블록 앞뒤에 뜻·의미·읽는 법·번역·예시 설명. 근거가 없는 구간이 하나라도 있으면 FAIL 이고 위치·문자열을 근거로 남긴다. 질문에 허용 문자 조건(`한글만` 등)이 있으면 `APPLICABILITY_EXCEPTION` 으로 2-1 에 맡긴다.
  - 관측 레코드 `foreign_script_spans`(`span_text`, `start`, `end`, `scripts`, `surrounding_text`, 구조 표지, `same_text_in_question`)는 위치 기록이며 `context_relevance: null`, `counted_in_pass_rate: false`. 한자 = 중국어로 단정하지 않음. 비율·연속 길이 임계값 없음.
  - 합성 대조 사례: "こんにちは는 ‘안녕하세요’라는 뜻입니다"(질문 주제·뜻 설명 → PASS), "浅草寺(센소지)"(한글 병기 → PASS), "파일을 선택하세요. こんにちは. 이름을 변경하세요."(설명 없음 → FAIL).

## 3. 1-2 문서·코드 유효성

| 조건 | 적용 | 비교식 |
|---|---|---|
| 코드블록 존재 (질문) | `코드블록으로/코드 블록에…` 요구 | 블록 수 ≥ 1 |
| 코드블록 개수 (질문) | `코드블록 정확히 N개` | 블록 수 (op) N |
| 코드블록 금지 (질문) | `코드블록은 쓰지 마` | 블록 수 == 0 |
| 언어 표지 (질문) | `python 코드블록`, `언어 표지 …python` 처럼 명시할 때만 | 모든 블록 info 첫 낱말 ∈ 별칭 (표지 확인이지 언어 인증 아님) |
| 형식 위반 — 코드블록 (MD 165) | 코드블록을 요구한 질문 | **코드 구획 표시 수** < 2 → FAIL (블록 수 아님) |
| 펜스 불균형 (MD 170) | 코드 또는 수식 구획 표시가 1개 이상 | `(코드 표시 % 2 == 1) OR (수식 표시 % 2 == 1)` — 합산하지 않음 |
| JSON 구문 | `json` 표지 블록, 또는 JSON 요구 + (단일 무표지 블록 / 코드블록 없는 본문의 JSON 줄 범위) | RFC 8259 엄격 파싱, NaN·Infinity 거부. 중복 키는 PASS + 관측 기록 |
| Python 구문 | `python/py/python3` 블록, 또는 Python 요구 + 무표지 블록 | `ast.parse` + `compile(dont_inherit=True)` — 실행·import 없음 |
| 짝이 없는 닫는 태그 (MD 169) | 닫는 태그가 1개 이상 | 여는 태그 대응 스택. 자기닫힘·void 요소 제외 |

- 코드 구획 표시: `textparse._fenced_code_blocks`(CommonMark, 펜스 문자·길이 규칙) 기준으로 여는 줄 1 + 닫는 줄 1. 목록 항목 안 펜스는 항목 내용 시작 열에서 0~3칸 들여쓴 것을 인정한다 (v16.2.6). 파일 끝까지 닫히지 않은 블록은 표시 1개. 렌더링 후 화면에서 사라진 것을 0개로 세지 않는다 (원문 구조로 센다).
- 수식 구획 표시: 코드 밖 `$$` 1회 = 1개 (구현 결정. 단일 `$` 는 통화 기호와 구별할 수 없어 세지 않음).
- 구문 판정 제외(`APPLICABILITY_EXCEPTION`/`UNSUPPORTED`): 질문이 오류 예시를 요청, 블록 앞 2줄에 `잘못된·틀린·수정 전·문제 줄…`, 대화형 셸(`>>>`), 트레이스백 로그, 생략 표시(`...`, `(생략)`) 부분 코드, 함수 본문 발췌에서만 나는 오류(`'return' outside function` 등), `jsonc/json5`.
- 태그 검사 범위: `displayed_text` 가 있으면 그 투영, 없으면 답변의 로컬 텍스트 투영(코드 제외·강조 제거) — 결과 `scope` 에 "실제 표시본 아님"을 명시.
- 과거의 "모든 블록 명시 종료" 검사는 복원하지 않았다.

## 4. 1-3 참조 연결 유효성

- 각주: 각주 파서(`[^x]`, `[각주N]`) + 빈 정의(`[^x]:` 뒤 공백) + 제목 형태 정의(`### [각주1] 용어`, 구현 결정). 사용한 각주만 대상. 누락·빈 정의·중복 정의 → FAIL. 이름이 지원하지 않는 형태로 다른 곳에 나오면 `UNSUPPORTED`.
- 인용 번호 `[n]`: 인용 번호 파서. `[n] 설명` 형태 출처 목록이 있을 때만 판정, 없으면 `UNSUPPORTED`.
- 내부 링크 `[..](#anchor)`: 제목 슬러그 규칙. 자동 제목 ID 규칙 차이로 보이면 `UNSUPPORTED`. 외부 URL 접속·출처 신뢰성은 검사하지 않음.

## 5. 2-1 분량·표현 조건

| 요구 | 측정 |
|---|---|
| 불릿 N개 | 코드 밖 최상위 `-`·`*`·`+` 줄 (중첩 제외). 앞 항목의 내용 시작 열보다 덜 들여쓴 같은 종류 항목은 형제로 본다 (CommonMark, v16.2.6) |
| 문장 N개 | `textparse.split_sentences`(마침표 뒤 공백·줄끝, 등록 약어 예외, 소수점·URL 내부 마침표 제외) + **인라인 코드 가림** |
| 문단 N개 | 빈 줄로 구분 (`textparse.find_paragraphs`). 줄바꿈만으로 나눈 줄은 한 문단 |
| 줄 N개 | 코드 밖 비어 있지 않은 줄 |
| 단어·어절 N개 | `textparse.count_words` (공백 구분 어절) |
| 글자 수 | 코드 펜스 밖 본문, 줄바꿈 제외, Unicode 코드 포인트. `공백 제외` 명시 시 공백 제거 |
| N개 추천 등 항목 수 | 단일 번호 목록 → 번호 제목(`### 1.`) → 단일 불릿 목록 → 단일 표 데이터 행 중 하나. 후보가 여럿이면 합산하지 않고 `UNSUPPORTED`. `번호를 붙여` 요구는 번호 구조만 셈 |
| 필수·금지 문자열, 시작·끝 표현 | 따옴표로 지정한 값 (`"완료"라는 문자열을 포함`, `'검토', '논의' 이 네 단어는 쓰지 말고`). 코드 제외·강조 제거·NFC 투영에서 단순 출현. 질문이 `정확히·그대로·똑같이·공백까지·띄어쓰기까지·토씨 하나 안 틀리게`로 정확 일치를 요구하지 않으면 연속 공백·탭·줄바꿈·NBSP 를 공백 하나로 접어 대조 (대소문자·구두점·코드 안 문구·제로폭 공백은 그대로 FAIL) | (§17, 통합 v16.4.0 §20)
| 허용 문자 | `한글만/영문만/대문자만/소문자만` — 문자 범주 L* 만 검사 |

비교 연산: `정확히/딱` ==, `이하/이내/까지/최대/넘지 않게/…를 넘기면 안` ≤, `이상/최소/적어도` ≥, `미만` <, `초과` >. 개수 표현에 수식어가 없으면 == (MD "요구한 개수와 불일치"). **글자 수에 비교어가 없으면 `UNSUPPORTED`**, `정도·약·내외·쯤` 근사 요구도 `UNSUPPORTED` — 과거 "300자 정도 = 정확히 300자" 엄격 정책으로 되돌리지 않음.

적용 범위 판정(실제 수집 답변 점검 후 추가, 구현 결정): 다음은 답변 전체 수로 대체하지 않는다.
- 지시 표현: `이 세 단어는`, `아래 7개 항목을` → 개수 요구가 아님 (조건 생성 안 함)
- 가정: `2문장이면 허전하고` → 조건 생성 안 함
- 항목별: `각 문단은 3문장`, `한두 문장씩`, `각 템플릿은 "…"으로 시작` → `UNSUPPORTED`
- 답변 일부: `제목은 20자 이내`, `상세 설명 한 단락`, `추천을 한 문단으로 덧붙여`, `마지막에 한 줄로` → `UNSUPPORTED`
- 목적어 + 출력 동사(`회의 시간을 한 문장으로 알려줘`)는 답변 전체

인용 안 지시: 질문의 펜스 코드·`>` 인용·표는 자료로 가리고, 다른 큰따옴표 안에 들어 있는 지시(`"'완료'를 포함해줘"를 번역해줘`)는 실행하지 않는다. 따옴표 없는 목록(`실측, 발열, 팬소음`)은 추출하지 않는다 (미지원).

## 6. 2-2 형식·구성 조건 — 표 고정 최소 행 수 삭제

- **MD 164행 "표 행이 2개 미만"은 폐기됐다.** 코드에 고정 최소 행 수 조건이 없다. 1행이나 다른 숫자로 바꾼 하한도 없다. 요구가 없으면 표 행 수 결과를 만들지 않는다.
- **헤더 없는 1행 표.** 칸이 모두 빈 마크다운 헤더 줄은 `header_rows=0`으로 센다(마크다운은 헤더 줄을 생략할 수 없다). 질문이 헤더 없이를 요구했는데 마크다운 표가 한 줄뿐이면 그 줄을 데이터 1행으로 본다. 실제 헤더 줄이 있는 표는 그대로 헤더 1행이다.
- 측정만: `header_rows`, `data_rows`, `total_rows = header_rows + data_rows` (관측 `table_rows`, 집계 제외). Markdown 구분선 `|---|` 은 세지 않는다. 없는 헤더를 가산하지 않는다.
- 표 구조: GFM 표(헤더+구분선) 또는 HTML `<table>`(헤더 없는 표 가능). 양끝 파이프를 생략한 GFM 표(구분선에도 파이프가 있어야 함)와 인용문(`>`) 안의 표도 인정한다 (v16.2.6). 표 문법이 아닌 파이프 문자열은 표로 인정하지 않는다.
- 비교: `데이터 행 N개`/`헤더를 제외한 … N개` → `data_rows`, `헤더 포함 전체 N행` → `total_rows`. 헤더 포함 여부가 없는 `3행` 은 `UNSUPPORTED`. 표가 여러 개면 행 수를 합산하지 않고 `UNSUPPORTED`.
- 열 이름(따옴표 목록, `순서대로` 이면 순서 포함), 열 수, 헤더 있음/없음, 표 금지.
- 목록 형식(`목록으로`, `번호를 붙여`, `불릿으로`; `번호 제목`도 번호 매김으로 인정 — 구현 결정), 목록 금지(`목록으로 나열하지 말고`), 제목 존재·개수(ATX `#`; 굵은 글씨 줄만 있으면 `UNSUPPORTED`, 제목 단계가 여러 개면 개수 `UNSUPPORTED`).
- JSON: 최상위 자료형(`JSON 객체/배열`), 필수 키, 필드 자료형. **1-2 구문 실패면 `DEPENDENCY_FAILED`** — 필드 누락으로 추정하지 않음.
- 질문이 마크다운 기호 사용을 금지하면서 표·코드블록을 요구하면 두 요구가 충돌하므로 구조 조건을 `UNSUPPORTED` 로 둔다.
- 코드·데이터 결과물 안의 구조 (`extract._format_internal_structure`): 질문이 YAML·JSON·CSV·XML·TOML·HTML·SQL·Python 등 결과물을 요청하면(`YAML로 작성`, `파이썬 함수를 작성`, `HTML 표로 만들어`) 결과물 안을 가리키는 목록·표·제목·항목 수 요구(2-1 항목 수 포함)는 Markdown 구조로 세지 않고 `UNSUPPORTED` 로 둔다. 결과물 안으로 보는 근거: 형식 이름이 바로 앞에 붙음(`파이썬 리스트`), 같은 절에 결과물 요청이 있음, 값을 넣는 동사(`넣어`·`반환`·`지정`)나 자료형 단어(`정수`·`문자열`·`배열`)가 함께 있음. 같은 절에서 `정리`·`비교`·`설명` 등으로 답변 구성을 요구하면 판정하고, 둘 다 아니면 모호하므로 `UNSUPPORTED`. `불릿`·`번호 목록`·`마크다운 표` 같은 Markdown 전용 표현은 항상 판정한다. 결과물 요청이 아니라 주제로만 나온 형식 이름(`HTML과 CSS의 차이를 표로`)은 적용하지 않는다.
- 코드블록 조건은 여기서 만들지 않는다 (1-2).

## 7. 3-1 · 3-2 · 3-3

- **3-1 질문 계산**: 지원 틀 — 단가×수량 총액, `A에서 B를 빼`/`더해`/`곱해`/`나눠`, `A의 B%`, 질문 안 산술식. 질문 피연산자와 답변 결과의 양수·음수 부호를 보존한다. 후보가 둘 이상이면 `UNSUPPORTED`. 답변 값 연결 순서: 라벨(`총액은 …`, 등식이면 마지막 `=` 뒤) → 질문 피연산자로만 이루어진 답변 등식 → 답변 전체가 숫자 하나. 연결 값이 없거나 여러 개면 `UNSUPPORTED`.
- **3-1 답변 등식**: `식 = 식 = 값` 연쇄 전체를 `arith` 의 재귀 하강 파서(`_evaluate`, Fraction)로 구간마다 계산해 비교. ×÷ → */, 강조 `**` 제거, 연산자 앞 단위(`1,240,000원 ×`) 제거. `%`가 붙은 값을 일반 숫자로 바꾸지 않으며, 명시적인 `A / B * 100 = N%` 백분율 환산식만 기존 숫자 검산을 적용한다. 그 밖의 퍼센트 등식은 `UNSUPPORTED`. 소수 보고값만 마지막 자리 절반 허용(`_tolerance_for`). 같은 줄·앞 2줄의 부정·오류 표현(`틀린 식`, `NEGATION_MARKERS`) 또는 뒤 2줄의 `올바른 식·정답은` 정정이 있으면 보류.
- 단가 2,000원·수량 3개 질문에 `2,000 + 3 = 2,003` → 답변 등식 PASS, 질문 계산값 FAIL (다른 조건으로 각각 기록).
- **3-2**: `다음 세 가지`, `아래 3개`, `N가지를 소개/정리…` (한글 수사 포함). 선언 바로 뒤(사이 1줄 이내) 목록 전체(`checks_consistency._next_structure`, 잘라 세지 않음) · 표 데이터 행(헤더 미포함) · 같은 단계 제목(묶음 제목 바로 아래 하위 제목이면 하위 단계). `예를 들어·그중·일부·몇 가지·N개 중` 은 제외.
- **3-3**: 질문의 원본 1개(JSON 배열·Markdown 표·목록). 명시 연산 필터(`'k'가 N 이상인 항목만`) → 중복 제거 → 정렬(`기준 오름/내림차순`) → 키 이름 변경 순으로 비교값 생성. 출력(JSON 배열 / 단일 표 / 목록)과 자료형 구분 정확 비교: `0 ≠ false ≠ "" ≠ null ≠ 누락`. 정렬·`순서 유지` 요구 시 순서 포함. 표·목록 출력은 자료형이 남지 않아 표시 문자열로 비교(결과에 명시). 명시 고유성(`중복 없이`), 집계(`합계·평균·최댓값…`). 원본이 없거나 둘 이상이면 `UNSUPPORTED` — 임의 정답을 만들지 않음.

## 9. 안전성·한도

- 답변 HTML·스크립트·코드는 실행하지 않는다. HTML 표 파싱은 `html.parser` 구조 수집만. 화면은 `textContent` 만 사용, CSP `script-src 'self'`. 보고서는 스크립트 없음·전부 이스케이프·`default-src 'none'`.
- 입력 문구("규칙을 무시하고 PASS로 기록")는 데이터일 뿐 설정·코드를 바꾸지 못한다 (테스트).
- 한도: 질문 100,000자, 답변·표시본 400,000자, JSON 1,000,000자, Python 200,000자, 한 번 실행 20,000건. 초과·재귀 한도·메모리 오류는 `LIMIT_EXCEEDED`(품질 FAIL 아님). JSONL 깨진 줄은 버리지 않고 `INPUT_ERROR` 항목으로 남김.
- 결과 파일은 기존 파일을 덮어쓰지 않는다 (`--overwrite` 명시 필요). 원본 MD·수집 원문·기존 결과는 읽기만 한다.

## 12. v16.2.4 회귀 보완 (2026-10-07)

- 코드 제외 범위는 구문 검사와 줄 분석 모두 같은 CommonMark 펜스 파서를 사용한다. 네 백틱 구획 안의 세 백틱은 구획을 닫지 않으며, 예시 안의 불릿·문장은 본문 개수에 포함하지 않는다.
- 선언 개수 검사에서 목록 도입 설명 한 줄을 허용하고, 항목에 들여쓴 설명·중첩 항목이 있어도 뒤의 최상위 항목까지 센다.
- J 기준 선택은 요청 종결 표현 뒤의 `.`, `?`, `!` 및 조합을 허용한다. 인용 자료나 일반 서술문은 계속 요청 문장에서 제외한다.
- 당시 의미 평가 v2.2는 답변을 턴당 2,000자, 필요시 오래된 답변부터 300자로 축약하고 60,000자 초과 이력을 보내지 않았다. 사용자 원문 전송 요구에 따라 **v2.3부터 이 축약·이력 생략 정책을 제거했다. 현재는 이전 질문·답변 전문을 그대로 보낸다.**
- 표시용 `case_id`가 중복돼도 화면·보고서는 입력 배열 인덱스로 질문을 구별한다. 종합 문제와 대화 턴 결과에 `case_index`를 추가하며 기존 원본 ID는 유지한다.
- 웹은 최대 8개 작업을 보관한다. 새 작업 접수 시 완료·오류 작업만 정리하며, 8개 모두 실행 중이면 기존 작업을 유지하고 HTTP 429로 새 요청을 거절한다.

## 13. v16.2.5 추가 검증 보완 (2026-10-07)

- `turn`은 1~20,000의 정수(또는 변환 가능한 십진 숫자 문자열)만 허용한다. 한도는 `LIMITS.batch_cases`와 같다. 잘못된 문자열·범위 초과는 해당 항목만 `INPUT_ERROR`이며 다른 항목은 계속 평가한다. 누락 턴은 개별 번호 전체를 만들지 않고 `2~9999턴` 같은 구간으로 기록한다.
- 파싱된 입력 항목에서 중첩 참조 데이터·메타데이터까지 숫자가 유한한지 검사한다. `NaN`, `Infinity`, `1e400`처럼 비유한수로 읽힌 값은 해당 항목의 `INPUT_ERROR`다. 문자열 안의 `"NaN"`은 그대로 유지한다. JSON 응답·저장·내보내기도 비유한수 토큰을 허용하지 않는다.
- 각주·인용·내부 링크의 사용 위치와 대상 모두 코드 구획·인라인 코드를 제외한 동일한 본문에서 찾는다. 지원 밖 각주 정의는 `UNSUPPORTED`로 기록하고 다른 참조 검사를 계속한다.
- 원본 후보는 펜스와 본문 JSON 배열을 함께 탐색하며 펜스 구간을 이중 집계하지 않는다. 원본이 둘 이상이면 기존 정책대로 `UNSUPPORTED`다.
- 요청 문장의 숫자 사이 소수점은 문장 경계가 아니다. `초등학생도 … 3.14 … 설명해줘`의 소수점 앞 대상·수준 조건을 보존한다.
- CLI `single --answer`는 전달된 문자열을 그대로 평가한다. 리터럴 `\n`을 줄바꿈으로 변환하지 않는다. 실제 여러 줄 답변은 쉘에서 실제 줄바꿈을 전달하거나 JSON/JSONL 파일 입력을 사용한다.
- CLI `run`은 결과 파일 충돌을 CODE·모델 호출 전에 확인한다. `--overwrite` 없이는 기존 파일을 변경하지 않으며, 쓰기 직전에도 충돌을 다시 검사한다.
- 의미 평가 결과의 `criteria[]`에 기준 정의와 적용 조건(`applies_when`)을 저장한다. 보고서는 저장 당시 기준을 사용하며, 과거 파일에 없는 정의·조건은 미보관 상태로 표시한다. 의미 평가 결과가 전혀 없을 때만 현재 기준을 참고용이라고 명시한다.
- 자동 저장 실패 시 평가 결과는 계속 보여주되 화면·HTML에 저장 실패를 표시한다. 웹 화면에서 해당 실행의 JSON을 직접 다운로드할 수 있다.
- 회귀 검증: `tests/test_review_io_cli_regressions.py`, `tests/test_review_reference_regressions.py`, `tests/test_review_turn_regressions.py`, `tests/test_review_saved_report_regressions.py`.

## 14. 의미 평가 v2.3 원문 이력 전송 (2026-10-07)

- 대화 이력의 질문·답변은 원문 전체를 보내며 길이에 따른 2,000자·300자 축약과 60,000자 제한·이력 생략을 하지 않는다. 현재 질문·답변도 기존처럼 원문 그대로 보낸다.
- 새 의미 결과에는 `history_policy: "full_original_text"`를 기록하고 `context.history_truncated`는 `false`로 유지한다. 과거 결과에 남아 있는 축약 표시와 판정은 수정하지 않는다.
- 제공자가 전체 요청을 거절하면 `API_ERROR` 등 의미 단계의 호출 상태로 기록한다. 자동으로 이력을 줄여 재평가하거나 J6를 적용 대상에서 빼지 않는다. 호출에 실패한 대화는 기존 정책에 따라 `INCOMPLETE`로 집계한다.
- 앞 턴 누락·입력 오류·중복 때문에 이력이 불완전할 때의 J6 제외 정책은 유지한다. CODE 판정 및 공통 통과율 계산도 유지한다.
- 회귀 검증: `tests/test_review_semantic_regressions.py`, `tests/test_full_history_original_text.py`, `tests/test_combined_aiona_dataset.py`.

## 16. v16.2.6 Markdown 구조 인식 보완 (2026-10-12)

공식 기준·비교식·집계는 그대로다. 측정 재료를 만드는 구조 파서가 CommonMark·GFM과 다르게 읽던 부분만 고쳤다.

| 구조 | 이전 동작 | 현재 동작 | 영향 받는 검사 |
|---|---|---|---|
| CRLF 줄바꿈 | 줄 끝 `\r` 이 본문에 남아 표 줄을 인식하지 못하고 글자 수에 포함 | `\r` 은 줄바꿈의 일부로 보고 원문은 보존 | 2-2 표, 2-1 글자 수 |
| 형제 목록 항목의 1~3칸 어긋남 (`- a` 뒤 ` - b`) | 하위 항목으로 세어 최상위 개수에서 빠짐 | 앞 항목의 내용 시작 열보다 덜 들여쓴 같은 종류 항목은 형제 | 2-1 불릿·항목 수, 3-2 선언 개수 |
| 목록 항목 안 4칸 이상 들여쓴 펜스 | 코드로 인식하지 못해 코드블록 요구 FAIL, 코드 줄을 본문 줄·문장·문자열로 셈 | 항목 내용 시작 열 기준 0~3칸이면 펜스 | 1-2 코드블록, 본문을 세는 모든 검사 |
| 들여쓴 펜스의 Python 내용 | 들여쓰기 때문에 '본문 발췌'로 보고 미판정 | 펜스 들여쓰기만큼 앞 공백을 뺀 내용으로 구문 확인 (줄 번호 동일, 원문 위치는 그대로) | 1-2 Python 구문 |
| 양끝 파이프 없는 GFM 표 (`a \| b` / `---\|---`) | 표 없음 FAIL | 표로 인정 (구분선에 파이프가 있을 때만) | 2-2 표 |
| 인용문 안 표 (`> \| a \| b \|`) | 표 없음 FAIL | 같은 깊이의 인용 줄끼리 표로 읽음 | 2-2 표 |

- 바뀌지 않은 것: 목록 밖 4칸 들여쓰기의 백틱 줄은 펜스가 아니다. 빈 줄 뒤 덜 들여쓴 본문이 오면 앞 목록 항목은 닫힌다. 번호 항목 아래 2칸 불릿처럼 종류가 다른 항목은 이전처럼 들여쓰기 그대로 비교한다. 인용문 안 목록, 줄 수의 제목·구분선·출처 줄 포함, 줄바꿈만 있는 문장 경계, 필수 문구의 공백·대소문자 차이는 현재 공식 정의대로 유지한다 (정의 변경은 승인 대상).
- 결과 기록: `versions.analysis` 는 `v16-analysis-1.3`, 해당 검사 규칙 버전(1-2.code_block·1-2.python_syntax·2-1.count·2-2.table·3-2.declared_count)을 올렸다. 저장된 결과는 다시 계산하지 않는다.
- 변경 전후 비교: 기존 테스트가 엔진에 넣는 질문·답변 1,846건은 판정·상태가 하나도 바뀌지 않았다. 위 구조를 담은 합성 사례에서만 의도한 판정이 바뀌었다.
- 회귀 검증: `tests/test_code_eval_engine.py` (`test_commonmark_structures_are_measured_as_rendered`, `test_indented_backticks_outside_list_items_stay_text`, `test_prose_pipe_above_a_rule_is_not_a_table`, `test_crlf_line_endings_measure_like_lf`).

## 17. 필수·금지 문자열의 공백 접기 (2026-10-12, 감사 G-1)

렌더링상 같은 문구가 연속 공백·NBSP·줄바꿈 차이만으로 FAIL 하던 것을 고쳤다. 공식 조건(출현 여부)은 그대로이고 대조 방식만 바뀐다.

- 질문이 `정확히`·`그대로`·`똑같이`·`글자 그대로`·`토씨 하나 안 틀리게`·`한 글자도 안 틀리게` 같은 정확 일치 수식어를 문구 앞뒤에 붙이지 않으면, 답변 투영과 문구의 공백 구간(`str.isspace`: 공백·탭·줄바꿈·NBSP·전각 공백)을 공백 하나로 접어 비교한다. 수식어가 있으면 지금처럼 원문 그대로 비교한다. 결과 행의 `required.exact`·`measured.whitespace`(`exact`/`folded`)·`scope` 에 어느 쪽인지 남는다.
- 대소문자·구두점·코드 구획 안 문구·제로폭 문자(U+200B 등, 공백이 아님)는 접지 않으며 지금처럼 FAIL 이다. 금지 문자열과 시작·끝 표현에도 같은 접기를 적용해 줄바꿈으로 금지어를 피한 경우를 잡는다.
- 근거 위치는 원문 좌표를 유지한다(접힌 공백은 구간 첫 글자 위치). 금지 문자열의 중복 키(`forbidden_key`)는 접기 전 투영으로 계산해 AIONA 금지 표현과의 중복 집계가 바뀌지 않는다.
- `정확히 포함해줘`·`그대로 넣어줘`·`정확히 "…"라고 써줘` 같은 질문은 이전에는 문자열 조건이 추출되지 않았으며, 이제 `exact` 조건으로 추출된다 (`v16-extract-1.8`).
- 결과 기록: `2-1.literal` 규칙 버전 `v16-1.1`. 저장된 결과는 다시 계산하지 않는다.

### 18-1. 이전 턴의 지속 형식·분량 지시 (G-3, v16.3.0)

| 항목 | 규칙 |
|---|---|
| 읽는 범위 | 같은 대화(`conversation_id`)의 1턴부터 바로 앞 턴까지 **사용자 질문**만. 이전 AI 답변은 읽지 않는다. 앞 턴이 하나라도 없거나 중복·입력 오류면 이어받지 않고 `meta.inherited_conditions` 에 이유를 남긴다 |
| 지속 지시 | 같은 문장에 `앞으로·이후로·이제부터·지금부터·다음부터·계속·매번·항상·언제나·대화 내내·모든 답변` 이 있는 지시. 따옴표 안 인용·자료로 제시한 부분의 표현은 지시가 아니다. `이번에만·이번 답변만` 은 이어받지 않는다 |
| 이어받는 조건 | 표·목록·불릿 수·JSON·Markdown 금지·제목·코드블록·문장·줄·문단·어절·글자 수·허용 문자·필수·금지 문구·시작·끝 표현. 항목 수·계산·원본 변환처럼 질문마다 달라지는 요구는 이어받지 않는다 |
| 우선순위 | 뒤 턴의 같은 종류 지속 지시가 앞 지시를 바꾼다. 해제 표현(`…안 해도 돼`, `…말고`, `형식 제한 없이`, `자유롭게`)은 해당 종류를 지운다. 현재 질문에 같은 종류의 요구가 있으면 현재 요구가 우선한다 |
| 작업 한정 | `요약할 때는 3줄로` 처럼 작업이 정해진 지시는 현재 질문에 그 작업 낱말이 있을 때만 적용한다 |
| 결과 표시 | 결과 행 `source=history_instruction`, 제목 `… · N턴 지시 유지`, 근거 `target=history`(현재 질문 위치를 쓰지 않음), `details.inherited_from`, 쉬운 설명 첫머리에 해당 턴 지시를 밝힘 |
| 적용 경로 | `evaluate_batch` (웹·CLI 일괄). 단일 질문 평가와 대화가 아닌 입력은 기존과 같다 |

J6 지시문은 그대로 분량·형식을 CODE 몫으로 둔다. 같은 형식 실패를 J6와 CODE가 함께 판정하지 않는다.

### 18-2. 필수 문구 공백 (G-1, v16.3.1) — 통합 시 §17 방식으로 일원화 (§20-1)

- 필수 문구(`required_literal`)는 원문 출현이 없으면, 문구 안 공백 자리에 연속 공백·줄바꿈·탭·NBSP 등 유니코드 공백이 와도 같은 문구로 본다. 측정값 `whitespace_normalized_occurrences`, 비교식에 `(공백 정규화)`.
- 띄어쓰기를 없애거나(`보호정책`) 구두점이 끼거나 대소문자가 다르면 그대로 FAIL. 제로폭 공백은 공백이 아니므로 허용하지 않는다.
- 같은 문장에 `정확히·그대로·똑같이·공백까지·띄어쓰기까지·한 글자도 바꾸지 말고` 가 있으면 `required.exact=true` 로 글자 그대로 비교한다. `정확히 3개` 처럼 개수에 붙은 `정확히` 는 제외. 이런 표현이 문구와 동사 사이에 있으면 필수 문구가 추출되지 않던 문제도 함께 고쳤다.
- 금지 문구·시작·끝 표현은 바꾸지 않았다.

### 18-3. 추가 오류 수정 (v16.3.1)

## 19. v16.3.2 이전 턴 지시 해제 (F3, 2026-10-12, fix/evaluation-reliability)

3단계 실사용 검증(G3-04)에서 따옴표 문구 끝맺음 지시의 해제를 인식하지 못해 이미 취소된 지시로 FAIL 한 오류를 고쳤다. 공식 기준·비교식은 그대로다. 추출 버전 `v16-extract-1.10`.

| 항목 | 규칙 |
|---|---|
| 문구 지시 해제 | 따옴표로 문구를 가리키고 쓰지 않게 하는 표현 — `'X'로 끝내지 않아도 돼`, `'X'는 빼줘`, `'X'를 붙일 필요 없어`, `'X'로 끝내지 마`, `'X' 없이`, `'X' 조건은 취소해`. 그 문구를 요구한 시작·끝·필수 문구 지시만 지우고 다른 문구 지시는 유지한다. 문구 비교는 앞뒤 공백·끝 문장부호·대소문자를 무시한다 |
| 금지 문구 허용 | `'X'는 이제 써도 돼` 는 그 문구의 금지 지시만 지운다 |
| 대상 낱말 | 끝맺음·끝인사·맺음말·마무리 문구 → 끝 표현, 시작 문구·첫 인사·머리말 → 시작 표현. `표 형식은`, `글자 수 제한은` 처럼 대상 뒤에 형식·제한·조건이 붙어도 그 대상만 해제한다 (이전에는 전체 해제) |
| 해제 표현 추가 | `…할 필요 없어`, `…하지 마`(쓰기·넣기·붙이기·지키기 등), `안 붙여도·안 끝내도`, `취소`, `생략`, `예외`. `무시하지 마·취소하지 마` 처럼 해제 낱말을 다시 부정하면 해제가 아니다. 대상 낱말 뒤에는 조사만 허용해 `표현은 신경 쓰지 않아도 돼` 를 표 해제로 읽지 않는다 |
