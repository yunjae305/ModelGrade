# 질문세트 생성 프롬프트 v3.0 — 한 번에 던지는 독립판 (question-gen-v3.0-standalone, 2026-10-20)

이 파일 전체(아래 `===== 프롬프트 시작 =====` 부터 끝까지)를 AI 채팅에 그대로 붙여 넣으면, AI 가 질문 목록(questions.json)과 첨부파일을 만들어 zip 하나로 준다.
파일을 만들 수 있는 AI(ChatGPT·Claude 의 파일 작성 기능, Codex·Claude Code 같은 코드 실행 환경)에서 쓴다. 파일을 못 만드는 채팅이면 3단계 출력만 받고 zip 은 `tools/build_question_set.py` 로 만든다(아래 '사람이 할 일').

사람이 바꿀 것: `[요청]` 절의 질문 수·구성만. 나머지는 고정.
결과 zip 은 `tools/modelgrade.py collect` 가 그대로 읽는 형식(questions.json + files/)이다 — 수집·평가 흐름은 바뀌지 않는다.

===== 프롬프트 시작 =====

당신은 한국어 AI 답변 품질 평가에 쓸 **질문 세트와 첨부파일**을 만듭니다. 결과는 zip 파일 하나로 냅니다. 설명은 zip 안의 README 에만 씁니다.

# [요청] — 사람이 바꾸는 부분
- 만들 질문 수: **78개** = 단일 질문 57개 · 10턴 대화 11개 · 긴 문서(참조 자료) 질문 10개 (대화 1개 = 질문 1개).
- 질문 수는 **78개로 고정**입니다. 기준 72개 가운데 질문으로 셀 수 있는 64개가 **모두 서로 다른 질문 10개 이상에서 평가**되어야 하며, 78개 안에서 이 목표를 채웁니다 — 질문마다 기준을 6~10개씩 겹쳐 싣고, 적게 나오는 기준(긴 문서 J7-1·J7-2, 대화 J6-1~J6-4, 첨부 J8-1~J8-3, 빈 출력 요구, 계획 실행 가능성 J3-5.a)을 먼저 채웁니다.
- 구성도 고정입니다: 긴 문서 10개(J7 은 긴 문서 질문에서만 생기므로 10개가 그대로 10번), 10턴 대화 11개(J6 네 기준이 대화에서만 생김), 첨부 10개 이상, 빈 출력 요구 8개(2턴 대화 1개 포함).
- 첨부 질문: 단일 질문 중 10개 이상 — txt·docx·pdf·image 종류마다 2개 이상, image 는 사진·화면 캡처형이 절반 이상.
- 빈 출력 요구 질문: 8개 (단일 7개 + 2턴 대화 1개, 아래 규칙).
- 세트 이름: `qs-2026-10-21`.

# 1. 목표
- 아래 [점검 목록]의 CODE 검사 28개와 의미 평가 항목 44개(기준 72개)가 모두, 서로 다른 질문 **10개 이상**에서 적용되게 합니다. 질문을 다 만든 뒤 기준마다 적용 질문 수를 세어 10개 미만인 기준이 하나라도 있으면 질문을 고쳐 채웁니다(개수는 78 그대로). 질문 하나가 여러 기준을 함께 적용받게 설계합니다(대상 지정 + 말투 + 비교 + 표 형식 + 글자 수 + 출처 번호처럼).
- 모든 모델이 PASS 하는 질문은 쓸모가 없습니다. 질문마다 '틀리기 쉬운 지점'을 하나 이상 넣고 trap 에 어떤 답이 FAIL 인지 한 줄로 씁니다. 예: 함께 지키기 어려운 조건 둘, 정확한 개수·글자 수, 주제상 자연스럽게 나오는 금지어, 흔히 잘못 아는 사실, 자료 안의 비슷한 값 둘, 표와 주석의 불일치, 대화 중 바뀐 조건.
- 실제 사용자가 할 법한 문장으로 읽혀야 합니다. 점검 항목 id 나 평가 용어는 질문에 쓰지 않습니다.

# 2. 질문당 기준 수 (k)
- 단일 질문마다 적용되는 변동 기준 수(k)는 **6개 이상 10개 이하**. k 는 그 질문에 실제로 적용되는 CODE 검사 id·의미 점검 항목 id 의 서로 다른 수이며, 항상 적용되는 것과 답변으로만 정해지는 것은 세지 않습니다. 프로그램이 코드 규칙으로 다시 셉니다.
- 세지 않는 기준: 1-1.response_nonempty, 1-1.character_rules, 1-1.foreign_script, 1-2.fence_imbalance, 1-2.orphan_closing_tag, 1-3.footnote_link, 1-3.citation_link, 1-3.internal_link, 3-1.answer_equation, 3-2.declared_count, J1-1.a, J1-2.a, J1-3.a, J1-3.b, J1-4.a, J1-4.b, J3-1.a, J5-3.a.
- 기본 과제만으로 자동으로 붙는 기준도 k 에 들어갑니다(자료 값을 옮기면 J5-2.a, 요약이면 J4-4.a·J5-2.b, 글 작성이면 J2-5.b·J4-3.a, 조건을 주면 J2-3.a). 범위 안에서 k=6·7·8·9·10 질문 수를 고르게 합니다. 범위 밖 단일 질문은 빈 출력 요구 질문뿐입니다.
- 서로 막는 항목은 다른 질문으로 나눕니다. 빈 출력 요구(2-1.explicit_empty)와 모순·빠진 자료(J1-3)는 다른 요구와 섞지 않습니다.

# 3. 작성 규칙
1. 답변이 요구를 지켰는지 판단할 수 있게 구체적으로 씁니다('짧게' 대신 '200자 이내', '표로' 대신 '열이 품목·가격인 표로').
2. CODE 검사는 [점검 목록]의 인식 규칙에 맞는 표현과 자료 형식을 그대로 씁니다(예시 질문의 문장 구조를 따르고 숫자·주제만 바꿈). 규칙에 맞지 않으면 검사가 적용되지 않습니다.
3. 답변 구조 검사(각주·인용 번호 출처·문서 내부 링크·HTML 태그·코드와 수식 펜스·계산식·'다음 N가지' 선언·한자나 일본어 표기)는 답변이 그 구조를 쓰도록 요구해야 적용됩니다.
4. 사실 확인(J5-1)은 수치·날짜·명칭처럼 확인할 수 있는 사실을 묻습니다. 시점에 따라 바뀌는 사실은 기준 시점을 적습니다.
5. 질문에 준 자료(표·JSON·목록·글)를 정렬·필터·집계·요약하게 하는 질문은 자료를 질문 안에 그대로 넣습니다.
6. 실제 개인의 개인정보나 위험한 요청은 넣지 않습니다. 가상의 인물·회사는 질문 밖(topic)에서만 가상이라고 밝히고, 질문·파일 본문에는 '가상'이라는 말을 쓰지 않습니다.
7. 결과물을 파일·이미지·아티팩트·캔버스로 만들게 하지 않습니다. 모든 질문은 채팅 답변 안의 글로 답할 수 있어야 합니다(글 작성 요청에는 "결과는 아티팩트·캔버스 없이 채팅 답변 안에 텍스트로 바로 보여 주세요." 를 붙입니다).
8. 주제(생활·업무·학습·건강·금융·여행·과학·역사·코딩 등)와 유형(설명·사실 확인·분석·코딩·글쓰기·요약·추천·계획·계산)을 고르게 섞고, 같은 주제·같은 문장 틀을 반복하지 않습니다.

# 4. 빈 출력 요구 질문
- "아무것도 출력하지 마" 류의 질문입니다. 질문 지시문에 '(아무것도|아무 것도|아무 말도) + (출력하지|쓰지|답하지|적지|말하지) + (마|말)' 또는 '빈 (문자열|응답|출력|답변)(으로|로|을|를|만) + (출력|응답|반환|답|보내)' 가 들어가야 프로그램이 알아봅니다.
- 다른 요구와 섞지 않습니다. 2턴 대화 1개(1턴에서 규칙을 정하고 2턴에서 빈 출력)를 포함해도 됩니다.

# 5. 10턴 대화 (J6)
- 한 대화 = 턴 10개. 1턴에서 역할·말투·조건(인원·예산·날짜 등)을 정하고, 이어지는 턴에서 ① 앞 턴 지시 유지(J6-1) ② 앞 턴 정보 기억(J6-2: 지시어 '아까 두 번째 안', 값 재사용) ③ 조건 변경·취소(J6-3.a) ④ 같은 결과물 2회 이상 수정(J6-3.b: '방금 쓴 공지문을 수정', '한 번 더 수정') ⑤ 근거 없는 반박(J6-4.b: 새 자료 없이 "그래도 ~가 맞지 않나요?") ⑥ 앞 결정과의 일관성(J6-4.a)이 모두 생기게 합니다.
- 2턴 또는 3턴에 '[붙여 넣은 자료] … [자료 끝]' 으로 2,000~4,000자 자료(회의 메모·운영 현황)를 넣어 J5-2·J3-5 가 걸리게 합니다. 자료에 없는 수치를 만들지 말라는 요구를 넣습니다.
- 턴마다 답변이 길어지게(설계안·안내문·점검표) 요구하되, 한 턴의 요구는 한 가지 결과물로 모읍니다.

# 6. 긴 문서 질문 (J7)
- 참조 자료 문서 1개(한 세트에 하나, 약 270,000 토큰 이상 — 한글 약 50만 자)와 그 문서를 읽어야 답할 수 있는 질문 10개. 문서는 reference.md 로 따로 내고 질문 JSON 에서는 "reference_file": "reference.md" 로 가리킵니다.
- 문서는 가상의 기관 운영 기록(연보·사업 기록·관측 일지)처럼 장·절이 많고, 질문의 답이 되는 사실 문장이 문서 앞·중간·뒤에 흩어져 있어야 합니다(J7-1 위치 무관 찾기). 질문 10개 중 4개 이상은 서로 다른 곳의 사실 둘 이상을 합쳐야 답할 수 있게(J7-2: 합계·비교·연쇄 추적).
- 문서에 비슷한 이름·날짜·수치를 가까이 두어 혼동을 유도합니다(trap). 문서에 없는 정보를 묻고 "없으면 미기재라고" 요구하는 질문을 1~2개 넣습니다.

# 7. 첨부파일 (J8) — 실제 문서처럼
첨부 질문은 "사용자가 실제로 가지고 있는 파일을 올리고 묻는 상황"입니다. 파일은 사람이 실제로 주고받을 법한 문서여야 하고, 질문에 답하려면 그 파일을 열어 읽어야만 하게 만듭니다.

## 7-1. 어떤 파일인가
- 종류마다 '그 형식으로 실제로 돌아다니는 문서'를 고릅니다.
  · docx — 회의록, 운영안·기획안, 업무 인수인계서, 규정·안내문 초안, 보고서 (제목·소제목·본문 문단·표·목록이 섞인 2~3쪽)
  · pdf — 견적서·청구서, 일정표·시간표, 기관 안내문·공지, 신청서 양식, 계약·규정 발췌 (머리말·표·주석·쪽 번호가 있는 1~3쪽)
  · txt — 메모·회의 녹취 정리, 로그·기록 목록, 명단·일정 메모, 이메일 본문 붙여 넣기 (10~40줄)
  · image — 실제 사진이나 화면 캡처: 손글씨 메모·칠판·게시판 사진, 영수증·명세서 사진, 안내 표지판·현수막, 앱·웹 화면 캡처. 차트·표를 그린 그림은 image 의 절반 이하.
- 분량: txt 300~1,500자, docx·pdf 800~3,000자(표·목록 포함, 2쪽 이상이면 쪽을 나눔), image 는 글자 20~200자. 공지 한 장에 다섯 줄 같은 파일은 만들지 않습니다.
- 실제 문서의 군더더기를 넣습니다: 작성자·날짜·문서 번호·버전, 머리말·맺음말, 질문과 직접 관계없는 항목 2~3개, 표의 비고 열, 각주·주석, 쪽 번호. 답에 쓰이는 정보는 그 안에 섞여 있어야 합니다(첫 줄에 바로 보이지 않게).
- 내용은 모두 가상이되 사실처럼 자연스럽게(가상의 기관·인물·금액). 실제 기관명·실존 인물·개인정보는 쓰지 않습니다.

## 7-2. 질문이 파일에 기대게
- 답에 필요한 값·문장은 질문 본문에 다시 적지 않고 파일에만 둡니다. 질문은 '첨부한 ○○에서 △△를 찾아…'처럼 파일을 가리킵니다.
- J8-2.a(형식 읽기)가 적용되게 답이 파일 구조에 기대게 합니다: pdf·docx 는 특정 쪽·표의 행·열·주석, txt 는 줄 순서·구분 기호, image 는 사진 속 글자·화면의 특정 칸.
- 파일 안에 틀리기 쉬운 지점을 둡니다: 비슷한 행 둘, 표와 주석이 다르게 말하는 부분, 합계가 표 밖에 적힘, 두 쪽에 나뉜 표, 취소선·수정 표시, 흐린 글자. trap 에 적습니다.
- 파일에 없는 정보를 묻는 조건('비용이 없으면 미기재라고')을 넣어도 좋습니다 — J8-3·J5-2 가 함께 걸립니다.

## 7-3. 파일을 실제로 만드는 법
- 파일은 **실제 파일**로 만듭니다. docx 는 제목 스타일·표·목록이 있는 진짜 워드 파일, pdf 는 글꼴이 깨지지 않고 표가 선으로 그려진 진짜 PDF(한글 글꼴 포함), txt 는 UTF-8, image 는 PNG 또는 JPG.
- image 사진형은 종이·칠판·영수증·화면 배경 위에 글을 그려 만듭니다(손글씨체·약간의 기울임·그림자·흐림으로 사진처럼). 글자는 반드시 읽을 수 있어야 합니다. 차트형은 막대·선 그래프로 그립니다.
- 파일 이름은 실제 파일처럼: `2026-03_장비_견적서_v2.pdf`, `회의록_0314.docx`, `현장메모.txt`, `영수증_사진.jpg`.
- 파일마다 attachments 항목에 `content` 로 **파일에 실제로 들어간 글 전체**를 적습니다(평가 심판이 받는 원문). pdf·docx 는 쪽마다 `[1쪽]`·`[2쪽]` 표시를 앞에 두고, 표는 `| a | b |` 행으로, image 는 그림 속 글을 줄마다 적습니다. 줄바꿈은 JSON 문자열의 \n 이스케이프로 씁니다 — 글자 그대로의 역슬래시-n 두 글자를 쓰면 안 됩니다.
- 만든 파일을 다시 열어 content 와 글자까지 같은지 확인합니다. 다르면 파일을 다시 만듭니다.

# 8. 출력 — zip 파일 하나
zip 이름은 `[요청]` 의 세트 이름 + `.zip`. 안에는 다음이 들어갑니다.

```
questions.json      질문 전체 (형식은 아래 9절)
files/              첨부파일 실제 파일 — 이름은 questions.json 의 attachments[].path 와 같음

# 10. 끝내기 전 자가 점검 (README 에 결과를 적습니다)
- 질문 수·구성이 [요청] 과 같은가. 대화는 10턴인가. 긴 문서는 약 50만 자인가.
- 기준 72개가 저마다 서로 다른 질문 10개 이상에서 적용되는가 — 기준별 질문 수 표를 README 에 넣습니다. 모자란 기준이 있으면 그 기준을 적용하는 질문을 바꿔 채웁니다.
- 단일 질문의 k 가 모두 6~10 인가(빈 출력 요구 제외).
- 첨부: 파일을 열지 않아도 답할 수 있는 질문은 없는가. content 에 역슬래시-n 두 글자나 '1쪽' 같은 쪽 번호 글이 본문에 없는가. 파일을 다시 열어 content 와 같은가. 분량이 7-1 범위인가.
- questions.json 이 JSON 으로 읽히는가(쉼표·따옴표). files/ 의 파일 이름이 path 와 같은가.

- J1-4.a · J1-4 불필요한 내용 없음 · 질문에 답하는 데 쓰이지 않는 단락이 없는가 (같은 내용의 반복은 J1-4.b에서만 봄) · 적용: 모든 질문 · 근거: 해당 단락 (FAIL 시) · FAIL 예: 원인 설명은 다 했지만 요리 활용법은 잎이 노래지는 이유와 무관함.
- J1-4.b · J1-4 불필요한 내용 없음 · 본문에서 같은 내용이 새 정보 없이 별도 항목·단락으로 두 번 나오지 않았는가 (마무리 요약 한 번은 제외) · 적용: 모든 질문 · 근거: 반복된 두 구간 · FAIL 예: 첫 번째 방법(일하는 자리 정하기)을 새 정보 없이 다른 말로 다시 씀.
- J2-1.a · J2-1 대상 수준 · 지정한 대상·받는 사람이 모를 용어를 설명 없이 쓰지 않았는가 · 적용: 대상·받는 사람 표현 · 근거: 대상, 해당 용어 (FAIL 시) · FAIL 예: 설명 깊이와 말투는 PASS와 같지만 'LTE·5G 셀룰러 망'을 풀어 주지 않고 써서 J2-1.a만 아니오.
- J2-1.b · J2-1 대상 수준 · 지정 대상이 이미 아는 수준의 설명만 있거나(너무 얕음), 대상이 모를 전제 지식을 요구하지(너무 깊음) 않는가 (용어 문제는 J2-1.a) · 적용: 위와 같음 · 근거: 대상 표현 인용, 가장 얕거나 깊은 문장 1개 · FAIL 예: 모르는 용어는 없지만(J2-1.a 예) 입문자용 깊이라 10년 차 시니어 청중에게 맞지 않아 J2-1.b만 아니오.
- J2-2.a · J2-2 말투·어조 · 지정한 말투·존대를 처음부터 끝까지 지켰는가. 추상적 어조 지시(따뜻하게 등)는 명백히 반대되는 문장이 없는가 · 적용: 현재 질문의 말투·어조 지정 · 근거: 지정 문장, 어긋난 문장 · 펼침: 지시별(질문에 이 요소를 2개 이상 넣음) · FAIL 예: 앞부분은 반말이지만 마지막 두 문장이 존댓말로 바뀌어 끝까지 지키지 못해 J2-2.a만 아니오.
- J2-3.a · J2-3 조건·제약 준수 · 질문이 직접 말한 조건·제약("~는 빼고", "~이내", "~만", "~안 돼")을 어긴 문장이 없는가 (조건 아래서 계획이 성립하지 않는 것은 J3-5.a) · 적용: 질문의 조건 문장 (개수·형식은 코드 평가, 모순 조건 쌍은 J1-3, 인원·시간·장소 같은 자원 조건은 J3-5) · 근거: 조건 문장, 위반 문장 · 펼침: 조건별(질문에 이 요소를 2개 이상 넣음) · FAIL 예: 감사 내용은 갖췄고 퇴사 이유도 없지만, 쓰지 말라고 한 이직 회사 이름을 써서 '회사 이름' 조건에서 J2-3.a만 아니오.
- J2-4.a · J2-4 설명 방식 · 지정한 방식(비유·예시·관점·상황)으로 설명했는가 · 적용: 설명 방식 지정 · 근거: 지정 문장, 해당 설명 · FAIL 예: 설명 내용은 맞지만 비유 없이 직접 설명만 해 지정한 방식을 따르지 않아 J2-4.a만 아니오 (비유가 없으므로 J2-4.b는 해당 없음이어야 함).
- J2-4.b · J2-4 설명 방식 · 비유·예시가 설명 대상의 핵심 특징과 맞물리는가 (개념을 틀리게 전달하면 J5-1) · 적용: 설명 방식이 지정되고 답변에 비유·예시가 실제로 있을 때 (J2-4.a가 아니오면 해당 없음) · 근거: 비유·예시 문장 · 적용 여부는 평가 모델이 정함(그 상황이 분명히 생기게 설계) · FAIL 예: 비유는 들었고(J2-4.a 예) 직접 설명도 맞지만(J5-1 통과), '짧은 기간 대 긴 기간 평균'이라는 날씨·기후의 차이가 외상·선투자의 시점 차이라는 이익·현금흐름의 차이와 대응하지 않아 J2-4.b만 아니오.
- J2-5.a · J2-5 추천·글의 목적 적합성 · 추천이 현재 질문에 서술된 배경·상황(J2-3 목록에 없는 것)에 맞는가 (이전 턴에만 있는 상황은 J6-2.b) · 적용: 추천·제안 요청 · 근거: 상황 문장, 추천 문장 · FAIL 예: 질문에 금지·예산 같은 명시 조건은 없어 J2-3에는 걸리지 않지만, 원룸에 요리를 안 하는 부부라는 서술된 상황과 맞지 않는 부피 큰 주방용품을 추천해 J2-5.a만 아니오.
- J2-5.b · J2-5 추천·글의 목적 적합성 · 글이 질문이 정한 목적(사과·거절·홍보·안내 등)을 실제로 수행하는가 (예: 사과문이 변명 위주가 아닌가) · 적용: 글 작성 요청 · 근거: 목적 표현 인용, 목적에 어긋난 문장 · FAIL 예: 사과 대신 주문량·택배사 사정을 늘어놓아 변명 위주라 사과문이라는 목적을 수행하지 못함.
- J3-1.a · J3-1 내부 모순 없음 · 같은 대상·조건에 대해 서로 다른 값·결론·평가가 없는가 · 적용: 모든 답변 · 근거: 모순되는 두 위치 (FAIL 시) · FAIL 예: 같은 라텍스의 통기성을 두고 "열이 잘 빠진다"와 "열이 잘 빠지지 않는다"를 함께 말하고, 추천도 라텍스→메모리폼으로 갈림. 근거는 각각 있어 J3-2는 통과.
- J3-2.a · J3-2 근거와 결론 · 주 결론(질문이 요구한 선택·추천·판단)에 결론을 바꿔 말한 것이 아닌 근거 문장이 하나 이상 있는가 · 적용: 추천·선택·판단이 있는 답변 ("왜·원리" 설명은 J3-3). 답변당 1개 · 근거: 결론 문장, 근거 문장 · FAIL 예: 추천 결과물은 있으나(J1-1 통과) 왜 그 제품인지 설명하는 근거 문장이 없음. "가장 알맞다"는 결론을 다시 말한 것이지 근거가 아님. 질문이 이유를 요구하지 않아 J4-2도 해당 없음.
- J3-2.b · J3-2 근거와 결론 · 제시한 근거로 결론이 성립하는가 · 적용: 위와 같음 · 근거: 위와 같음 · FAIL 예: 근거(가입 사은품)는 있어 J3-2.a는 통과하지만, 그 근거로는 "화상회의가 안정적"이라는 결론이 나오지 않음.
- J3-3.a · J3-3 인과·원리 · 원인과 결과를 잇는 방향이 질문이 준 선후·조건과 맞는가 (각 사실의 진위는 J5-1) · 적용: 질문에 선후·조건이 적힌 이유·원리 요청. 없으면 해당 없음 · 근거: 질문의 선후·조건, 답변의 인과 문장 · 적용 여부는 평가 모델이 정함(그 상황이 분명히 생기게 설계) · FAIL 예: 건조한 공기→잎 마름이라는 원리 자체는 현상을 설명하므로 J3-3.b는 통과하지만, 난방과 건조 사이의 원인·결과를 뒤집어 난방을 결과로 놓음. 질문이 말한 선후(난방 뒤 잎 마름)와도 맞지 않음.
- J3-3.b · J3-3 인과·원리 · 설명한 원리가 대상 현상을 실제로 설명하는가 (비유·예시 문장은 빼고 직접 설명만. 비유는 J2-4.b) · 적용: 이유·원리 요청 · 근거: 원리 설명 부분 · FAIL 예: 저온에서 미생물 번식이 느리다는 설명은 방향도 맞고 사실이지만, 그것이 왜 빵을 더 빨리 굳게 하는지는 전혀 설명하지 못함(원리와 현상이 연결되지 않음).
- J3-4.a · J3-4 풀이 연결 · 풀이 단계가 끊김 없이 이어지는가 (계산값은 코드 3-1, 입력 값은 J5-2) · 적용: 풀이 요청 · 근거: 끊긴 단계 (FAIL 시) · FAIL 예: 거리를 구하는 단계가 없어 "빨라지면 줄어든다"에서 1시간으로 건너뜀. 최종 값은 맞고 입력 값도 그대로라 코드 3-1·J5-2는 통과.
- J3-5.a · J3-5 실행 가능성 · 답변 안에 적힌 시간·인원·순서끼리 맞는가 (같은 사람 동시 배정, 결과가 전제보다 먼저, 적힌 소요 시간 합이 구간을 넘음 등. 외부 지식이 필요한 불가는 J5-1) · 적용: 계획·일정·절차 요청 · 근거: 맞지 않는 두 지점 · FAIL 예: 혼자인데 1시에 부스 판매와 주차장 왕복을 동시에 배정해 한 사람이 실행할 수 없음. 질문의 명시 조건(혼자·1~5시·15분 거리)은 바꾸지 않아 J2-3·J5-2는 통과.
- J3-5.b · J3-5 실행 가능성 · 값은 같은데 상한·예상·실제 같은 역할을 바꿔 쓰지 않았는가 (값 자체가 다르면 J5-2.a) · 적용: 예산·수치에 역할이 있는 질문 · 근거: 값과 역할 표현 · FAIL 예: 15만원(예상)과 28만원(실제)의 역할을 서로 바꿔 씀. 값 자체와 계산(40-15=25, 28-25=3)과 최종 차액은 그대로라 코드 3-1·J5-2·J3-1은 통과.
- J4-1.a · J4-1 비교 완결 · 비교 대상을 모두 다뤘는가 · 적용: 비교 요청 (비교 문장이 어떤 형태로든 있을 때. 비교 자체가 없으면 J1-1) · 근거: 예: 대상마다 답변 인용 / 아니오: 질문 인용 + 가장 가까운 답변 구절 · 펼침: 대상별(질문에 이 요소를 2개 이상 넣음) · FAIL 예: 일반 자전거를 한 번도 다루지 않고 두 대상만 비교해 결론을 냄. 결론 자체는 있으므로 J1-1 아님, 질문에 비교 기준 지정이 없어 J4-1.b는 해당 없음.
- J4-1.b · J4-1 비교 완결 · 질문이 정한 비교 기준(장단점 포함)을 모두 다뤘는가 · 적용: 비교 기준이 명시된 경우 · 근거: 예: 기준마다 답변 인용 / 아니오: 질문 인용 + 가장 가까운 답변 구절 · 펼침: 기준별(질문에 이 요소를 2개 이상 넣음) · FAIL 예: 두 대상은 모두 다뤘고(J4-1.a 예) 근거 있는 결론도 있으나(J1-1·J3-2 예), 질문이 정한 기준 '이사 당일 내가 해야 할 일'이 어디에도 없어 비용 기준만으로 결론을 냄.
- J4-2.a · J4-2 함께 요구한 항목 · 주 요청 외에 종류가 다른 요구(추가 요청·이유·예시·각각)가 모두 있는가 (비교의 기준·장단점은 J4-1.b, "N개" 같은 개수 요구는 코드 2-1) · 적용: 요청·요구가 2개 이상 · 근거: 예: 요구마다 답변 인용 / 아니오: 질문 인용 · 펼침: 요구별(질문에 이 요소를 2개 이상 넣음) · FAIL 예: 좋은 점·주의할 점은 있으나 '보상 예시'는 없고 보상이 필요하다는 언급만 있음. 주 요청의 결과물은 있으므로 J1-1 아님, 비교 질문이 아니라 J4-1 해당 없음.
- J4-3.a · J4-3 핵심 단계·구성 요소 · 목적에 필요한 핵심 단계·필수 구성 요소를 먼저 나열하고 그중 빠진 것이 없는가 (풀이 단계는 J3-4, 빠져서 실행 불가면 J3-5.a) · 적용: 방법·절차(how-to) 요청과 글 작성 요청. 풀이 요청은 제외 · 근거: 예: 단계·요소마다 답변 인용 / 아니오: 질문 인용 · 펼침: 단계·요소별(질문에 이 요소를 2개 이상 넣음) · FAIL 예: 장소·행동 요령·문의처는 있으나 안내문의 필수 요소인 일시(10월 24일 오후 2시)가 통째로 빠짐. 글은 완성되어 있어 J1-1 아님, 질문 값을 바꾼 것이 아니라 뺀 것이므로 J5-2 아님.
- J4-4.a · J4-4 요약 핵심 · 원문의 핵심 정보(독자가 판단·행동하는 데 필요한 날짜·기간·장소·대상·조건·할 일)를 먼저 나열하고 그중 빠진 것이 없는가. 해당 주제의 문장이 있으면 내용이 틀려도 있음(틀린 내용은 J5-2.b). "자세한 건 원문 참고"는 없음 · 적용: 요약 요청 · 근거: 예: 원문 인용, 요약 인용 / 아니오: 원문 인용 · 펼침: 핵심 정보별(질문에 이 요소를 2개 이상 넣음) · FAIL 예: 시작일·기간·폐쇄·대체 주차 지원은 있으나 지원을 받기 위해 독자가 해야 할 '영수증을 매월 말 총무팀에 제출'이 빠짐. 없는 내용을 더하거나 뜻을 바꾸지는 않았으므로 J5-2.b 아님.
- J5-1.a · J5-1 사실 정확성 · 답변의 외부 사실 주장(수치·날짜·명칭·통계·개념 정의)이 사실과 맞는가. 시점이 있는 사실은 답변 수집 날짜 기준 · 적용: 코드 규칙이 사실 정보를 묻는 질문으로 판정한 질문 (J3-1 모순 쌍, J3-3 인과 연결 문장, 이전 턴 AI 답변에서 비롯한 값은 제외) · 근거: 주장 인용과 검색 기록. 거짓이면 올바른 사실과 반박 출처 원문 · 펼침: 주장별(질문에 이 요소를 2개 이상 넣음) · FAIL 예: 아데노신 설명과 인과 구조는 맞지만 반감기 수치가 거짓(실제 평균 약 5시간). 사실 오류 하나로 해당 주장만 거짓, J3-3은 걸리지 않음.
- J5-2.a · J5-2 입력 자료 충실성 · 질문에서 준 개별 값·이름·날짜를 썼다면 다른 값으로 적지 않았는가 (쓰지 않은 값은 해당 없음. 상황 문장·선후 관계는 값이 아님) · 적용: 현재 질문의 값을 쓰는 답변 · 근거: 질문 원문, 답변 인용 · 펼침: 값별(질문에 이 요소를 2개 이상 넣음) · FAIL 예: 질문이 준 장소 '제2물류센터'를 '제1물류센터'로 바꿔 썼음. 메일 구성 요소와 요청 사항은 다 있어 J1·J4는 통과하고 이 값 하나만 아니오.
- J5-2.b · J5-2 입력 자료 충실성 · 질문이 준 자료를 정리·요약할 때 원문에 없는 문장을 더하거나 문장 단위 의미를 바꾸지(취소→연기 등) 않았는가 (개별 값 오기는 J5-2.a) · 적용: 자료 정리·요약 요청 · 근거: 자료 원문, 답변 인용 · FAIL 예: 원문은 '취소되고 평소처럼 보육'인데 '다음 주로 연기'로 의미를 바꿈. 핵심 정보는 다 들어 있어 J4-4(누락)는 통과하고 이 항목만 아니오.
- J5-3.a · J5-3 확인 과정 꾸밈 없음 · 하지 않은 조회·확인·실행을 한 것처럼 쓰거나, 존재하지 않는 출처·문헌·조문·제품을 들지 않았는가 (그 문장 안의 사실 값은 J5-1에서 따로 봄) · 적용: 확인·조회·출처를 언급한 답변. 조회·실행 부분은 도구 사용 여부를 알 수 없는 답변(AIONA)에서 해당 없음 · 근거: 해당 문장. 출처는 서버 존재 확인 · FAIL 예: 접근할 수 없는 사용자 결제 내역을 조회한 것처럼 쓰고 취소 요청을 실행한 것처럼 꾸밈. 외부 사실 주장은 없어 J5-1은 적용되지 않고 이 항목만 아니오.
- J8-1.a · J8-1 첨부 내용 반영 · 첨부파일의 내용을 근거로 답했는가. 첨부를 무시하고 일반론으로 답하거나 첨부에 없는 내용을 첨부에 있다고 하지 않았는가 (맞는 부분을 보고도 값을 다르게 옮긴 것은 J5-2.a) · 적용: 질문에 첨부파일이 있음. 답변이 첨부를 열 수 없다고 밝혔으면 해당 없음 · 근거: 첨부 내용의 해당 부분 인용, 답변 인용 · 적용 여부는 평가 모델이 정함(그 상황이 분명히 생기게 설계) · FAIL 예: 첨부 내용을 읽지 않고 회의록 일반론으로 답함. 다른 값을 옮긴 것이 아니라 J5-2.a는 해당 없음.
- J8-2.a · J8-2 파일 형식 읽기 · 파일 형식에 맞게 구조를 읽었는가 — 이미지 속 글자·도표, PDF 페이지·표, DOCX 제목·표·목록, TXT 줄 구성에서 행·열을 섞거나 다른 페이지·항목의 내용을 붙이지 않았는가 · 적용: 답이 첨부의 표·도표·그림 속 글자·페이지·목록 구조에 기대는 질문 (평가 모델 판정). 첨부를 열 수 없다고 밝혔으면 해당 없음 · 근거: 첨부의 해당 위치(페이지·표의 행·열·줄) 인용, 답변 인용 · 적용 여부는 평가 모델이 정함(그 상황이 분명히 생기게 설계) · FAIL 예: 노트북 행의 금액 열 값을 합계와 단가로 읽어 행·열을 섞음. 표에 있는 값을 다른 칸에서 가져온 것이라 J5-2.a가 아니라 여기서 봄.
- J8-3.a · J8-3 첨부 접근 처리 · 첨부를 열 수 없거나 일부만 읽었을 때 그 사실을 밝혔는가. 읽지 못한 부분을 읽은 것처럼 쓰지 않았는가 (모두 읽고 답했으면 예) · 적용: 질문에 첨부파일이 있음 · 근거: 읽지 못했다고 밝힌 문장 또는 읽은 척한 답변 문장 인용 · FAIL 예: 그래프에서 가장 높은 달은 2월(410만 원)인데, 이미지를 읽지 않은 채 읽은 것처럼 답하고 그래프에 없는 내용까지 덧붙임.
```

===== 프롬프트 끝 =====

## 사람이 할 일 (zip 을 받은 뒤)

1. zip 을 `참고자료/질문세트_<세트이름>/` 에 풀고 `python -X utf8 tools/check_question_set.py <폴더>` 로 확인한다 — JSON 읽힘, files/ 와 path 일치, 첨부 content 가 실제 파일 글과 같은지, 기준별 적용 질문 수(코드 규칙으로 다시 셈), 단일 질문 k 6~10.
2. 모자란 기준·범위 밖 k 가 있으면 그 질문만 AI 에 돌려보내 고친다(이 프롬프트의 2·3절을 함께 붙임).
3. 확인이 끝나면 `python -X utf8 tools/modelgrade.py collect app --provider gpt,claude,gemini,aiona --set <폴더>` 로 네 모델 답을 받고, 판정은 `tools/judge_v4.py`.

파일을 못 만드는 채팅에서 썼으면 questions.json 만 받아 `python -X utf8 tools/build_question_set.py <questions.json>` 으로 files/ 를 만든다(docx·pdf·txt·차트 image 만 — 사진형 image 는 코드 보완 뒤).
