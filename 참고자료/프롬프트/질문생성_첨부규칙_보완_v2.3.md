# 질문생성 프롬프트 — 첨부파일(J8) 규칙 보완안 v2.3 (2026-10-20)

질문생성 프롬프트 v2.2 의 `# 첨부파일 (J8)` 절(4줄)을 아래로 **통째로 바꾼다**. 나머지 절은 그대로.
배경: 10-20 미팅 — 지금 첨부 10개는 공지 다섯 줄·표 한 개 수준이라 사람이 실제로 보내는 파일과 거리가 멀고, 생성 때 줄바꿈을 `\n` 두 글자로 써서 pdf 한 문단에 표가 글자로 적힌 파일(Q107·Q115)과 줄바꿈 없는 txt(Q113)가 나왔다.

---

```text
# 첨부파일 (J8)

첨부 질문은 "사용자가 실제로 가지고 있는 파일을 올리고 묻는 상황"이어야 합니다. 파일은 사람이 실제로 주고받을 법한 문서여야 하며, 질문에 답하려면 그 파일을 열어 읽어야만 하게 만듭니다.

## 1. 어떤 파일인가 — 실제 문서처럼
- 파일 종류는 txt·docx·pdf·image 네 가지. 종류마다 1개 이상, 첨부 질문은 모두 합쳐 4개 이상.
- 종류마다 '그 형식으로 실제로 돌아다니는 문서'를 고릅니다. 예:
  · docx — 회의록, 운영안·기획안, 업무 인수인계서, 규정·안내문 초안, 보고서 (제목·소제목·본문 문단·표·목록이 섞인 2~3쪽)
  · pdf — 견적서·청구서, 일정표·시간표, 안내문·공지(기관 발송), 신청서 양식, 계약·규정 발췌 (머리말·표·주석·쪽 번호가 있는 1~3쪽)
  · txt — 메모·회의 녹취 정리, 로그·기록 목록, 간단한 명단·일정 메모, 이메일 본문 붙여 넣기 (10~40줄)
  · image — 실제 사진이나 화면 캡처: 손글씨 메모·칠판·게시판 사진, 영수증·명세서 사진, 안내 표지판·현수막, 화면 캡처(앱·웹 화면). 차트·표를 그린 그림은 image 질문 절반 이하로.
- 분량: txt 300~1,500자, docx·pdf 800~3,000자(표·목록 포함, 쪽 2개 이상이면 '[다음 쪽]'으로 나눔), image 는 글자 20~200자. 공지 한 장에 다섯 줄 같은 파일은 만들지 않습니다.
- 실제 문서의 군더더기를 넣습니다: 작성자·날짜·문서 번호·버전, 머리말·맺음말, 질문과 직접 관계없는 항목 2~3개, 표의 비고 열, 각주·주석, 쪽 번호. 답에 쓰이는 정보는 그 안에 섞여 있어야 합니다(첫 줄에 바로 보이지 않게).
- 내용은 모두 가상이되 사실처럼 자연스럽게(가상의 기관·인물·금액). 실제 기관명·실존 인물·개인정보는 쓰지 않습니다. 파일 안에 '가상'이라는 말은 넣지 않습니다(질문 밖 meta 에만 적음).

## 2. 질문이 파일에 기대게 — J8 세 항목이 모두 생기게
- 답에 필요한 값·문장은 질문 본문에 다시 적지 않고 파일에만 둡니다(파일을 안 열면 답할 수 없게). 질문은 '첨부한 ○○에서 △△를 찾아…'처럼 파일을 가리킵니다.
- J8-2.a(형식 읽기)가 적용되게, 답이 파일의 구조에 기대게 합니다:
  · pdf·docx: 특정 쪽·특정 표의 행·열·주석을 읽어야 하는 요구('2쪽 표의 합계', '주석과 표가 다른 부분')
  · txt: 줄 순서·구분 기호(날짜·콜론·탭)로 나뉜 항목을 읽어야 하는 요구
  · image: 사진 속 손글씨·표지판·영수증 글자, 화면 캡처의 특정 칸을 읽어야 하는 요구
- 파일 안에 '틀리기 쉬운 지점'을 하나 이상 둡니다: 비슷한 행 두 개(품목명·날짜가 비슷), 표와 주석이 다르게 말하는 부분, 합계가 표 밖에 적힘, 두 쪽에 나뉜 표, 취소선·수정 표시된 값, 사진의 흐린 글자. trap 에 그 지점을 씁니다.
- 파일에 없는 정보를 묻는 조건을 하나 넣어도 좋습니다('비용이 적혀 있지 않으면 미기재라고') — J8-3·J5-2 가 함께 걸립니다.

## 3. 명세 쓰는 법 — 프로그램이 파일을 만듭니다
- attachments 에 {name, type, content, (image 일 때) scene 또는 chart} 를 씁니다. name 은 실제 파일 이름처럼('2026-03_장비_견적서_v2.pdf', '회의록_0314.docx', '현장메모.txt', '영수증_사진.jpg').
- content 는 파일에 들어갈 글 전체입니다. **줄은 반드시 실제 줄바꿈(JSON 문자열 안의 \n 이스케이프)으로 나눕니다. 글자 그대로의 역슬래시-n('\\n') 두 글자를 쓰면 안 됩니다** — 그러면 한 줄로 붙은 파일이 만들어집니다.
- 줄 표기(프로그램이 이 표기로 제목·표·쪽을 그립니다):
  · '# 제목', '## 소제목', '### 작은 제목'
  · '- 항목' (목록)
  · 표: '| 열1 | 열2 | 열3 |' 행을 이어 씁니다(머리 행 다음에 '|---|---|---|' 구분선). 표는 셀마다 '|' 로 나누고, 표 안에서 줄을 바꾸지 않습니다.
  · '[다음 쪽]' 한 줄 = 쪽 나눔(pdf·docx). 쪽 번호는 프로그램이 붙이므로 '1쪽'·'2쪽' 같은 글을 본문에 쓰지 않습니다.
  · 그 밖의 줄은 본문 문단.
- image:
  · 사진·캡처: "scene": {"kind": "handwritten_memo | receipt | signboard | whiteboard | screenshot", "lines": ["그림에 넣을 글 줄", ...], "note": "배경·상태 설명(흐림, 기울어짐, 형광펜 등)"} — 프로그램이 종이·칠판·영수증·앱 화면 배경 위에 글을 그립니다. lines 의 글이 평가 모델이 받는 원문입니다.
  · 막대그래프: "chart": {"title", "labels": [...], "values": [숫자...], "unit"}.
  · 표·글 그림: content 에 줄 표기로.
- content 전체 4,000자 이하. 첨부 하나당 파일 1개. 한 질문에 첨부 2개까지.

## 4. 자가 점검 (출력 전에 확인)
- 파일을 열지 않아도 답할 수 있는 질문인가 → 다시 씁니다.
- content 에 '\\n' 두 글자가 있나, '1쪽' 같은 쪽 번호 글이 있나, 표 행이 '|' 로 시작·끝나지 않는 줄이 있나 → 고칩니다.
- 분량이 위 범위에 드는가, 질문과 무관한 항목이 2개 이상 섞여 있는가, 틀리기 쉬운 지점이 trap 에 적혀 있는가.
```

## 이번 78개에 적용하는 방법 (API 호출 없이)
78개의 첨부 질문 10개(Q30·48·107·113·115·270·278·289·298·323)는 질문 본문은 두고 **파일 내용(content)만** 위 규칙으로 다시 써서 프로그램으로 파일을 다시 만든다. 답에 쓰이는 값(날짜·금액·담당자·시각)은 그대로 두어 질문·trap 이 바뀌지 않게 하고, 문서 머리말·무관한 항목·비고·쪽 나눔을 더한다. 다시 만든 뒤 열어서 대조하고, 네 모델에 이 10개만 다시 수집한다.
