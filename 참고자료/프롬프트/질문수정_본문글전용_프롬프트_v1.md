# 질문 수정 프롬프트 — 결과물을 "답변 본문 글"로만 받기 (v1, 2026-10-20)

왜: 네 AI(ChatGPT 앱·Claude 앱·Gemini·AIONA)에 같은 질문을 던지고 **답변 맨 아래 복사 아이콘**으로 답을 받는다. 파일·문서·이미지·아티팩트·캔버스로
만들어진 답은 복사 아이콘이 그 내용을 주지 않아 수집이 안 된다(간단평가 1차: Claude Q12·Q25 가 Claude Docs 문서로 답해 보류). 그래서 326개 질문 중
결과물을 문서·파일·이미지로 만들게 하는 질문을 고쳐 **모든 답을 본문 글로** 받고, 그 뒤 78개를 다시 뽑는다.

후보 목록: `참고자료/질문세트_326_생성프롬프트v2/문서생성_후보_v1.csv` (낱말 기준 61개 질문·118턴, 사람이 보고 넣고 뺀다).
검증: 수정 뒤 질문마다 조건 수 k(6~10)와 노리는 기준(target_items)이 전과 같은지 코드로 다시 센다(`tools/repair_k_range.py`, 질문별 해석 프롬프트) — 같지 않으면 되돌린다.

## 프롬프트 원문 (아래를 그대로 주고, [입력]에 질문을 넣는다)

당신은 AI 답변 품질 평가용 질문을 손질하는 편집자입니다. 질문의 **평가 조건은 하나도 바꾸지 않고**, 결과물의 **형태**만 "답변 본문에 글로 바로 쓰기"로 바꿉니다.

배경: 이 질문들은 여러 AI 채팅 앱에 똑같이 던지고, 답은 답변 맨 아래의 복사 아이콘으로 받습니다. 파일·문서·이미지·슬라이드·캔버스·별도 문서(아티팩트)로 만들어진 답은 복사 아이콘으로 받을 수 없습니다. 그래서 그런 결과물을 요구하거나 유발하는 표현을 고쳐야 합니다.

규칙
1. 바꾸는 것은 결과물의 **형태**뿐입니다.
   - "문서/안내문/매뉴얼/계획서/보고서/초안/메일/대본/양식 등을 작성·만들어·생성해 달라" → 같은 내용을 **답변 본문에 글로 바로 써 달라**는 표현으로. 긴 결과물(공지문 전문, 매뉴얼, 계획서)도 본문에 그대로 쓰게 합니다. "파일로/별도 문서로/슬라이드로/캔버스에" 같은 말은 지웁니다.
   - 이미지·그림·도식·다이어그램·포스터를 **만들라**는 요청 → 그 내용을 **글로 설명**하게 바꿉니다(예: "흐름도를 그려줘" → "흐름을 단계별로 글로 설명해줘"). 단, 그 질문이 노리는 조건(개수·형식 등)은 그대로 둡니다.
2. 바꾸지 말 것(글자 하나도): 개수·글자 수·문장 수·불릿 수, 형식 지정(표·코드블록·JSON·목록·소제목), 금지어·금지 형식, 말투(존댓말·반말)·대상(초등학생 등), 순서, 날짜·숫자·이름·금액, 참조 자료·첨부 파일을 읽으라는 지시, 대화에서 앞 턴을 이어받는 지시, 주제, 난이도, 함정. 조건을 담은 문장은 그대로 복사해 둡니다.
3. 덧붙이는 문장은 아래 고정 문구 **하나만**, 질문(또는 그 턴) 맨 끝에 한 번:
   「결과는 파일·이미지·아티팩트·캔버스 없이 채팅 답변 안에 텍스트로 바로 보여 주세요.」 (질문이 반말이면 '…보여 줘.')
   이 문장 말고는 새 요구를 넣지 않습니다. 특히 "정확히·N개·문장·글자·코드블록·표·목록·JSON·불릿·존댓말·반말·금지" 같은 낱말을 새로 넣지 않습니다(조건 추출기가 조건으로 셉니다).
4. 대화(여러 턴)는 **결과물을 만드는 턴에만** 3번 문구를 붙이고, 나머지 턴과 맥락 지시는 그대로 둡니다.
5. 결과물을 만들지 않는 질문(사실 확인·계산·비교·요약 등)은 손대지 않고 "변경 없음"으로 돌려줍니다.
6. 질문의 길이·어조는 되도록 유지합니다. 문장을 다시 쓰더라도 뜻이 같아야 합니다.

출력 형식(JSON 배열만, 다른 말 없이):
[
  {"id": 질문 번호, "turn": 턴 번호, "changed": true|false,
   "question": "수정 후 질문 전문(변경 없음이면 원문 그대로)",
   "note": "무엇을 어떻게 바꿨는지 한 줄(변경 없음이면 '변경 없음')"}
]

[입력]
(질문 번호·턴·종류·노리는 기준 목록·질문 원문을 넣는다. 대화는 턴 순서대로 모두 넣는다.)

## 예시 (Q25 9턴 — 실제로 Claude 가 문서로 답한 턴)

- 원문(끝부분): "… 현장 매뉴얼을 작성해 주세요. 운영자가 당일에 바로 쓸 수 있게 …"
- 수정: "… 현장 매뉴얼을 작성해 주세요. 운영자가 당일에 바로 쓸 수 있게 … **결과는 파일·이미지·아티팩트·캔버스 없이 채팅 답변 안에 텍스트로 바로 보여 주세요.**"
- 조건(섹션 수·말투·날짜·장소 등)은 그대로.

## 적용 순서

1. 후보 CSV 를 보고 수정할 질문을 정한다(필요하면 후보에 없는 것도 추가).
2. 질문마다(대화는 통째로) 위 프롬프트로 수정안을 받는다 → `questions.json` 에 반영(원본은 git 이력에 남음).
3. 코드로 검증: 조건 수 k·target_items 전과 같은지, 고정 문구가 한 번만 들어갔는지.
4. 최소 78 다시 뽑기(`tools/min_eval_list.py … --min 10 --save-set`) → `질문세트_최소78/ids.json` 갱신.
5. 수집은 새 실행으로 다시(질문이 바뀌면 전 답은 비교 대상이 아니다).

참고 — 더 간단한 대안: 질문을 고치지 않고 수집기가 보낼 때 고정 문구를 질문 끝에 붙이는 방법도 있다(모든 모델에 똑같이, 판정 입력에도 같은 글을 보임). 질문 원문을 고정하려는 결정과 맞지 않아 이번에는 질문 자체를 고친다.


## 실제 적용 (2026-10-20, v2.1-본문글)

- 처음 문구 「…만들지 말고 답변 본문에 글로 바로 써 주세요」는 기준 적용 규칙에 걸렸다: '말고'(제약 → J2-3.a), '답변/글 … 써'(글 작성 → J2-5.b·J4-3.a), '문서'(자료 낱말 → '정리해'와 함께 J5-2.b). 그래서 이 낱말을 모두 피한 문구로 바꿨다:
  **「결과는 파일·이미지·아티팩트·캔버스 없이 채팅 답변 안에 텍스트로 바로 보여 주세요.」** (반말 질문은 '…보여 줘.')
- 대상: 문서를 만들게 하는 질문 53개 — 대화 22개(10턴 계획 대화 Q11~Q26 전부, 2턴 Q56·Q209·Q226·Q275·Q287·Q318)는 모든 턴, 단일 31개(안내문·공지·사과문·안내 글·메시지)는 그 턴. 코드·JSON·표·계산·요약 질문과 빈 출력 요구 질문은 손대지 않음. 문장은 고치지 않고 끝에 고정 문구만 붙임(204턴).
- 검증: 수정 전후 `qg.check()` 의 턴별 적용 기준(CODE·의미) 487턴 모두 같음, k_var·커버리지 같음, 판정상황표 v2 의 판정 항목 487턴 같음(Q275_T1 근거 인용 끝에 '…' 만 붙음). 최소 78 다시 뽑기 → 목록·순서 이전과 같음(기준마다 10번 이상, 못 채운 기준 0).
