게시판 '수업 안내' 칸 글쓰기 규정(발췌)
- 글이 길면 맨 위에 목차를 둔다. 목차의 항목은 글 안의 실제 소제목으로 바로 가는 내부 링크로 만든다.
- 내부 링크의 이름과 실제 소제목의 글자는 같아야 한다. 게시판은 소제목 글자를 그대로 주소로 바꾸기 때문에, 소제목이 '접수 안내'인데 링크가 '접수'를 가리키면 눌러도 움직이지 않는다.
- 덧붙일 설명이 본문 흐름을 끊으면 각주로 뺀다. 각주 표시와 각주 정의는 이름이 같아야 하고, 정의는 글 맨 아래에 모은다.
- 다른 기록을 근거로 쓴 문장에는 대괄호 숫자로 출처 번호를 붙이고, 글 아래에 번호별 출처 목록을 둔다.
- 자주 묻는 질문은 접는 칸에 넣어 글이 길어 보이지 않게 한다. 접는 칸은 여는 표시와 닫는 표시가 반드시 짝을 이뤄야 한다.
- 담당자가 휴대전화에 복사해 둘 운영 메모는 글 맨 아래에 코드 구획 하나로 넣는다. 코드 구획 안의 글은 게시판에서 복사 버튼이 붙는다.
- 각주 · 출처 목록 · 내부 링크 · 접는 칸은 코드 구획 안에 넣지 않는다. 코드 구획 안에 들어가면 링크가 눌리지 않고 접는 칸도 글자 그대로 보인다.

1. 목차

- 소제목에 문장 부호나 괄호를 넣으면 주소가 달라져서 링크가 안 맞는 일이 있었어요. 소제목은 낱말 하나로 두시는 게 안전합니다.

2. 각주
- 준비물 설명을 각주로 빼시는 거 좋아요. 이번 안내문에는 각주를 '준비물' 하나로 두시면 어떨까요? 각주가 여러 개면 글 아래가 어수선해져요.
- 각주 표시는 본문 문장 끝에 붙이고, 정의는 글 맨 아래 출처 목록 위나 아래에 둡니다. 표시와 정의의 이름이 같아야 눌렀을 때 정의로 내려갑니다. 지난번 소모임 안내 글에서 표시는 '준비'로, 정의는 '준비물'로 써서 눌러도 아무 데도 안 간 적이 있어요.
- 정의 없이 표시만 있으면 게시판이 표시를 글자 그대로 보여 줍니다. 반대로 정의만 있고 표시가 없으면 정의가 글 아래에 덩그러니 남아요.

3. 출처 번호
- 운영 확인 기록의 참고 기록 번호를 그대로 쓰시면 됩니다. [1]은 교육장 점검 메모, [2]는 운영 예산 메모로요. 이 묶음 맨 끝에도 같은 두 줄을 붙여 둘게요.
- 번호를 붙인 문장은 그 기록에 실제로 적힌 내용이어야 합니다. 예를 들어 행사 · 접수 시각, 인력, 준비 조건은 [1], 비용 이야기는 [2]예요.
- 글 아래 출처 목록의 번호와 본문 번호가 서로 맞아야 해요. 본문에 [1]만 쓰고 목록에 [1] · [2]를 다 두는 건 괜찮지만, 본문에 [3]이 있는데 목록에 없으면 안 됩니다.

4. 문의 접는 칸
- 걱정하시는 거 이해해요. 그래서 접는 칸의 제목을 '문의'로 분명히 달고, 목차에서 '문의' 링크로 바로 오게 하면 못 보고 지나칠 일이 줄어요.
- 접는 칸은 여는 표시, 제목 표시, 내용, 닫는 표시 순서예요. 제목 표시 안의 글자가 접힌 상태에서 보이는 글자입니다. 이번에는 제목 표시 안에 '문의'라고만 쓰시면 됩니다.
- 접는 칸 안에도 목록을 쓸 수 있어요. 다만 접는 칸 여는 표시 바로 다음 줄에 목록을 붙이면 목록 모양이 깨지는 일이 있어서, 한 줄 띄우시는 게 좋아요.

- 그다음: 목차('접수', '문의')
- 본문: 일시, 참여 조건, 지켜 주실 것 같은 내용. 각주 표시는 본문 문장에 붙임
- '접수' 소제목과 내용
- '문의' 소제목, 그 아래 접는 칸(제목 표시 '문의')
- 각주 정의('준비물')
- 출처 목록([1] · [2])
- 맨 아래: 담당자 복사용 운영 메모 코드 구획 하나

이 순서면 코드 구획이 맨 마지막이라, 각주 정의 · 출처 목록 · 접는 칸 · 링크가 모두 코드 구획 밖에 놓여요. 선생님이 다른 순서가 더 낫다고 보시면 말씀해 주세요. 꼭 이대로일 필요는 없어요.

## 붙임 — 다른 글의 운영 메모는 어떻게 써 왔나(윤채아 메모)

반려마루 게시판의 다른 글 맨 아래 운영 메모 코드 구획에 무엇을 써 왔는지 모아 보았다. 이번 운영 메모를 쓸 때 참고하라고 노하람에게 보냈다. 실제 문장은 옮기지 않고 어떤 내용이었는지만 적는다.

- 보호자 상담의 날 운영 메모: 상담 순서를 부르는 방법, 상담실 문을 닫아 두는 이유, 상담 기록지를 상담이 끝난 뒤 바로 서랍에 넣는 것. 모두 담당자가 그날 지킬 행동을 한 문장씩 적었다.
- 노령견 천천히 걷기 모임 운영 메모: 출발 전 물 그릇 확인, 그늘에서 쉬는 지점, 노령견이 지쳐 보일 때 보호자에게 하는 말. 역시 문장 형태였다.
- 강아지 사회화 소모임 운영 메모: 장난감을 꺼내는 순서, 놀이를 멈추는 신호. 이 메모는 목록 기호로 썼다가 복사했을 때 읽기 불편하다는 말이 나와서 다음 회차부터 문장으로 바꿨다.
- 공통점: 운영 메모에는 회원에게 하는 안내가 아니라 담당자 자신에게 하는 말이 들어간다. 그래서 '~합니다'보다 '~한다'로 짧게 쓰는 경우가 많았다. 개인 정보와 예산 값은 넣지 않았다.
- 이번 워크숍은 진행 인력이 한 사람이라 운영 메모가 특히 중요하다는 데 노하람과 윤채아의 의견이 같았다.

## 붙임 — 지난 게시 사고 기록(윤채아가 메일 9를 쓰기 전에 모아 둔 것)

게시판을 새로 바꾼 뒤 '수업 안내' 칸과 '소모임' 칸에서 있었던 형식 사고들이다. 이번 점검 순서는 이 사고들에서 나왔다.

- 봄 소모임 안내 글: 목차의 '신청 방법'을 눌러도 움직이지 않았다. 실제 소제목이 '신청 방법 안내'였다. 목차 이름과 소제목 글자가 달랐던 것이다.
- 여름 산책 모임 글: 각주 표시는 '준비'였고 정의는 '준비물'이었다. 표시를 눌러도 아무 데도 가지 않았고, 정의는 글 아래 따로 떠 있었다.
- 상담의 날 글: 운영 메모 코드 구획의 닫는 표시가 빠졌다. 그 아래 출처 목록과 문의 안내까지 모두 회색 상자 안에 들어가 링크가 눌리지 않았다. 권시우 님이 메일 4에서 말한 일이다.
- 초여름 워크숍 후기 글: 자주 묻는 질문 접는 칸의 닫는 표시를 빼먹어서, 그 아래 후기 사진 설명까지 전부 접혀 보이지 않았다. 댓글로 "글이 중간에 끊겼다"는 말이 여러 번 달렸다.
- 노령견 모임 글: 접는 칸을 코드 구획 안에 넣어서, 접는 칸 표시가 글자 그대로 보였다.
- 같은 노령견 모임 글: 출처 번호 [3]을 본문에 썼는데 목록에는 [1] · [2]만 있었다. 원래 [3]은 지운 기록이었다.

## 붙임 — 회원 소식지 · 출입문 판과 게시판 글의 차이(윤채아 메모)

같은 안내문을 세 곳에 올리지만, 형식은 곳마다 다르다.

- 회원 게시판: 목차 링크 · 각주 · 출처 번호 · 접는 칸 · 코드 구획을 모두 쓸 수 있다. 이번 형식 규정이 적용되는 곳이다.
- 회원 소식지(종이): 링크와 접는 칸을 쓸 수 없다. 목차는 쓰지 않는다. 각주는 글 아래 작은 글씨로, 출처 번호는 넣지 않는다. 문의 내용은 펼친 채로 싣는다. 운영 메모는 싣지 않는다.
- 사무실 출입문 판: 큰 글씨로 일시 · 접수 · 참여 조건 · 문의처만 싣는다. 나머지는 '게시판과 소식지를 보세요'로 대신한다.
- 세 곳 모두 내용은 같아야 한다. 고칠 때는 같은 날 함께 고친다.

## 붙임 — 게시판 형식 낱말 풀이(윤채아가 새 담당자용으로 만든 쪽지)

게시판을 처음 쓰는 사람이 메일에 나온 낱말을 헷갈리지 않도록 적었다.

- 목차: 글 맨 위에 두는 짧은 목록. 항목을 누르면 글 안의 해당 소제목으로 바로 내려간다.
- 내부 링크: 같은 글 안의 다른 위치로 가는 링크. 보이는 이름은 대괄호 안에, 가는 곳은 샵 기호와 소제목 글자로 적는다. 가는 곳의 글자는 실제 소제목 글자와 같아야 한다.
- 소제목: 글 안의 작은 제목. 게시판은 소제목 글자를 그대로 내부 링크 주소로 쓴다. 그래서 소제목 글자를 바꾸면 목차 링크도 함께 바꿔야 한다.
- 각주 표시: 본문 문장 끝에 붙이는 작은 표시. 대괄호 안에 꺾쇠 기호와 각주 이름을 쓴다.
- 각주 정의: 글 아래에 두는 각주 설명. 표시와 같은 이름 뒤에 쌍점을 붙이고 설명을 쓴다. 표시만 있고 정의가 없거나, 이름이 서로 다르면 작동하지 않는다.
- 출처 번호: 본문 문장에 붙이는 대괄호 숫자. 반려마루 안의 기록을 가리킨다.
- 출처 목록: 글 아래에 두는 번호별 기록 제목. 번호와 제목은 운영 확인 기록의 참고 기록 절과 같게 쓴다.
- 접는 칸: 눌러야 내용이 펼쳐지는 칸. 여는 표시, 제목 표시(접힌 상태에서 보이는 글자), 내용, 닫는 표시로 이뤄진다. 여는 표시와 닫는 표시가 짝을 이뤄야 한다.
- 코드 구획: 회색 상자로 보이는 칸. 안의 글은 꾸밈 없이 글자 그대로 보이고 복사 버튼이 붙는다. 여는 표시와 닫는 표시가 짝을 이뤄야 한다. 안에 넣은 링크 · 각주 · 접는 칸은 작동하지 않는다.
- 운영 메모: 담당자가 그날 휴대전화에 복사해 두고 읽는 문장. 게시판 글 맨 아래 코드 구획 하나에 넣는다.

## 붙임 — 게시판 댓글 문의는 누가 어떻게 답하나(권시우 · 윤채아 합의, 9월 24일)

안내문을 올리면 댓글로 문의가 달린다. 초여름 회차 때는 여러 사람이 각자 답을 달아 서로 다른 답이 나간 일이 있었다(되짚기 자료 문의 기록 2번 등). 이번에는 이렇게 하기로 했다.

- 문의 댓글에 답하는 사람은 교육 담당 노하람 한 사람이다. 문의처가 노하람이기 때문이다.
- 윤채아와 권시우는 댓글을 보면 노하람에게 알리기만 하고 직접 답하지 않는다.
- 답은 운영 확인 기록의 문의 답변 범위 안에서 한다. 범위 밖의 질문(예: 대리 참석, 회원 여부)은 "확인하고 다시 답을 드리겠습니다"로만 답하고 대표와 확인한다.
- 날짜와 연락처를 묻는 댓글에는 미정이라고 답한다. 짐작으로 날짜를 말하지 않는다.
- 같은 질문이 여러 번 달리면, 안내문의 '문의' 접는 칸에 그 질문과 답을 더한다. 더할 때는 메일 9의 점검 순서를 다시 거친다.
- 댓글 답에 출처 번호를 붙이지 않는다. 출처 번호는 안내문 본문과 출처 목록에서만 쓴다.

## 붙임 — 안내문 첫 번째 수정본에서 형식상 손볼 곳(윤채아가 9월 23일에 읽고 적은 것)

노하람이 9월 21일에 만든 첫 번째 수정본(접수 시각 변경 · 가족 동반 예외 취소 반영)을 게시판 규정에 비추어 읽었다. 내용은 고치지 않고 형식만 보았다.

- 목차가 없다. 글이 길어졌으니 목차를 넣는 편이 좋다.
- '접수'에 해당하는 내용이 '오시는 날 안내'라는 소제목 아래 섞여 있다. 목차 링크를 걸려면 '접수'라는 소제목을 따로 세워야 한다.
- 문의 내용이 글 중간과 끝에 나뉘어 있다. '문의' 소제목 하나 아래 접는 칸으로 모으면 좋겠다.
- 준비물 이유가 본문 문장 안에 길게 들어가 있다. 각주로 빼면 본문이 짧아진다.
- 출처 번호가 없다. 운영 확인 기록을 근거로 한 문장에 번호를 붙이고 글 아래 목록을 두는 것이 규정이다.
- 운영 메모가 없다. 담당자 복사용 메모를 맨 아래에 두면 좋겠다.
- 날짜와 연락처는 '미정'으로 잘 적혀 있다. 그대로 두면 된다.

## 붙임 — 게시판 형식 규정이 생긴 까닭(윤채아 메모)

지난봄 반려마루 회원 게시판을 새 게시판으로 옮기면서 형식 규정을 만들었다. 새로 온 담당자가 왜 이렇게까지 형식을 따지는지 물어서 적어 둔다.

- 예전 게시판은 글을 꾸밀 수 없어서 긴 안내문이 한 덩어리 글로 올라갔다. 회원들이 "어디에 접수 시간이 있느냐"고 댓글로 묻는 일이 많았다. 새 게시판으로 옮기면서 목차와 내부 링크를 쓰기로 한 것은 그 때문이다.
- 안내문마다 비슷한 질문이 댓글로 반복되었다. 자주 묻는 질문을 접는 칸에 넣으면 글이 길어 보이지 않으면서도 답을 찾을 수 있다.
- 담당자가 당일 휴대전화로 안내문 전체를 다시 읽기는 어렵다. 담당자에게 필요한 문장만 맨 아래 코드 구획에 모아 두면 복사 버튼 하나로 메모장에 옮길 수 있다. 특히 혼자 진행하는 날에 쓸모가 있었다.
- 근거를 밝히지 않은 숫자가 안내문에 섞여 혼선이 생긴 적이 있었다. 출처 번호를 붙이면 어느 기록에서 온 값인지 나중에 확인할 수 있다.
- 형식이 많아지면 실수도 늘어난다. 그래서 게시 전 점검 순서(메일 9)를 함께 만들었다.

## 붙임 — 휴대전화 화면에서 확인한 것(윤채아, 9월 25일 시험 글)

- 목차는 휴대전화에서 한 줄에 하나씩 보인다. 두 항목이면 화면 첫머리에 다 들어온다.
- 접는 칸 제목 표시의 글자는 본문 글자보다 조금 작게 보인다. 접힌 칸 앞에 작은 삼각형이 붙는데, 나이 많은 회원은 이 표시를 잘 모를 수 있다. 목차에서 '문의'로 오게 하는 이유가 여기 있다.
- 코드 구획은 휴대전화에서 좌우로 밀어야 보이는 경우가 있다. 운영 메모 문장을 너무 길게 쓰지 않고 한 문장씩 줄을 바꾸면 밀지 않아도 된다.
- 각주 표시는 휴대전화에서 손가락으로 누르기에 작다. 각주를 여러 개 두지 않고 '준비물' 하나로 하자는 메일 3의 제안과 맞는다.
