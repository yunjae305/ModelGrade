    · 인식: 단가×수량 총액 관계 추출: 질문에 단가 표현(단가/개당/한 개에/1개에/하나에 … 원, 또는 …원짜리)과 수량 표현(수량/개수 …, 또는 …개/장/권/병/잔/벌 사면·구매·구입·주문·샀)과 총액 낱말(총액·총 금액·합계 금액·총 비용·전체 금액·총 얼마·모두 얼마·얼마)이 모두 있으면, 단가·수량 후보가 각각 정확히 1개일 때 기대값 = 단가×수량 (라벨: 총액·총 금액·총금액·합계 금액·합계·총 비용·전체 금액·총); 후보가 여러 개면 UNSUPPORTED
    · 인식: 동사형 사칙연산 추출: 'a에서 b를 빼'(−), 'a와/과/에/, b를 더하·더해·합하·합해·합치'(+), 'a에/과/와 b를 곱'(×), 'a를 b로 나누'(÷) 꼴에서 부호(+/−) 포함 피연산자 두 개로 기대값 계산; b가 0인 나누기는 관계로 보지 않음
    · 인식: 퍼센트 관계 추출: 단가×수량·동사형 관계(미확정 포함)가 하나도 없을 때만 'a(원|명|개|점)의 b%' 또는 'a의 b퍼센트'에서 기대값 = a×b/100 (라벨: 결과·답·값)
    · 인식: 명시 수식 추출: 앞선 관계가 하나도 없을 때만 '12 + 8은?'처럼 부호 포함 숫자와 +−×÷*/ 연산자로 된 식 뒤에 은/는/=/의 값·의 결과가 오면 재귀 하강 파서(arith._evaluate)로 기대값 계산 (라벨: 결과·답·값); 해석 불가·0 나눗셈이면 건너뜀
    · 인식: 계산 관계 후보 단일성: 질문에서 성립(ok)하는 계산 관계가 2개 이상이면 답변에 맞춰 고르지 않고 UNSUPPORTED; 추출 단계에서 미확정(unsupported)된 관계도 그대로 UNSUPPORTED 로 보고
    · 인식: 기대값·주장값 비교: |주장값 − 기대값| ≤ 허용오차. 허용오차는 주장값 표기 기준: 정수 표기면 0(정확 일치), 소수 표기면 마지막 자리의 절반(예: 3.33 → ±0.005)
- 3-3.transform · 원본 보존·변환 · 질문·앞 턴 지시에 요구가 있을 때 · 예: 아래 JSON에서 'score'가 80 이상인 항목만 남기고 'score' 기준 내림차순으로 정렬해줘. ```json [{"id":1,"score":90},{"id":2,"score":70},{"id":3,"score":85}] ```
    · 알아보는 질문 조건(섞어 씀): 정렬·필터·변환
    · 인식: 원본 자료 1개 확정: 질문에서 비어 있지 않은 JSON 배열(펜스 또는 본문)·헤더 있는 마크다운 표·(JSON·표 후보가 하나도 없을 때만) 2개 이상 최상위 목록 항목 중 정확히 1개를 원본으로 잡음. 0개면 transform 요구를 만들지 않음(단 원본 보존 요구가 있으면 '원본 대상을 확정하지 못함' UNSUPPORTED). 2개 이상이면 '원본 자료로 보이는 것이 N개' 사유로 UNSUPPORTED
    · 인식: 연산 인식은 각 1회, 적용 순서 고정: 필터·중복 제거·정렬·키 변경은 각각 첫 매치 1개만 인식하고, 질문 어순과 무관하게 필터→중복 제거→정렬→키 변경 순으로 원본에 적용함. 키는 따옴표 리터럴 또는 바로 앞의 영문·한글 단어(key2)로 잡음
    · 인식: 필터 연산 적용: 질문의 "'키'(이|가|은|는|값이) N 이상|이하|초과|미만(인) (항목|것|행|…)만" 을 인식해 원본에서 키 값이 조건을 만족하는 항목만 남김. 키 값이 숫자(또는 숫자 문자열)가 아닌 항목이 있으면 비교값을 만들지 않음(UNSUPPORTED)
    · 인식: 중복 제거 연산 적용: 질문의 "중복(을|된 값을|된 항목을|값을|된 것을) 제거|없애|빼" 를 인식해 자료형을 구분한 same() 기준으로 첫 등장 항목만 남김
    · 인식: 정렬 연산 적용: 질문의 "('키' (을|를|의) 기준(으로)) 오름차순|내림차순|큰 순서|작은 순서|높은 순|낮은 순(으로) 정렬|나열|배열" 을 인식해 숫자(전부 숫자 변환 가능) 또는 문자열(전부 str) 키로 안정 정렬. 내림·큰·높은 → desc, 그 외 asc. 키가 없는 항목이 있거나 값 자료형이 섞이면 UNSUPPORTED
    · 인식: 키 이름 변경 적용: 질문의 "'a'(키|필드)(을|를) 'b'(으로|로) 바꿔|변경|바꾸" 를 인식해 각 객체의 키 a를 b로 바꿈. 항목이 객체가 아니면 UNSUPPORTED
    · 인식: 원본 보존 요구 → 순서 비교 켜기: 질문의 "원본|원래|주어진 (값|데이터|순서|자료) … 그대로|유지|보존|바꾸지" 또는 "순서|값|ID|아이디 (그대로) 유지|보존" 이 있으면 preserve=true 로 잡아 연산이 없어도 transform 요구(기대=원본)를 만들고, 정렬 연산이 있을 때와 같이 순서까지 비교(ordered)
- 3-3.unique_values · 명시 고유성 · 질문·앞 턴 지시에 요구가 있을 때 · 예: 아래 목록의 과일 이름을 중복 없이 JSON 배열로 나열해줘. ```json ["사과", "배", "사과", "포도"] ```
    · 알아보는 질문 조건(섞어 씀): 중복 없이
    · 인식: '중복 없이' 요구 인식: 질문(자료 펜스·인용·표를 가린 지시문)에 "중복 없이|되지 않게|되지 않도록" 또는 "서로 다른 값" 이 있고 질문 본문에 원본 자료가 1개 있으면 unique_values 요구를 만듦. 원본 자료가 없거나 코드·함수 작성 요구면 조건을 만들지 않음(행 없음)
    · 인식: 중복 항목 0개: 출력의 각 항목이 앞선 어떤 항목과도 same() 으로 같지 않아야 함(목록은 항목 본문 strip 문자열, 표는 헤더→셀 dict). 중복 인덱스 수 == 0 이면 PASS, 아니면 '중복 항목 N개' 로 FAIL (자료형 구분)
- 3-3.aggregate · 명시 집계값 · 질문·앞 턴 지시에 요구가 있을 때 · 예: 아래 표에서 '점수'의 합계를 알려줘. | 이름 | 점수 | |---|---| | 철수 | 80 | | 영희 | 90 |
    · 알아보는 질문 조건(섞어 씀): 합계·평균 집계
    · 인식: 집계 요구 인식: 질문의 "'키'|키단어 (열|필드|값)(의) 합계|총합|평균|최댓값|최솟값|최대값|최소값" 첫 매치를 인식해 key·agg 를 잡음(키는 따옴표 리터럴 또는 바로 앞 영문·한글 단어)
    · 인식: 원본 자료 1개 확정: 질문의 비어 있지 않은 JSON 배열·헤더 있는 표·(그 둘이 없을 때) 2개 이상 목록 중 정확히 1개가 원본이어야 함. 여러 개면 '어느 자료를 계산하라는지 정할 수 없음' 으로 UNSUPPORTED, 없으면 요구가 만들어지지 않음
    · 인식: 집계값 일치 (허용 오차): |답변값 − 기대값| ≤ 허용 오차. 정수로 적었으면 오차 0(정확 일치), 소수로 적었으면 마지막 표시 자리의 절반(0.5×10^-자릿수)까지 인정
## 의미 평가 점검 항목 (id · 세부 기준 · 점검 질문(예 = PASS) · 적용 · 판정 근거 · 펼침 · FAIL 예)
- J2-1.a · J2-1 대상 수준 · 지정한 대상·받는 사람이 모를 용어를 설명 없이 쓰지 않았는가 · 적용: 대상·받는 사람 표현 · 근거: 대상, 해당 용어 (FAIL 시) · FAIL 예: 설명 깊이와 말투는 PASS와 같지만 'LTE·5G 셀룰러 망'을 풀어 주지 않고 써서 J2-1.a만 아니오.
- J2-1.b · J2-1 대상 수준 · 지정 대상이 이미 아는 수준의 설명만 있거나(너무 얕음), 대상이 모를 전제 지식을 요구하지(너무 깊음) 않는가 (용어 문제는 J2-1.a) · 적용: 위와 같음 · 근거: 대상 표현 인용, 가장 얕거나 깊은 문장 1개 · FAIL 예: 모르는 용어는 없지만(J2-1.a 예) 입문자용 깊이라 10년 차 시니어 청중에게 맞지 않아 J2-1.b만 아니오.
- J2-2.a · J2-2 말투·어조 · 지정한 말투·존대를 처음부터 끝까지 지켰는가. 추상적 어조 지시(따뜻하게 등)는 명백히 반대되는 문장이 없는가 · 적용: 현재 질문의 말투·어조 지정 · 근거: 지정 문장, 어긋난 문장 · 펼침: 지시별(질문에 이 요소를 2개 이상 넣음) · FAIL 예: 앞부분은 반말이지만 마지막 두 문장이 존댓말로 바뀌어 끝까지 지키지 못해 J2-2.a만 아니오.
- J2-3.a · J2-3 조건·제약 준수 · 질문이 직접 말한 조건·제약("~는 빼고", "~이내", "~만", "~안 돼")을 어긴 문장이 없는가 (조건 아래서 계획이 성립하지 않는 것은 J3-5.a) · 적용: 질문의 조건 문장 (개수·형식은 코드 평가, 모순 조건 쌍은 J1-3, 인원·시간·장소 같은 자원 조건은 J3-5) · 근거: 조건 문장, 위반 문장 · 펼침: 조건별(질문에 이 요소를 2개 이상 넣음) · FAIL 예: 감사 내용은 갖췄고 퇴사 이유도 없지만, 쓰지 말라고 한 이직 회사 이름을 써서 '회사 이름' 조건에서 J2-3.a만 아니오.
- J2-4.a · J2-4 설명 방식 · 지정한 방식(비유·예시·관점·상황)으로 설명했는가 · 적용: 설명 방식 지정 · 근거: 지정 문장, 해당 설명 · FAIL 예: 설명 내용은 맞지만 비유 없이 직접 설명만 해 지정한 방식을 따르지 않아 J2-4.a만 아니오 (비유가 없으므로 J2-4.b는 해당 없음이어야 함).
- J2-4.b · J2-4 설명 방식 · 비유·예시가 설명 대상의 핵심 특징과 맞물리는가 (개념을 틀리게 전달하면 J5-1) · 적용: 설명 방식이 지정되고 답변에 비유·예시가 실제로 있을 때 (J2-4.a가 아니오면 해당 없음) · 근거: 비유·예시 문장 · 적용 여부는 평가 모델이 정함(그 상황이 분명히 생기게 설계) · FAIL 예: 비유는 들었고(J2-4.a 예) 직접 설명도 맞지만(J5-1 통과), '짧은 기간 대 긴 기간 평균'이라는 날씨·기후의 차이가 외상·선투자의 시점 차이라는 이익·현금흐름의 차이와 대응하지 않아 J2-4.b만 아니오.
- J2-5.a · J2-5 추천·글의 목적 적합성 · 추천이 현재 질문에 서술된 배경·상황(J2-3 목록에 없는 것)에 맞는가 (이전 턴에만 있는 상황은 J6-2.b) · 적용: 추천·제안 요청 · 근거: 상황 문장, 추천 문장 · FAIL 예: 질문에 금지·예산 같은 명시 조건은 없어 J2-3에는 걸리지 않지만, 원룸에 요리를 안 하는 부부라는 서술된 상황과 맞지 않는 부피 큰 주방용품을 추천해 J2-5.a만 아니오.
- J2-5.b · J2-5 추천·글의 목적 적합성 · 글이 질문이 정한 목적(사과·거절·홍보·안내 등)을 실제로 수행하는가 (예: 사과문이 변명 위주가 아닌가) · 적용: 글 작성 요청 · 근거: 목적 표현 인용, 목적에 어긋난 문장 · FAIL 예: 사과 대신 주문량·택배사 사정을 늘어놓아 변명 위주라 사과문이라는 목적을 수행하지 못함.
- J3-2.a · J3-2 근거와 결론 · 주 결론(질문이 요구한 선택·추천·판단)에 결론을 바꿔 말한 것이 아닌 근거 문장이 하나 이상 있는가 · 적용: 추천·선택·판단이 있는 답변 ("왜·원리" 설명은 J3-3). 답변당 1개 · 근거: 결론 문장, 근거 문장 · FAIL 예: 추천 결과물은 있으나(J1-1 통과) 왜 그 제품인지 설명하는 근거 문장이 없음. "가장 알맞다"는 결론을 다시 말한 것이지 근거가 아님. 질문이 이유를 요구하지 않아 J4-2도 해당 없음.
- J3-2.b · J3-2 근거와 결론 · 제시한 근거로 결론이 성립하는가 · 적용: 위와 같음 · 근거: 위와 같음 · FAIL 예: 근거(가입 사은품)는 있어 J3-2.a는 통과하지만, 그 근거로는 "화상회의가 안정적"이라는 결론이 나오지 않음.
- J3-3.a · J3-3 인과·원리 · 원인과 결과를 잇는 방향이 질문이 준 선후·조건과 맞는가 (각 사실의 진위는 J5-1) · 적용: 질문에 선후·조건이 적힌 이유·원리 요청. 없으면 해당 없음 · 근거: 질문의 선후·조건, 답변의 인과 문장 · 적용 여부는 평가 모델이 정함(그 상황이 분명히 생기게 설계) · FAIL 예: 건조한 공기→잎 마름이라는 원리 자체는 현상을 설명하므로 J3-3.b는 통과하지만, 난방과 건조 사이의 원인·결과를 뒤집어 난방을 결과로 놓음. 질문이 말한 선후(난방 뒤 잎 마름)와도 맞지 않음.
- J3-3.b · J3-3 인과·원리 · 설명한 원리가 대상 현상을 실제로 설명하는가 (비유·예시 문장은 빼고 직접 설명만. 비유는 J2-4.b) · 적용: 이유·원리 요청 · 근거: 원리 설명 부분 · FAIL 예: 저온에서 미생물 번식이 느리다는 설명은 방향도 맞고 사실이지만, 그것이 왜 빵을 더 빨리 굳게 하는지는 전혀 설명하지 못함(원리와 현상이 연결되지 않음).
- J3-4.a · J3-4 풀이 연결 · 풀이 단계가 끊김 없이 이어지는가 (계산값은 코드 3-1, 입력 값은 J5-2) · 적용: 풀이 요청 · 근거: 끊긴 단계 (FAIL 시) · FAIL 예: 거리를 구하는 단계가 없어 "빨라지면 줄어든다"에서 1시간으로 건너뜀. 최종 값은 맞고 입력 값도 그대로라 코드 3-1·J5-2는 통과.
- J3-5.a · J3-5 실행 가능성 · 답변 안에 적힌 시간·인원·순서끼리 맞는가 (같은 사람 동시 배정, 결과가 전제보다 먼저, 적힌 소요 시간 합이 구간을 넘음 등. 외부 지식이 필요한 불가는 J5-1) · 적용: 계획·일정·절차 요청 · 근거: 맞지 않는 두 지점 · FAIL 예: 혼자인데 1시에 부스 판매와 주차장 왕복을 동시에 배정해 한 사람이 실행할 수 없음. 질문의 명시 조건(혼자·1~5시·15분 거리)은 바꾸지 않아 J2-3·J5-2는 통과.
- J3-5.b · J3-5 실행 가능성 · 값은 같은데 상한·예상·실제 같은 역할을 바꿔 쓰지 않았는가 (값 자체가 다르면 J5-2.a) · 적용: 예산·수치에 역할이 있는 질문 · 근거: 값과 역할 표현 · FAIL 예: 15만원(예상)과 28만원(실제)의 역할을 서로 바꿔 씀. 값 자체와 계산(40-15=25, 28-25=3)과 최종 차액은 그대로라 코드 3-1·J5-2·J3-1은 통과.
- J4-1.a · J4-1 비교 완결 · 비교 대상을 모두 다뤘는가 · 적용: 비교 요청 (비교 문장이 어떤 형태로든 있을 때. 비교 자체가 없으면 J1-1) · 근거: 예: 대상마다 답변 인용 / 아니오: 질문 인용 + 가장 가까운 답변 구절 · 펼침: 대상별(질문에 이 요소를 2개 이상 넣음) · FAIL 예: 일반 자전거를 한 번도 다루지 않고 두 대상만 비교해 결론을 냄. 결론 자체는 있으므로 J1-1 아님, 질문에 비교 기준 지정이 없어 J4-1.b는 해당 없음.
- J4-1.b · J4-1 비교 완결 · 질문이 정한 비교 기준(장단점 포함)을 모두 다뤘는가 · 적용: 비교 기준이 명시된 경우 · 근거: 예: 기준마다 답변 인용 / 아니오: 질문 인용 + 가장 가까운 답변 구절 · 펼침: 기준별(질문에 이 요소를 2개 이상 넣음) · FAIL 예: 두 대상은 모두 다뤘고(J4-1.a 예) 근거 있는 결론도 있으나(J1-1·J3-2 예), 질문이 정한 기준 '이사 당일 내가 해야 할 일'이 어디에도 없어 비용 기준만으로 결론을 냄.
- J4-2.a · J4-2 함께 요구한 항목 · 주 요청 외에 종류가 다른 요구(추가 요청·이유·예시·각각)가 모두 있는가 (비교의 기준·장단점은 J4-1.b, "N개" 같은 개수 요구는 코드 2-1) · 적용: 요청·요구가 2개 이상 · 근거: 예: 요구마다 답변 인용 / 아니오: 질문 인용 · 펼침: 요구별(질문에 이 요소를 2개 이상 넣음) · FAIL 예: 좋은 점·주의할 점은 있으나 '보상 예시'는 없고 보상이 필요하다는 언급만 있음. 주 요청의 결과물은 있으므로 J1-1 아님, 비교 질문이 아니라 J4-1 해당 없음.
- J4-3.a · J4-3 핵심 단계·구성 요소 · 목적에 필요한 핵심 단계·필수 구성 요소를 먼저 나열하고 그중 빠진 것이 없는가 (풀이 단계는 J3-4, 빠져서 실행 불가면 J3-5.a) · 적용: 방법·절차(how-to) 요청과 글 작성 요청. 풀이 요청은 제외 · 근거: 예: 단계·요소마다 답변 인용 / 아니오: 질문 인용 · 펼침: 단계·요소별(질문에 이 요소를 2개 이상 넣음) · FAIL 예: 장소·행동 요령·문의처는 있으나 안내문의 필수 요소인 일시(10월 24일 오후 2시)가 통째로 빠짐. 글은 완성되어 있어 J1-1 아님, 질문 값을 바꾼 것이 아니라 뺀 것이므로 J5-2 아님.
- J4-4.a · J4-4 요약 핵심 · 원문의 핵심 정보(독자가 판단·행동하는 데 필요한 날짜·기간·장소·대상·조건·할 일)를 먼저 나열하고 그중 빠진 것이 없는가. 해당 주제의 문장이 있으면 내용이 틀려도 있음(틀린 내용은 J5-2.b). "자세한 건 원문 참고"는 없음 · 적용: 요약 요청 · 근거: 예: 원문 인용, 요약 인용 / 아니오: 원문 인용 · 펼침: 핵심 정보별(질문에 이 요소를 2개 이상 넣음) · FAIL 예: 시작일·기간·폐쇄·대체 주차 지원은 있으나 지원을 받기 위해 독자가 해야 할 '영수증을 매월 말 총무팀에 제출'이 빠짐. 없는 내용을 더하거나 뜻을 바꾸지는 않았으므로 J5-2.b 아님.
- J5-1.a · J5-1 사실 정확성 · 답변의 외부 사실 주장(수치·날짜·명칭·통계·개념 정의)이 사실과 맞는가. 시점이 있는 사실은 답변 수집 날짜 기준 · 적용: 코드 규칙이 사실 정보를 묻는 질문으로 판정한 질문 (J3-1 모순 쌍, J3-3 인과 연결 문장, 이전 턴 AI 답변에서 비롯한 값은 제외) · 근거: 주장 인용과 검색 기록. 거짓이면 올바른 사실과 반박 출처 원문 · 펼침: 주장별(질문에 이 요소를 2개 이상 넣음) · FAIL 예: 아데노신 설명과 인과 구조는 맞지만 반감기 수치가 거짓(실제 평균 약 5시간). 사실 오류 하나로 해당 주장만 거짓, J3-3은 걸리지 않음.
- J5-2.a · J5-2 입력 자료 충실성 · 질문에서 준 개별 값·이름·날짜를 썼다면 다른 값으로 적지 않았는가 (쓰지 않은 값은 해당 없음. 상황 문장·선후 관계는 값이 아님) · 적용: 현재 질문의 값을 쓰는 답변 · 근거: 질문 원문, 답변 인용 · 펼침: 값별(질문에 이 요소를 2개 이상 넣음) · FAIL 예: 질문이 준 장소 '제2물류센터'를 '제1물류센터'로 바꿔 썼음. 메일 구성 요소와 요청 사항은 다 있어 J1·J4는 통과하고 이 값 하나만 아니오.
- J5-2.b · J5-2 입력 자료 충실성 · 질문이 준 자료를 정리·요약할 때 원문에 없는 문장을 더하거나 문장 단위 의미를 바꾸지(취소→연기 등) 않았는가 (개별 값 오기는 J5-2.a) · 적용: 자료 정리·요약 요청 · 근거: 자료 원문, 답변 인용 · FAIL 예: 원문은 '취소되고 평소처럼 보육'인데 '다음 주로 연기'로 의미를 바꿈. 핵심 정보는 다 들어 있어 J4-4(누락)는 통과하고 이 항목만 아니오.
