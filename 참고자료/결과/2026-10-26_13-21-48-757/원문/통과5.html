def can_attempt(attempts: int, limit: int) -> bool:
    """응시 횟수가 한도 미만인지 확인하여 가능 여부(True/False)를 반환합니다.

    입력값을 직접 변경하지 않고 비교 결과만 반환합니다.
    """
    return attempts < limit


# --- 사용 예시 ---

print(f"응시 횟수: {current_attempts}, 한도: {exam_limit} -> 응시 가능: {result1}")

# 2. 한도에 도달한 경우 (3회 응시 / 한도 3회 -> 불가: False)
current_attempts = 3
result2 = can_attempt(current_attempts, exam_limit)
print(f"응시 횟수: {current_attempts}, 한도: {exam_limit} -> 응시 가능: {result2}")

# 3. 한도를 초과한 경우 (4회 응시 / 한도 3회 -> 불가: False)
current_attempts = 4
result3 = can_attempt(current_attempts, exam_limit)
print(f"응시 횟수: {current_attempts}, 한도: {exam_limit} -> 응시 가능: {result3}")

답변
파이썬에서 `0`과 `False`를 보존하면서 `None`만 걸러내려면, 조건문에 단순히 `if x:`를 쓰는 대신 `if x is not None`으로 명시해야 합니다. 파이썬에서는 `0`과 `False` 역시 거짓(Falsy)으로 취급되므로, 단순 참/거짓 검사를 거치면 함께 삭제되기 때문입니다.

요청하신 함수와 사용 예시는 다음과 같습니다.

```python
def remove_none_values(measurements):
    """
    측정값 목록에서 None만 제거한 새로운 리스트를 반환합니다.
    - 0과 False는 그대로 보존됩니다.
    - 원본 리스트는 수정되지 않습니다.
    """
    return [item for item in measurements if item is not None]


# --- 사용 예시 ---
# 0, False, None, 양수, 음수 등이 섞여 있는 원본 측정값 리스트
raw_measurements = [12.5, 0, None, -3.2, False, 0.0, None, 45]

# 함수 실행 (새로운 리스트 생성)
cleaned_measurements = remove_none_values(raw_measurements)

# 결과 확인
print("정제된 목록:", cleaned_measurements)
print("원본 목록  :", raw_measurements)

```

### 동작 원리 설명

1. **`is not None` 조건 사용**
* `None`은 파이썬에서 유일한 싱글턴 객체입니다. 따라서 값이 정확히 `None`인지를 판별할 때는 동등 비교(`!=`) 대신 항등 연산자(`is not`)를 사용하는 것이 가장 정확하고 권장되는 방식입니다.
* 이렇게 비교하면 `0`이나 `False`는 `None`과 완전히 다른 객체이므로 걸러지지 않고 안전하게 보존됩니다.


2. **리스트 컴프리헨션(List Comprehension) 활용**
* `[item for item in measurements if ...]` 형태는 기존 리스트의 요소를 하나씩 꺼내 조건에 맞는 것만 골라 **완전히 새로운 리스트**를 만듭니다.
* `measurements.remove()`나 `del`처럼 원본을 직접 건드리는 방식이 아니기 때문에, 함수를 실행한 후에도 넘겨준 원본 리스트는 처음 상태 그대로 유지됩니다.

답변
두 예약 시간대가 서로 겹치는지 확인하는 파이썬 함수와 실행 예제입니다.

```python
def is_overlapping(start1: int, end1: int, start2: int, end2: int) -> bool:
    """
    두 예약 구간(분 단위)이 겹치는지 판별합니다.
    시작 시각과 종료 시각이 맞닿는 경우(예: 90과 90)는 겹치지 않는 것으로 처리합니다.
    """
    return start1 < end2 and start2 < end1


# 사용 예: 60~90과 90~120
result = is_overlapping(60, 90, 90, 120)
print(f"겹침 여부: {result}")

```

### 동작 원리 설명

두 시간대가 겹치지 않는 상황을 먼저 떠올리면 쉽게 이해할 수 있습니다.

1. **첫 번째 예약이 완전히 먼저 끝나는 경우:** 첫 번째 종료 시각이 두 번째 시작 시각보다 작거나 같을 때 (`end1 <= start2`)
2. **두 번째 예약이 완전히 먼저 끝나는 경우:** 두 번째 종료 시각이 첫 번째 시작 시각보다 작거나 같을 때 (`end2 <= start1`)

두 예약이 겹치려면 위 두 상황 중 어느 것에도 해당하지 않아야 합니다. 이를 반대로 뒤집으면 다음 두 조건을 동시에 만족해야 합니다.

* 첫 번째 시작 시각이 두 번째 종료 시각보다 빨라야 합니다 (`start1 < end2`).
* 두 번째 시작 시각이 첫 번째 종료 시각보다 빨라야 합니다 (`start2 < end1`).

`60~90`과 `90~120`을 대입해 보면:

* `60 < 120`은 참(True)이지만,
* `90 < 90`은 거짓(False)이 됩니다.

두 조건을 모두 만족해야 겹치는 것이므로 최종 반환값은 `False`가 되며, 문제 조건대로 끝나는 시각과 시작 시각이 같을 때 겹치지 않게 정확히 동작합니다.

### 1. 초기 기포와 비등(끓음) 기포의 성분 비교

물속 기포는 겉보기에 비슷해 보이지만, 온도가 올라감에 따라 전혀 다른 물리·화학적 메커니즘으로 만들어집니다.

| 구분 | 처음 바닥에 생기는 작은 기포 | 충분히 끓는 동안의 큰 기포 |
| --- | --- | --- |
| **주요 성분** | **공기 (산소, 질소, 이산화탄소 등)** | **수증기 ($H_2O$ 기체)** |
| **발생 원리** | 기체의 용해도 감소 (헨리의 법칙 관련) | 상변화(비등, Boiling) 및 증기압 도달 |
| **특징** | 바닥이나 벽면에 좁쌀 모양으로 맺힘 | 물 내부 전체에서 격렬하게 생성되어 솟구침 |

* **처음 바닥에 생기는 작은 기포:** 물속에는 평소 대기 중의 산소와 질소 같은 공기가 녹아 있습니다(용존 기체). 기체의 용해도는 액체의 온도가 올라갈수록 감소합니다. 바닥부터 온도가 오르면 물이 품을 수 있는 기체의 양이 줄어들어, 과포화된 기체가 냄비 바닥의 미세한 흠이나 요철을 중심으로 뭉쳐 공기 방울이 됩니다.
* **충분히 끓을 때의 기포:** 물 전체의 온도가 끓는점($100^\circ\text{C}$, 1기압 기준)에 도달하면 물의 **증기압**이 외부 **대기압**과 같아집니다. 이때는 표면뿐 아니라 물 내부 어디서든 액체 물이 기체인 수증기로 상태 변화를 일으키며 거대한 수증기 방울을 만듭니다.

### 2. 기포의 생성부터 수면 상승까지의 단계별 원인

기포가 발생하여 물 표면으로 빠져나가는 과정은 열전달, 부력, 압력의 상호작용으로 진행됩니다.

**1단계: 바닥에서의 핵생성 (Nucleation)**
열원과 직접 맞닿는 바닥의 물이 가장 먼저 뜨거워집니다. 바닥 표면의 미세한 틈새나 미세 입자는 표면장력 장벽을 낮춰 기포가 쉽게 자리 잡는 **핵생성 자리(Nucleation site)** 역할을 합니다. 초기에는 녹아 있던 공기가, 비등 시점에는 기화된 수증기가 이곳에 모여 구 형태를 이룹니다.

**2단계: 이탈과 부력 작용**
기포가 자라남에 따라 기포의 부피($V$)가 커집니다. 아르키메데스의 원리에 따라 기포가 받는 부력($F_b = \rho_{물} \cdot V \cdot g$)은 기포 내부의 기체 무게보다 훨씬 큽니다. 바닥에 기포를 붙잡아 두려는 표면장력보다 위로 뜨려는 부력이 더 커지는 순간, 기포는 바닥을 떼고 상승하기 시작합니다.

**3단계: 상승 중 주변 조건에 따른 변화**

* **완전히 끓기 전(과도기):** 바닥에서 생성된 수증기 기포가 위쪽으로 올라가다 아직 상대적으로 차가운 상부의 물을 만납니다. 이 차가운 층에서 수증기가 급격히 열을 빼앗겨 다시 액체로 응축($H_2O(g) \to H_2O(l)$)되면서 부피가 순간적으로 급감해 찌그러집니다. 냄비가 본격적으로 끓기 전 바닥에서 '쉬익-' 또는 '사각사각' 소리가 나는 이유가 바로 이 미세 기포들이 수없이 터지고 찌그러지기 때문입니다.
* **충분히 끓을 때:** 물 전체가 균일하게 끓는점에 도달해 있으므로 올라가면서 응축되지 않습니다. 오히려 위로 올라갈수록 상부의 **수압이 감소**하고, 주변의 뜨거운 물로부터 수증기가 계속 유입되어 **기포의 부피가 점점 커지며 가속 상승**합니다.

**4단계: 수면 도달 및 방출**
수면에 도착한 기포는 얇은 액체 막이 대기와의 압력 차 및 표면장력 한계로 파열되며, 내부의 기체(공기 또는 수증기)와 잠열을 대기 중으로 방출합니다.

### 3. '운반 상자' 비유와 물리적 요소의 대응

기포가 열과 물질을 싣고 이동하는 전체 과정을 **특수 포장된 운반 상자 시스템**에 비유하면 다음과 같이 명확히 대응됩니다.

* **운반 상자 (택배 박스):** 기포의 표면(기체와 액체 사이의 계면 막).
* **상자 속 화물 (내용물):**
* *초기:* 방출되어 쫓겨난 **공기 분자들**.
* *끓을 때:* 바닥의 열에너지를 가득 머금고 기화된 **수증기 분자들(기화잠열)**.


* **상자를 밀어 올리는 동력:** 물과 기체의 밀도 차이로 발생하는 **부력**.
* **배송 경로의 환경 변화:**
* *초기 배송 실패 (비등 직전):* 상자가 바닥을 출발했으나, 경로 위쪽의 차가운 물(냉각 구간)을 만나 상자가 납작하게 찌그러지고 화물이 다시 액체로 내려앉음.
* *정상 배송 (충분히 끓을 때):* 경로 전체가 따뜻하여 화물이 안전하게 보존되며, 위로 올라갈수록 외부의 누르는 힘(수압)이 약해져 **상자가 점점 커지며 신속하게 이동**.


* **배송 완료:** 수면에 닿아 상자가 열리면서(기포 파열), 바닥에서 가져온 열에너지와 수증기를 대기로 전달하고 임무를 마침.

초기에 생기는 작은 기포는 액체 속에 숨어 있던 기체가 밀려 나오는 현상이며, 충분히 끓을 때의 거대한 기포는 물 자체가 형태를 바꾸어 열을 뿜어내는 상변화 과정입니다.

### 1. 이야기로 이해하는 물방울의 비밀

1. **따뜻한 방 안 (신나게 뛰어노는 아이들)**
따뜻한 방 안에는 눈에 보이지 않지만 공기 중에 수증기 친구들이 가득해요. 이 친구들은 에너지가 넘쳐서 넓은 운동장을 땀 흘리며 마구 뛰어다니는 개구쟁이 아이들과 같아요. 너무 빠르게 이리저리 날아다녀서 우리 눈에는 보이지 않지요.
2. **차가운 물병의 등장 (운동장에 나타난 차가운 얼음성)**
이때 방 한가운데에 냉장고에서 막 꺼낸 차가운 물병이 쑥 들어왔어요. 마치 햇볕 쨍쨍한 운동장 한가운데에 꽁꽁 언 얼음성이 우뚝 솟아난 것과 같아요.
3. **차가운 벽과의 만남 (으~ 추워!)**
