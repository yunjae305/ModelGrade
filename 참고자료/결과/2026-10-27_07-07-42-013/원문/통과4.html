응시 횟수가 한도보다 작은지 확인하는 함수입니다. 비교만 하고 값을 바꾸지 않습니다.



```python

def can_attempt(attempts: int, limit: int) -> bool:

    """응시 횟수가 한도 미만이면 True, 아니면 False를 반환합니다."""

    return attempts < limit





# 사용 예

print(can_attempt(2, 3))  # True  : 2번 응시했고 한도는 3번이므로 아직 가능합니다.

print(can_attempt(3, 3))  # False : 한도에 도달했으므로 허용하지 않습니다.

print(can_attempt(5, 3))  # False : 한도를 넘었으므로 허용하지 않습니다.

print(can_attempt(0, 1))  # True  : 아직 한 번도 응시하지 않았으므로 가능합니다.

```



**설명**



- `attempts`는 지금까지 응시한 횟수이고, `limit`은 응시할 수 있는 최대 횟수입니다.

- `attempts < limit`은 "응시 횟수가 한도보다 작은가?"를 묻는 비교입니다. 맞으면 `True`, 아니면 `False`가 나옵니다. 그 결과를 그대로 `return`하면 됩니다.

- 부등호로 `<`를 썼기 때문에 횟수가 한도와 같아지는 순간 `False`가 됩니다. 예를 들어 한도가 3이면 0, 1, 2번 응시한 사람만 다시 응시할 수 있고, 3번째 응시를 마친 뒤부터는 허용하지 않습니다.

- 함수 안에서는 입력값을 읽기만 하고 다시 대입하지 않습니다. 그래서 넘겨준 값은 함수를 부른 뒤에도 그대로입니다.

- `attempts: int`, `-> bool`은 타입 힌트입니다. 어떤 값이 들어오고 나가는지 알려 주는 표시이고, 실행 결과에는 영향을 주지 않습니다.

답변
Python 코드는 아래 코드블록 하나에 함수와 사용 예를 함께 담았습니다.



```python

def remove_none(measurements):

    """측정값 목록에서 None만 제거한 새 목록을 돌려줍니다.



    0, 0.0, False, 빈 문자열 등은 None이 아니므로 그대로 남깁니다.

    입력 목록은 수정하지 않습니다.

    """

    # 'is not None'은 값이 정확히 None인지 확인합니다.

    # 'if x'처럼 쓰면 0과 False도 사라지므로 사용하지 않습니다.

    return [x for x in measurements if x is not None]





# 사용 예

data = [3.5, None, 0, False, 7, None, 0.0, "", 12]

cleaned = remove_none(data)



print(cleaned)   # [3.5, 0, False, 7, 0.0, '', 12]

print(data)      # [3.5, None, 0, False, 7, None, 0.0, '', 12]  (원본 그대로)

print(cleaned is data)  # False (새 목록입니다)

```



## 설명



**1. 핵심은 `is not None`입니다.**

파이썬에서는 `0`, `False`, `0.0`, 빈 문자열 `""`이 조건문에서 "거짓처럼" 취급됩니다. 그래서 `if x`로 걸러내면 None뿐 아니라 0과 False까지 함께 지워집니다. `x is not None`은 값이 정확히 None인지만 확인하므로 나머지 값은 모두 보존됩니다.



**2. `==` 대신 `is`를 쓰는 이유입니다.**

None은 프로그램 전체에 단 하나만 존재하는 특별한 값이라서, 같은 객체인지 비교하는 `is`가 정확하고 관례적인 방법입니다.



**3. 리스트 컴프리헨션이 새 목록을 만듭니다.**

`[x for x in measurements if x is not None]`은 "목록의 각 값 `x`를 하나씩 꺼내, None이 아닌 것만 모아 새 목록을 만든다"는 뜻입니다. 새 목록을 만들어 반환하기 때문에 입력 목록은 전혀 바뀌지 않습니다. 사용 예의 마지막 두 줄 출력에서 원본이 그대로이고 결과가 별개의 목록임을 확인하실 수 있습니다.



**4. 피해야 할 방법입니다.**

반복문 안에서 `data.remove(None)`을 호출하면 원본이 수정되고, 순회 중에 목록을 바꾸면 값을 건너뛰는 버그가 생길 수 있습니다. 위 방식이 더 안전하고 간단합니다.

def is_overlapping(start1, end1, start2, end2):

    """두 예약 시간대가 겹치면 True, 아니면 False를 돌려줍니다.



    시간은 '분' 단위 정수이며, 끝나는 시각과 다음 시작 시각이 같으면

    """

    return start1 < end2 and start2 < end1

**1단계: 처음에 값을 가져올 때**

**2단계: 서버의 값을 수정했을 때**

사서가 공식 장부를 고쳤습니다. 이 시점에서 원본은 이미 새 값입니다. 다만 안내 데스크 옆 현황표는 **누가 고쳐 주기 전까지는 그대로**입니다. 현황표는 장부가 바뀐 사실을 스스로 알지 못하기 때문입니다.

**4단계: 캐시를 비웠을 때**

## 핵심 원리



캐시는 **빠르게 보여 주기 위한 복사본**이고, 원본은 **기준이 되는 진짜 기록**입니다. 복사본은 만들어진 시점의 내용을 담고 있으므로, 원본이 바뀐 뒤에도 복사본을 갱신하는 일이 따로 일어나지 않으면 두 값이 한동안 어긋납니다. 그래서 캐시를 비운 뒤에 새 값이 보였다는 사실은 **원본에는 새 값이 이미 들어 있었다**는 점과 잘 맞아떨어집니다.
